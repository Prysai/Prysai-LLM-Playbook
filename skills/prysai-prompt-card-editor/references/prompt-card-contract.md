# Prompt-card contract

Use this reference only after the Skill admission gate passes. It defines a
project-authored editorial format; it is not a universal prompt formula or a
claim that any product will follow it.

## Required fields

| Field | Editor decision | Reject or stop when |
| --- | --- | --- |
| Learner job | One observable thing a reader can attempt now. | The request is a broad identity or outcome claim such as fluent, expert, or best. |
| Use only if | Low-risk context and the material the reader may supply. | It depends on files, tools, accounts, private material, or an external action. |
| Do not use if | A clear non-fit boundary. | The card silently widens authority or data access. |
| Copy-ready card | Original, short request with visible context and response shape. | It reproduces unlicensed text, invents an input, or asks for hidden reasoning. |
| Self-check | One reader-verifiable question about the response or attempt. | The answer is asked to certify itself. |
| Failure or stop | One first mismatch and the smallest safe next route. | A retry changes several conditions or promises a fix. |
| Receipt | Minimal facts retained after the attempt. | It is presented as proof of learning, correctness, or safety. |
| Origin and license | Project-owned wording or a precise, reviewable reuse boundary. | Provenance, permission, or version is unknown. |

## Card anatomy

Use this order when the card is rendered for a reader:

```text
TITLE — one ordinary action, not a result promise
USE ONLY IF — low-risk context and what the reader supplies
COPY — the original text-only request
CHECK — one thing the reader verifies independently
IF IT MISSES — the smallest fallback or named handoff
RECEIPT — what was attempted, checked, and remains unproven
```

Keep one card to one decision. A language card can ask for one short attempt;
it cannot establish proficiency. A research card can create a source-check
plan; it cannot verify a source merely by creating a citation. A writing card
can preserve named facts; it cannot certify accuracy or publication readiness.

## Editorial red flags

Reject or route away a card that does any of the following:

- promises a result within a fixed number of days or turns;
- asks the model to browse, use a tool, contact a person, edit a file, or make
  an account-level change without a Task Protocol;
- makes a privacy, safety, factual-correctness, or platform-equivalence claim
  that the card cannot independently support;
- uses audience, difficulty, facts, or success criteria that the reader did
  not supply; or
- differs from an existing card only by tone, role-play, or extra adjectives.

## Evidence label

For a candidate card, use this sentence without strengthening it:

> This card is an original, static editorial template. A completed attempt can
> record what one reader tried and checked; it does not prove learning,
> transfer, correctness, safety, or model performance.
