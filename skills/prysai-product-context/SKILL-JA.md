# プロダクト・コンテキスト

ポジショニング、コンテンツ、SEO、コンバージョン、ローンチ、分析、営業に先立ち、
バージョン管理された製品・マーケティングの共通コンテキストを作成または更新します。
共有理解、対象者、ポジショニング、ブランドの声、製品コンテキストが不足している場合に
使います。顧客の証拠を作ったり、調査の代わりになったり、後続のマーケティング変更を
実行したりしません。

## 起動条件と引き継ぎ

共有する製品、対象者、ポジショニング、メッセージ、ブランド、コンバージョン、測定の
コンテキストが成果物として不足している場合に担当します。

次の場合は引き継ぎます。

- `$skill` が明示された：尊重し、求められた場合だけコンテキストを提供する。
- 外部の事実調査が必要：Research Router。
- 既存コンテキストの主張を監査する：Evidence Review。
- コンテンツやローンチ変更を実行する：Task Protocol または Workflow Orchestrator。
- ポジショニング手法だけを学ぶ：Codex Coach。

マーケティング実行者、分析システム、顧客調査の代替にはなりません。下流成果物のために
重要なコンテキストの不足が見つからない限り、Product Context を再度呼びません。

## 必須入力と不足項目の扱い

`product_or_project`、`current_goal`、`known_audience`、`available_sources`、
`decision_to_support`、`canonical_location` を要求します。さらに `decision_owner`、
`context_version`、`version_baseline` が必要です。自身の保守バージョンを製品コンテキスト
のバージョンと混同しません。既存コンテキスト、その現在のバージョンまたはハッシュ、
変更履歴を確認してから提案します。顧客の証拠、指標、推薦、競合の事実、好みがなければ
`hypothesis` または `unknown` と記録し、影響の大きい不足だけを質問します。

初期状態は権威を持たない草稿または提案差分です。説明、レビュー、校正の依頼だけで
正規ファイルを再構築・書き込みしません。正規コンテキストを書き込む前に、正確な対象
パス、現行バージョン／ハッシュ、変更フィールドの範囲、プライバシー分類と PII 判断、
担当者、可逆なバックアップまたはロールバック先、書き込み直前の明示的な確認を要求
します。確認は対象と操作を特定し、ログイン、トークン、以前の承認、「すべてのアクセス」
では代用できません。項目が欠ければ `blocked` と `blocked_on` を返し、書き込みや変更履歴
の作成をしません。対象、基準、書き込み範囲が一致しない既存コンテキストを上書きしません。

## 収集とバージョン管理

一行の説明、カテゴリ、種類、目標、対象利用者と決定者、達成したい仕事、反対象者、問題、
代替案、反論、差別化、証拠、顧客の言葉、使う・避ける言葉、用語集、トーン、制約、
コンバージョン行動、測定の判断を収集します。重要な変更ごとにバージョンを上げ、日付付き
変更履歴を追加します。どの場所とバージョンが正規かを下流作業に伝えます。

変更履歴には旧版、新版、変更した主張、使用した証拠、決定者、影響する下流成果物、対象パス、
ロールバック先を記載します。所有者が受け入れるまで草稿は権威を持ちません。提案、確認済みの
書き込み、公開済みの変更を別の状態に保ち、一つの完了を次の完了とみなしません。

## 下流デザインへの引き継ぎ

Product Context は下流デザインを制約しますが、好みで視覚スタイルを決めたり、完成 UI を
生成したり、視覚品質を確認したりしません。Web ページ、アプリ、プレゼンテーション、
レポートなどの視覚成果物では、`design_handoff` に次を記載します。

- 実際の利用者のタスクと、成果物が支える判断;
- 必要な情報階層と最低限の有用な情報密度;
- 説明なしで認識できる業界の慣れたパターン;
- 必要な信頼シグナル、出典、開示、所有者、連絡先;
- 実際に存在する写真、在庫、データ、顧客の言葉、推薦、承認済みブランド素材;
- 証拠を捏造したり未裏付けの権威を示したりする禁止表現;
- 対象ビューポート、アクセシビリティ条件、レビュー担当者、レンダリング成果物の受け入れ確認。

実写真、在庫、顧客の言葉、推薦、承認済みブランドシステムがない場合は、生活感のある文、
合成リスト、装飾的な不動産イラスト、大きなエディトリアル明朝、柔らかなグラデーション、
浮遊カード、過剰な角丸で穴を埋めません。購入ガイド、サービス説明、チェックリスト、比較、
意思決定ツールを優先します。見た目が整っていても、指定条件でレンダリングしてレビューする
まで未検証です。

## リスク、副作用、確認

提供された出典からの草稿は `R0` または `R1` です。正確なローカル対象、基準、バックアップ、
プライバシー判断、ロールバック、担当者、直前確認が記録されている場合に限り正規ファイルの
書き込みを `R1` とします。公開サイトの変更、個人データ収集、メッセージ送信、分析変更は
`R2` 以上で、正確な対象、範囲、担当者、確認を持つ Task Protocol または Workflow Orchestrator
に渡します。個人を特定できる情報は必要かつ許可された場合だけにし、提供されたという理由
だけで顧客記録をそのままコンテキストにコピーしません。

## 強制停止

製品の同一性、決定者、正規場所、出典の出所、プライバシー境界、バージョン基準、現行対象の
状態、バックアップ、ロールバック先、書き込み確認が不明なら `blocked` で停止します。
未レビューの判断を上書きしたり PII を公開したり、指定されたフィールド範囲を越える場合も
停止します。仮定を証拠、草稿を顧客主張、コンテキスト更新を公開許可に変えません。

## 固定の出力

1. `context_scope_and_owner`
2. `authoritative_version_and_location`
3. `observed_facts`
4. `hypotheses_and_unknowns`
5. `audience_and_jobs`
6. `positioning_and_message_constraints`
7. `proof_points_and_evidence_gaps`
8. `changelog_entry`
9. `downstream_handoff`
10. `design_handoff`
11. `risk_and_permissions` — `risk`、`action_state`（`draft_only`、`write_blocked`、
    `write_confirmed`、`handoff_required`）、正確な対象、プライバシー判断、担当者、確認、
    バックアップ／ロールバック、停止条件を含める
12. `content_status`

## 証拠と状態の対応

各記述を `observed`、`attributed`、`hypothesis`、`decision`、`unknown` とします。提案を
検証するには、重要な主張を引用元と照合し、現行基準との差とプライバシー分類、変更範囲、
レビュー担当者が差分を確認できることを確認します。これは提案を検証するもので、顧客への
影響や下流実行を検証するものではありません。出典・所有者のレビュー前は `draft`、版管理
されたコンテキストはあるが新しい確認がない場合は `candidate`、宣言した証拠と所有者の
レビューを通過したら `verified`、プライバシー、公開、保守、ロールバックのゲートまで
通過して初めて `production-ready` とします。
