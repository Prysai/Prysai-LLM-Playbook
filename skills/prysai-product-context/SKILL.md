# Prysai Product Context

Create a compact shared context that downstream work can reuse. Start by
checking for an existing project context and its version/changelog. Preserve
past decisions and ask only for missing or changed sections.

## Capture

- product one-liner, category, type, and current goal;
- target users, decision-makers, jobs to be done, and anti-personas;
- core problems, alternatives, objections, and switching dynamics;
- differentiation and proof points, separating evidence from hypotheses;
- customer language, words to use/avoid, and glossary;
- brand tone, style, and constraints;
- conversion action and the decisions that measurement should inform.

## Workflow

1. Inspect existing context and project material.
2. Draft only what the evidence supports; mark assumptions.
3. Ask focused questions for high-impact gaps.
4. Save the canonical context in the project-approved location.
5. Increment version and add a dated changelog entry for substantive changes.
6. Tell downstream skills which context is authoritative.

## Boundaries

Do not invent customers, metrics, testimonials, market claims, or competitive
facts. Do not turn a positioning hypothesis into proof. Keep personally
identifying information out of general context unless explicitly required and
properly authorized.
