# LLM 比較協議

把「哪個比較好？」轉成一項可檢查的決策。這個 Skill 規劃或審查兩個指定 LLM、模型供應商或工作流程候選項之間公平且有任務範圍的比較；不會執行模型、花費預算、暴露私人輸入，也不會把小規模結果變成排行榜。

## 凍結決策

要求提供決策 ID 和負責人；恰好兩張候選卡；一個變動變數；固定任務集、輸入、順序、評分規則、重複次數和評分負責人；以及上下文指紋、工具和版本、權限、預算或成本依據、可用性期間、紀錄位置、保留界線、停止條件和不可比較條件。

候選項目、驗收規則、權限界線、成本依據或負責人缺失時回傳 `blocked`。不要靜默標準化帳號、方案、地區、速率限制、工具、系統上下文或輸出格式的差異。

將指定產品指令、權限或執行時行為交給 `prysai-platform-adapter-review`；將目前價格、可用性或產品事實交給 `prysai-source-investigator`；將已完成的比較主張稽核交給 `prysai-evidence-review`。

## 使用一個固定工作面

當合成輸入適合決策時，使用專案自有的三任務冒煙包 `evals/candidates/three-task-smoke-v1/`。任何外部執行前先執行其本地驗證器。這個套件提供凍結輸入、雜湊、預期輸出形狀和執行紀錄範本；不包含模型結果，也不作基準主張。

如果不適合，先為兩個候選項目定義新的任務契約。看到一個結果後，不要改變輸入、評分規則、上下文、工具、權限層級、預算或停止規則。條件改變就是新的比較，不是原決策下的重試。

## 保留誠實的執行紀錄

規劃和靜態測試夾具檢查屬於 `R0`。獲授權且可逆的本地執行屬於 `R1`。供應商、帳號、網路、付費 API、共享儲存庫或外部服務執行屬於 `R2`，需要明確目標、資料界線、預算、負責人、回復或清理方式和確認。

對每個候選項目和每項任務，保留執行 ID、嘗試 ID、候選項目 ID、任務 ID、輸入雜湊、上下文指紋、工具和版本、權限、成本依據、可用性事件、原始輸出位置、驗證、人工評分、結果狀態、不可比較原因和限制。初始輸出保持不可變；受控返工使用新的嘗試 ID。

容量錯誤、介面不可用、權限不匹配、輸入雜湊漂移、工具版本漂移或原始輸出缺失，都是應保留的證據，不是可以隱藏的空白儲存格。

## 限制結論

將每列分類為 `comparable`、`not-comparable` 或 `not-run`，然後只回傳一個決策：

- `worth-expanding`：聲明範圍內的任務級證據支持另行規劃更大規模的比較；
- `do-not-expand-yet`：觀察證據未通過聲明門檻，或存在尚未解決的重要故障；
- `insufficient-evidence`：輸入、條件、證據、評分或可比性不完整。

不要指定通用贏家、發佈總體排名、從可用性推斷能力、從一次成功推斷可靠性、比較不同口徑的成本，或把未執行的協議轉成模型效能證據。

## 回傳比較紀錄

回傳決策 ID、決策負責人、比較變數、候選卡、凍結條件、任務集和輸入雜湊、驗收與評分、執行狀態、可比較列、不可比較列、決策、證據、未知項目、轉交、風險、內容狀態，以及這項限制：這只是有任務範圍的候選決策；不是產品排名、基準測試、執行時保證、學習者結果或正式環境建議。
