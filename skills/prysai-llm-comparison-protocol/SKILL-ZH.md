# LLM 比较协议

把“哪个更好？”转化成一项可检查的决策。这个 Skill 规划或审查两名指定 LLM、模型供应商或工作流候选项之间、公平且有任务范围的比较；不会执行模型、花费预算、暴露私人输入，也不会把小规模结果变成排行榜。

## 冻结决策

要求提供决策 ID 和负责人；恰好两张候选卡；一个变化变量；固定任务集、输入、顺序、评分规则、重复次数和评分负责人；以及上下文指纹、工具和版本、权限、预算或成本依据、可用性窗口、日志位置、保留边界、停止条件和不可比较条件。

候选项、验收规则、权限边界、成本依据或负责人缺失时返回 `blocked`。不要静默标准化账户、套餐、地区、速率限制、工具、系统上下文或输出格式的差异。

将指定产品命令、权限或运行时行为交给 `prysai-platform-adapter-review`；将当前价格、可用性或产品事实交给 `prysai-source-investigator`；将已完成的比较断言审计交给 `prysai-evidence-review`。

## 使用一个固定工作面

当合成输入适合决策时，使用项目自有的三任务冒烟包 `evals/candidates/three-task-smoke-v1/`。在任何外部执行前运行其本地验证器。该包提供冻结输入、哈希、预期输出形状和运行记录模板；不包含模型结果，也不作基准断言。

如果不适合，先为两个候选项定义新的任务契约。看到一个结果后，不要改变输入、评分规则、上下文、工具、权限级别、预算或停止规则。条件改变就属于新的比较，不是原决策下的重试。

## 保留诚实的运行记录

规划和静态夹具检查属于 `R0`。获授权且可逆的本地运行属于 `R1`。供应商、账户、网络、付费 API、共享仓库或外部服务运行属于 `R2`，需要明确目标、数据边界、预算、负责人、回滚或清理方式和确认。

对每名候选项和每项任务，保留运行 ID、尝试 ID、候选项 ID、任务 ID、输入哈希、上下文指纹、工具和版本、权限、成本依据、可用性事件、原始输出位置、验证、人工评分、结果状态、不可比较原因和限制。初始输出保持不可变；受控返工要使用新的尝试 ID。

容量错误、表面不可用、权限不匹配、输入哈希漂移、工具版本漂移或原始输出缺失，都是应保留的证据，不是可以隐藏的空白单元格。

## 限制结论

将每行分类为 `comparable`、`not-comparable` 或 `not-run`，然后只返回一个决策：

- `worth-expanding`：声明范围内的任务级证据支持另行规划更大规模比较；
- `do-not-expand-yet`：观察证据未通过声明门槛，或存在尚未解决的重要故障；
- `insufficient-evidence`：输入、条件、证据、评分或可比性不完整。

不要指定通用赢家、发布总体排名、从可用性推断能力、从一次成功推断可靠性、比较不同口径的成本，或把未运行的协议转成模型性能证据。

## 返回比较收据

返回决策 ID、决策负责人、比较变量、候选卡、冻结条件、任务集和输入哈希、验收与评分、运行状态、可比较行、不可比较行、决策、证据、未知项、交接、风险、内容状态，以及这一限制：这只是有任务范围的候选决策；不是产品排名、基准、运行时保证、学习者结果或生产建议。
