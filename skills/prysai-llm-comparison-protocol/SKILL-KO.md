# LLM 비교 프로토콜

이름이 있는 두 LLM·모델 제공자·워크플로 후보를 과제 범위 안에서 공정하게 비교할 계획을
세우거나 검토합니다. 어느 쪽이 더 낫고 빠르고 저렴한지, 확장할 가치가 있는지 묻고 고정 조건,
원시 증거, 사용 불가 사례, 좁은 결론을 보존해야 할 때 사용합니다. 특정 플랫폼 수업 채택,
현재 제품 사실 조회, 승인 없는 모델 실행, 일반 순위 공개에는 쓰지 않습니다.

## 결정 고정

`decision_id`와 소유자, 후보 카드 정확히 두 개, 바뀌는 변수 하나, 고정 과제·입력·순서·루브릭·
반복·채점 담당자를 요구합니다. 컨텍스트 지문, 도구·버전, 권한, 예산·비용 근거, 이용 가능 시간,
로그 위치, 보존 경계, 중단 조건, 비교 불가 조건도 포함합니다.

후보·수용 기준·권한 경계·비용 근거·소유자 중 하나가 빠지면 `blocked`입니다. 계정·플랜·지역·
레이트 리밋·도구·시스템 맥락·출력 형식 차이를 조용히 표준화하지 않습니다.

제품 명령·권한·런타임 동작은 `prysai-platform-adapter-review`, 현재 가격·가용성·제품 사실은
`prysai-source-investigator`, 끝난 비교의 주장 감사는 `prysai-evidence-review`로 넘깁니다.

## 고정 표면 하나 사용

합성 입력이 결정에 맞으면 프로젝트 소유 `evals/candidates/three-task-smoke-v1/` 패키지를 사용합니다.
외부 실행 전에 로컬 검증기를 돌립니다. 이 패키지는 고정 입력·해시·예상 출력 형태·실행 기록 템플릿만
제공하며 모델 결과나 벤치마크 주장은 포함하지 않습니다.

맞지 않으면 어느 후보도 실행하기 전에 새 과제 계약을 정합니다. 한 결과를 본 뒤 입력·루브릭·맥락·도구·
권한·예산·중단 규칙을 바꾸지 않습니다. 조건을 바꾸면 새 비교입니다.

## 정직한 실행 기록 보존

계획과 정적 fixture 검사는 `R0`, 승인된 되돌릴 수 있는 로컬 실행은 `R1`, 제공자·계정·네트워크·유료 API·
공유 저장소·외부 서비스 실행은 `R2`이며 정확한 대상·데이터 경계·예산·소유자·롤백 또는 정리·확인이 필요합니다.

후보·과제마다 run ID, attempt ID, candidate ID, task ID, 입력 해시, 컨텍스트 지문, 도구·버전, 권한, 비용 근거,
가용성 이벤트, 원시 출력 위치, 검증, 사람 점수, 결과 상태, 비교 불가 이유, 한계를 남깁니다. 최초 출력은 수정하지 않고
통제된 재작업에는 새 attempt ID를 줍니다.

용량 오류·사용 불가 화면·권한 불일치·입력 해시 변경·도구 버전 변경·원시 출력 누락은 숨길 빈칸이 아니라 보존할 증거입니다.

## 결론 제한

각 행을 `comparable`, `not-comparable`, `not-run`으로 분류하고 판단 하나만 반환합니다.

- `worth-expanding`: 과제 수준 증거가 별도 계획의 더 큰 비교를 지지함;
- `do-not-expand-yet`: 증거가 선언한 게이트를 통과하지 못했거나 중요한 문제가 남음;
- `insufficient-evidence`: 입력·조건·증거·점수·비교 가능성이 부족함.

보편적 승자·일반 순위를 말하지 않고, 가용성에서 능력을, 한 번의 성공에서 신뢰성을 추론하지 않으며,
서로 다른 비용을 비교하지 않고, 실행하지 않은 프로토콜을 성능 증거로 바꾸지 않습니다.

## 비교 영수증 반환

결정 ID, 결정 담당자, 비교 변수, 후보 카드, 고정 조건, 과제·입력 해시, 수용·채점, 실행 상태,
비교 가능·불가 행, 결정, 증거, 미지, 인계, 위험, 콘텐츠 상태와 다음 한계를 반환합니다: 과제 범위의
후보 결정일 뿐 제품 순위·벤치마크·런타임 보장·학습 결과·운영 권고가 아님.
