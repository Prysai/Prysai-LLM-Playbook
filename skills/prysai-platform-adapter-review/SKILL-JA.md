# プラットフォーム・アダプターのレビュー

特定プラットフォーム向けのチュートリアルやワークフローが、出典のある実行可能で保守可能な差分を本当に提供しているかを判断します。ベンダー名を変えただけの機能一覧はアダプターではありません。

## 主張を固定する

プラットフォーム、利用面、アカウントまたはプランの境界、バージョンと日付、読者の結果、universal core の前提、提案する状態、レビュー対象の正確な主張を記録します。複数プラットフォームの主張が混ざっている場合は分けます。固定した比較タスクとルーブリックによって本当に比較可能な場合だけ、一つにまとめます。

## アダプター契約を確認する

次の項目に明確な回答を求めます。

1. `surface`：チャット、デスクトップ、CLI、IDE、Web、API、その他の入口;
2. `context_injection`：ファイル、ルール、会話状態、検索結果、利用者の成果物;
3. `actions`：その利用面が観察または変更できるもの;
4. `authority`：権限、確認、サンドボックス、アカウント、課金、外部への副作用;
5. `persistence`：ターン、セッション、タスク、プロジェクトを越えて残るもの;
6. `control_loop`：観察可能な計画、ツール利用、フィードバック、再試行、委任;
7. `verification_surface`：差分、ログ、引用、プレビュー、テスト、トレース、外部状態;
8. `failure_modes`：その製品特有の誤解と劣化経路;
9. `volatile_facts`：権威ある URL、確認日、範囲、担当者、次回レビュー;
10. `transfer_lab`：固定入力、安全な操作、受け入れ条件、片付け、失敗、証拠の限界。

理由を添えた場合だけ `not_applicable` とします。現在の情報源や実行が答えを支えていない場合は `unknown` とします。

## 証拠ゲートを適用する

三つの証拠クラスを分けます（公式事実の状態値は `official` です）。

- 公式事実：プラットフォームが保有する最新の一次ドキュメントまたは情報源;
- 観察された動作：設定と見える操作を保存した実行記録;
- 現場シグナル：症状や需要だけを示す公開報告。

コミュニティ投稿は公式事実のゲートを満たしません。ドキュメントは利用者のアカウント、実行環境、結果を証明しません。一度成功した実行から普遍的な動作、信頼性、優位性、学習者の転移を証明することもできません。

根拠のない同等性を退けます。Agent、ツール、メモリ、プロジェクト、Skill、検索など同じラベルがあっても、意味が同一とは限りません。同じ入力、受け入れ条件、リスク境界、レビュー基準を使う固定タスクだけを比較し、設定の差を残して `not_comparable` と記録します。

## 処置を決める

次のいずれかを返します。

- `admit_candidate`：必要な差分、情報源、実行、失敗、担当者、レビュー日、証拠の限界がすべてある;
- `draft_source_gap`：重要な変動主張に一次情報源がない;
- `draft_run_gap`：契約は出典付きだが、範囲を限定した実行がない;
- `merge_into_core`：意味のあるプラットフォーム差分がない;
- `quarantine`：ライセンス、安全、プライバシー、出所が不明確;
- `retire`：古い、担当者がいない、重複している、または役割を失ったアダプター。

ログイン成功、コマンドの存在、文章の完成度だけで状態を上げません。`candidate` のアダプターは、学習者の転移が検証されたことも、本番向けの案内になったことも意味しません。

## レビューを納品する

処置と最も強い理由から始めます。その後に契約マトリクス、根拠のない主張、情報源・実行・ライセンスの不足、universal core との重複、次の実験、担当者、次回レビュー、合格しても証明できないことを示します。主張の数に見合った形式にし、一つの主張に儀式的な見出しを並べません。
