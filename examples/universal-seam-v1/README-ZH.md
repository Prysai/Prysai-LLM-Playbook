# 通用衔接点固定练习 v1

这是配合“通用核心基础路线”的小型离线虚构练习。只需记住一件事：看见回复、分支标签、像工具输出的代码块，或解析器显示成功，**都不能单独证明**任务、目标、动作或结构化状态真的正确。

这里没有账号、模型调用、网络请求、凭据、真实仓库、文件修改、命令执行、提交、推送、发布或其他外部副作用。记录是项目原创的虚构材料，不是厂商日志。

## 你要做什么

逐条阅读 `cases.json`：找出准确的不一致之处，写下最小的安全检查，并严格使用给定状态。

| 状态 | 在本固定练习中的含义 |
| --- | --- |
| `verified_in_fixture` | 给定的本地值直接证明了所说的不一致。 |
| `blocked` | 目标或权限证据相互冲突，下一步必须停止。 |
| `not_run` | 没有执行回执；没有动作被展示为已经完成。 |
| `inferred` | 已发现差异，但要诊断真实协议仍需平台适配器。 |

在仓库根目录运行：

```powershell
$py = (Get-Command python -ErrorAction Stop).Source
& $py scripts\validate_universal_seam_fixture.py
& $py scripts\test_universal_seam_fixture.py
```

这两个命令只检查固定合同及其边界测试，不会联系模型或服务。

## 有边界的记录卡

```text
任务：给一条虚构记录分类一个衔接点问题。
先读：cases.json 和 expected/acceptance.json。
允许：比较固定值，并写一份本地判断记录。
不要：使用网络、账号、密钥、真实仓库、在线工具、命令、提交、推送或发布目标。
验收：写明不一致、不能成立的推断、最小安全检查、停止条件和给定的窄状态。
回执：案例 ID、观察字段、判断、未验证清单，以及是否需要未来的平台适配器。
停止：继续需要真实产品行为、权限、结构定义或外部状态时。
```

## 通过不能说明什么

通过只说明固定的虚构记录符合验收合同，不能证明外部问题、平台行为、动作已执行、学习迁移、安全性、可移植性或已准备发布。
