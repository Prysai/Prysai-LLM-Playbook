# Codex: From First Task to Real Work 路线图

## Phase 0：地基（已完成）

- 确立项目的产品定位和学习目标；
- 建立书籍、课程、实验室、skills、评测和治理的分层；
- 盘点六个输入压缩包并保存 SHA-256；
- 建立许可证/来源台账；
- 核对一轮官方 Codex 与模型基线；
- 建立项目规则和自动验证；
- 交付首个教练、任务协议和证据审查 skills；
- 完成四章书稿方向中的前四章与三个实验。

## Phase 1：核心学习闭环（进行中）

- 完成第 1–9 章的入门主线；
- 完成 L0–L3 的实验集和学习者记录模板；
- 增加 skill 选择、工具边界、模型选择和验证章节；
- 对首批 skills 做正例、边界例和失败例前测；
- 用真实但低风险任务做一次新鲜上下文验证。

## Phase 2：专业轨融合

- 工程轨：从定义到发布的可验证工作流；
- 研究轨：问题收敛、来源、引用、复核和披露；
- 营销轨：产品上下文、内容、转化和测量；
- 内容/设计/数据/自动化轨：以能力簇而不是目录数量组织；
- 每条轨都接入统一的任务协议和证据审查。

## Phase 3：组织级产品化

- 建立贡献者指南、评审角色和维护责任；
- 设计可发布的 plugin/skill 包边界；
- 确认许可证、品牌使用边界和公开范围（当前本地拟采用名称为 `Codex: From First Task to Real Work`，仓库路径暂保持私有开发路径）；
- 配置 CI：结构、链接、frontmatter、许可证、评测和过时事实检查；
- 以机器可读 release-readiness contract 管理版本、changelog、reviewed tag、候选证据与 rollback rehearsal；当前记录必须保持 `not_ready`，直到真实证据存在；
- 对关键章节做学习者测试和版本化发布。

## 当前章节整合状态

- 第 19–22 章草稿已写，待前测；章节入口已接入真实问题案例、评测夹具规范和研究档案。
- 评测框架已定义任务结构和分层评测，`evals/task-set-v1.yaml` 已落盘并通过结构校验；在产生模型运行日志前，仍不得声称评测已经完成。
- Luna 评估仍为 `draft / not run`，只有假设和实验设计，没有实际运行数据。

## Phase 4：持续更新

- 为官方文档、模型、产品入口和外部生态建立定期审查；
- 维护版本变更日志和迁移指南；
- 删除过时、低价值或高风险能力；
- 以评测数据而非目录数量决定保留与否。

## 还不能声称完成的内容

目前还不能称为“完整课程”“全部内容已融合”“所有 skills 已优化”或“已准备公开发布”。这些称号要等对应章节、实验、来源、评测、许可证和组织审查全部通过后再使用。
