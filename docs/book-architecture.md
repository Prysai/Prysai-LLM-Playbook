# 书籍式产品架构

Field Guide 的主线采用“问题 → 概念 → 判断 → 操作 → 证据 → 失败 → 复盘 → 迁移”的章节结构。读者可以顺读，也可以从任务入口跳读；每个跳读入口最终都应回到基础概念和验证闭环。

## 双层课程边界

课程只有一个可迁移的协作核心：结果定义、上下文选择、权限与副作用、证据、恢复、复用、评估和治理。Codex 是当前最深入的旗舰实践轨道，用真实文件、终端、浏览器、Git、Skill 与 Agent 展示这些原则如何落地。

“通用”不代表不同平台行为相同。命令、上下文注入、权限、持久化、可观察表面和失败模式等产品差异，必须放入有官方来源、运行记录、失败案例、负责人和复核日期的平台适配器。当前没有任何非 Codex 平台适配器达到公开课程准入门槛，因此不得暗示跨平台课程已经完成。

## 章节统一模板

每章必须包含：

1. 本章要解决的真实问题；
2. 读者完成后能解释和完成什么；
3. 最小必要概念；
4. 一个可观察的主流程；
5. 一个最小实验和一个失败实验；
6. 常见误区与边界；
7. 迁移到工程、研究、营销或团队场景的练习；
8. “我真的学会了吗？”验收清单；
9. 易变事实与官方来源表。

## 三个独立的发现维度

读者入口按三个维度组合，而不是复制三套正文：

1. **能力深度：** 从第一次安全操作到团队治理；
2. **平台轨道：** 通用核心与 Codex 旗舰轨道；
3. **实际任务：** 软件工程、研究、语言学习、内容审查或其他有边界的工作。

任务路线只引用规范教学单元，不另写一套互相漂移的核心解释。

## Codex 旗舰轨道的四条阅读路线

### 路线 A：第一次认识 Codex

适合没有开发背景或第一次打开 Codex 的人。重点是建立心智模型、完成安全配置、做出第一个小成果。

### 路线 B：把 Codex 用于真实工作

适合已经会聊天但交付不稳定的人。重点是任务定义、上下文、计划、执行、验证和交付。

### 路线 C：能力扩展与 Agent 协作

适合想使用 skills、MCP、浏览器、GitHub、外部服务和多阶段 Agent 工作流的人。重点是组合、边界、权限与可靠性。

### 路线 D：组织级熟练运用

适合个人与不同团队。重点是共享上下文、贡献规范、评测、审查、版本化和生产风险。

## 内容分层

```text
稳定层：模型如何根据上下文生成、工具如何改变行动空间、验证为什么必要
产品层：Codex 的入口、权限、skill、插件、连接器和工作模式
领域层：工程、研究、营销、文档、设计、数据等任务方法
实例层：具体命令、界面、模型名称、版本、价格和外部服务
```

稳定层可以长期复用；产品层需要跟随官方文档；领域层需要由实践评估；实例层必须带复核日期，不能无来源流入主线。

## 学习结果的四种证据

- **解释证据：** 学习者能用自己的话说明概念和边界；
- **操作证据：** 学习者完成了一个真实任务或实验；
- **判断证据：** 学习者能在多个方案中说明取舍；
- **审查证据：** 学习者能发现错误、风险、幻觉或未完成工作。

四类证据是特定任务与环境内的最低能力证据，不能单独证明长期“掌握”。保持、未见任务迁移、脱离提示后的独立表现和跨情境稳定性必须分别测量，并声明时间、任务、工具、评分者与辅助条件。
