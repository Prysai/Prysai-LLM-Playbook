# Prysai Lab 贡献模型

维护披露见 [`maintenance-disclosure.md`](maintenance-disclosure.md)。

Field Guide 是组织级项目。贡献不只包括写代码，也包括写章节、设计实验、审核来源、验证 skill、报告过时事实和改进学习路径。

## 贡献类型

| 类型 | 主要问题 | 必须附带 |
|---|---|---|
| 章节 | 学习者能否理解并迁移？ | 学习目标、实验、验收和来源 |
| 实验 | 学习者能否产生可观察证据？ | setup、失败变体、通过标准 |
| Skill | Codex 是否更稳定或更安全？ | 触发、正例、边界例、失败例和评测 |
| 来源更新 | 事实是否仍然有效？ | 官方链接、访问日期、适用范围 |
| 领域轨 | 方法能否迁移到专业任务？ | 领域上下文、风险、案例和评测 |
| 治理 | 团队是否能安全复用？ | 权限、责任、版本和回滚说明 |

## 每次贡献都要说明

- 这是原创内容、改写内容、外部组件还是外部链接；
- 使用了哪些来源和许可证；
- 哪些事实可能快速过时；
- 如何验证内容或 skill；
- 已知限制是什么；
- 下一次维护由谁负责或如何接手。

## 评审顺序

1. 目标和学习价值；
2. 来源与许可证；
3. 安全和权限边界；
4. 事实准确性；
5. 可读性与学习路径；
6. 实验或 skill 的可验证性；
7. 维护成本。

内容越接近生产操作、外部服务或高权限 Agent，所需证据越高。
