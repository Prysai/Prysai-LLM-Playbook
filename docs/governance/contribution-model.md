# Prysai Lab 贡献模型

维护披露见 [`maintenance-disclosure.md`](maintenance-disclosure.md)。

仓库根目录的 [`CONTRIBUTING.md`](../../CONTRIBUTING.md) 是外部贡献入口和变更分流路由；本文件保留 canonical 治理原则，避免两处重复维护完整规则。

Prysai LLM Playbook 是组织级项目。贡献不只包括写代码，也包括写章节、设计实验、审核来源、验证 skill、报告过时事实和改进学习路径。

## 贡献类型

| 类型 | 主要问题 | 必须附带 |
|---|---|---|
| 章节 | 学习者能否理解并迁移？ | 学习目标、实验、验收和来源 |
| 实验 | 学习者能否产生可观察证据？ | setup、失败变体、通过标准 |
| Skill | Codex 是否更稳定或更安全？ | 触发、正例、边界例、失败例和评测 |
| 来源更新 | 事实是否仍然有效？ | 官方链接、访问日期、适用范围 |
| 领域轨 | 方法能否迁移到专业任务？ | 领域上下文、风险、案例和评测 |
| 治理 | 团队是否能安全复用？ | 权限、责任、版本和回滚说明 |
| 测试材料 | 是否补充一个可复核的虚构夹具或文本协议？ | `contribution.json`、正反例、无原始个人/模型数据声明和不作效果主张 |

## 每次贡献都要说明

- 这是原创内容、改写内容、外部组件还是外部链接；
- 使用了哪些来源和许可证；
- 哪些事实可能快速过时；
- 如何验证内容或 skill；
- 已知限制是什么；
- 下一次维护由谁负责或如何接手。

## 评审顺序

1. 目标和学习价值；
2. 来源与许可证；
3. 安全和权限边界；
4. 事实准确性；
5. 可读性与学习路径；
6. 实验或 skill 的可验证性；
7. 维护成本。

内容越接近生产操作、外部服务或高权限 Agent，所需证据越高。

## 快速测试材料通道

快速通道仅接收原创、虚构、低风险的测试夹具和文本协议。提交者遵循
[`evals/contributions`](../../evals/contributions/README.md) 的目录与回执格式；自动检查只验证
范围、隐私与主张边界。维护者仍须审查来源、许可证、重复度、失败分支和维护成本。

具体的贡献脚手架、PR 边界和简短维护者检查表见
[`fast-material-review.md`](fast-material-review.md)。只有一个贡献目录的 PR 使用专用只读检查；
一旦改动超出该目录，完整质量工作流仍会运行。

可执行代码或验证器、真实学习者记录、模型原始输出、身份信息、同意文件、实际效果数据、许可证变更、安全/工作流
变更和成熟度升级不属于快速通道。它们必须进入授权的受限审查，不得因 CI 通过或一个 PR 而
升级为已验证结论。
