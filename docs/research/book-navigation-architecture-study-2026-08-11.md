# Book navigation architecture study — 2026-08-11

**Scope:** chapter order, sidebars, previous/next links, localization
boundaries, and repository structure in mature documentation projects.

**Status:** `candidate` / `reference-only`
**Accessed:** 2026-08-11 (America/Los_Angeles)
**Decision boundary:** This record extracts information-architecture principles
only. It does not copy external prose, code, images, styles, fonts, logos, or
brand language.

## Findings first

The projects agree on one important design rule: the visible tree and the page
footer must be derived from the same ordered navigation model. The model may be
a handwritten summary, a sidebar configuration, or a generated sidebar, but it
must have an explicit owner and predictable handling for drafts, parts,
locales, and non-page entries.

For this repository, the practical consequence is a small canonical source at
[`docs/governance/book-navigation.yaml`](../governance/book-navigation.yaml).
It drives the chapter footer generator and validator while leaving learning
levels, translation identity, and content maturity in their existing contracts.

## The model we are adopting

```text
canonical chapter order
        │
        ├── human-readable table of contents (separate route index)
        ├── English previous/next footer when an English source exists
        ├── legacy Chinese previous/next footer for the current source path
        └── structural validator
```

The generator intentionally does not generate the whole site. The public site
has a separate learning-path contract and generated data because its job is
discovery rather than page-by-page book rendering.

## Boundary cases that must remain visible

1. **First chapter:** only the next link appears in the footer.
2. **Middle chapter:** previous and next links appear in the footer.
3. **Last chapter:** only the previous link appears in the footer.
4. **Part boundary:** the link still follows the canonical sequence; the part
   label belongs to the table of contents, not a hidden navigation rule. The
   table of contents is a separate route index, not a footer button.
5. **Missing English source:** the English footer links to the current source
   only with `migration pending`; it does not claim that the target is English.
6. **Legacy reading path:** unsuffixed files keep Chinese links so the existing
   path does not unexpectedly switch language.
7. **Draft or future page:** a future framework adapter must decide whether the
   entry is a disabled draft or a navigable page; it must not silently invent a
   URL.

## What this study does not establish

- It does not prove that any framework is installed or suitable for this
  repository's deployment surface.
- It does not prove browser rendering, accessibility, search, or mobile layout
  for this project.
- It does not turn WorkBuddyGuide's public structure into permission to copy
  its content or assets.
- It does not establish that automatic directory ordering is safe for a
  curriculum without an explicit order contract.
