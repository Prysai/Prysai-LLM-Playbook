# 社群教學導入：更好的新手開場，而不是產品來源

**狀態：**`candidate` 研究記錄。  
**決定：**將提供的社群教學保留為 `reference-only` 訊號；不嵌入播放器、不複製逐字稿、不重用截圖，也不把它當成目前產品行為的依據。

## 這份記錄支援的決定

提供的 Bilibili/BibiGPT 材料有一項有用的編輯優點：從熟悉的名稱開始，讓新讀者知道為何值得繼續，並圍繞一個具體專案前進，而不是孤立列出控制項。這是教學模式，不是重用其表達的授權，也不是目前產品主張的依據。

這份記錄回答一個狹窄問題：**在保持自己的文字、來源與證據誠實的前提下，本指南能從這種教學模式學到什麼？**

答案是：在任何功能導覽之前，先從一個可觀察的問題開始：

> 當語言模型工具說它已經完成時，在相信結果前，你能檢查什麼？

這個問題適用於 Codex、Claude Code 與其他模型輔助工作介面，但不宣稱它們的控制項、權限、持久性或 Agent 行為等價。

## 通用課程的原創開場

這是第 1 章目前採用的讀者導向。它是專案原創文字，不是逐字稿或翻譯：

> 你可能聽過 Codex、Claude Code 這些名稱。它們是更大變化的例子：語言模型現在可以配合任務、情境，有時還能使用工具，而不只是回傳聊天回覆。在導覽控制項前，先學會一個讓後面更容易的問題：工具說它完成了，你實際能檢查什麼？
>
> 在第一課，你不需要背產品。你會區分建議行動與獲准行動、工具訊息與目標改變，以及看似合理的回答與證據。這裡會深入教 Codex 旗艦實作路徑；方法更廣，任何具名平台都要先有自己的介面卡，才能把按鈕當成事實教學。

這種開場給新手邀請、可用的心智模型與清楚的收穫，同時避開「核心產品」、「最佳選擇」或「另一產品的直接等價物」等未獲支持的說法。

## 前十分鐘：一個承諾，一條界線

基礎課程不該一開始就要求讀者選模型、付款方案、外掛或權限模式，而應做出一個小承諾：

1. **說明一個結果。**例如：改寫虛構訊息但不加入事實，或檢查單一檔案變更。
2. **展示起始材料。**要求模型行動前，讓學習者看到確切文字、檔案或 fixture。
3. **說明行動界線。**說明任務是純文字、唯讀，或允許一次可復原變更。不要使用秘密或外部帳號。
4. **展示檢查方式。**讀者說明哪些必須維持、哪些必須改變、哪些仍未知。
5. **讓停止變安全。**若目標、權限或證據不清楚，就停止並回報最小下一項檢查，而不是擴大存取。

現有的選用暖身練習用虛構來源訊息遵循這個模式。第 1 章開場現在說明，為何這個小結果比長長的功能清單更有價值。

## 命名含義：通用方法與明確旗艦

內容應分兩層：

- **通用方法：**定義結果，只選必要情境，設定行動界線，檢查證據，復原並保留記錄；
- **旗艦實作路徑：**在有目前一手來源、有界執行、失敗證據和複核日期的地方深入教 Codex。

Claude Code 與其他具名系統是比較或介面卡候選，不是可互換替代品。待處理的產品命名建議與分階段遷移記錄在[命名過渡說明](../strategy/naming-and-positioning-transition-2026-08-14.md)。
