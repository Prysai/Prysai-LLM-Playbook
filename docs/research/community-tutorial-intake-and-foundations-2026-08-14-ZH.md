# 社区教程导入：更好的新手开场，而非产品来源

**状态：**`candidate` 研究记录。  
**决定：**将提供的社区教程保留为 `reference-only` 信号；不嵌入其播放器、不复制其文字稿、不复用其截图，也不把它当作当前产品行为的依据。

## 这份记录支持的决定

提供的 Bilibili/BibiGPT 材料有一个有用的编辑优点：从熟悉的名字开始，让新读者知道为什么值得继续，并围绕一个具体项目推进，而不是孤立罗列控件。这是教学模式，不是复用其表达的许可，也不是当前产品声明的依据。

这份记录回答一个有限问题：**在保持自己的文字、来源和证据诚实的前提下，本指南可以从这种教学模式中学到什么？**

答案是：在介绍任何功能之前，先从一个可观察的问题开始：

> 当语言模型工具说自己已经完成时，在相信结果之前，你能检查什么？

这个问题适用于 Codex、Claude Code 和其他模型辅助工作界面，但不宣称它们的控制、权限、持久性或 Agent 行为等价。

## 通用课程的原创开场

这是第 1 章目前采用的面向读者方向。它是项目原创文字，不是文字稿或翻译：

> 你可能听过 Codex、Claude Code 这样的名字。它们体现了更大的变化：语言模型现在可以结合任务、上下文，有时还可以使用工具，而不只是返回聊天回复。在参观任何控件之前，先学会一个能让后面更容易的问题：当工具说自己完成了，你实际能检查什么？
>
> 在第一课中，你不需要背产品名称。你会区分建议的行动和获准的行动、工具消息和目标发生的变化、看起来合理的答案和证据。这里会深入讲 Codex 这条旗舰实践路径；方法本身更广，任何指定平台都必须先拥有自己的适配器，才能把按钮当作事实来教。

这样的开场给新手一个邀请、一个可用的心智模型和清晰的收获，同时避开“核心产品”“最佳选择”或“另一个产品的直接等价物”等未经支持的说法。

## 前十分钟：一个承诺，一条边界

基础课程不应一开始就让读者选择模型、付费套餐、插件或权限模式，而应作出一个小承诺：

1. **说清一个结果。**例如：不添加事实地改写一条虚构消息，或检查一个单文件改动。
2. **展示起始材料。**在要求模型行动前，让学习者看到确切的文字、文件或 fixture。
3. **说明行动边界。**说清任务是纯文本、只读，还是允许进行一次可逆改动。不要使用秘密或外部账号。
4. **展示检查方式。**读者说明什么必须保持、什么必须改变、什么仍然未知。
5. **让停止变得安全。**如果目标、权限或证据不清楚，就停止并报告最小的下一项检查，不要升级访问权限。

现有的可选热身练习用一条虚构源消息遵循这个模式。第 1 章的开场现在解释了为什么这样的小结果比长长的功能列表更有价值。

## 命名含义：通用方法，明确旗舰路径

内容应分成两层：

- **通用方法：**定义结果，只选择必要上下文，设定行动边界，检查证据，恢复，并保留记录；
- **旗舰实践路径：**在有当前一手来源、有界运行、失败证据和复核日期的地方深入讲 Codex。

Claude Code 和其他指定系统是比较或适配器候选，而不是可互换的替代品。待处理的产品名称建议和分阶段迁移记录在[命名过渡说明](../strategy/naming-and-positioning-transition-2026-08-14.md)中。
