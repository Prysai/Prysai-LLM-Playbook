## Niveaux de preuve et règles de réexamen

- Un `signalement utilisateur` prouve seulement que la personne dit avoir observé le symptôme dans l’environnement indiqué ; plusieurs environnements ne constituent pas automatiquement une confirmation officielle.
- Une `suggestion de répondant` consigne un contournement communautaire et ses risques ; elle ne devient pas une syntaxe de configuration ni une politique de support actuelle.
- Une `confirmation officielle` exige une réponse de mainteneur, une documentation officielle, un relevé de correction ou une note de version vérifiable ; un bot de dédoublonnage ne compte pas.
- Une `reproduction locale` ne peut être renseignée qu’après exécution dans ce projet et conservation des preuves ; l’index n’en contient aucune.
- Lorsqu’un cas volatil est cité, conserver URL d’origine, état de l’Issue, version/plateforme signalée, date d’accès et limite « non reproduit dans ce projet ». `closed` décrit l’état de la page, pas une correction ni la disponibilité pour tous les comptes.

## Limites des forums et des licences

Les pages Stack Overflow sont marquées CC BY-SA 4.0. Le projet ne reprend que des résumés factuels, la structure du problème et les liens ; il ne copie ni longs passages, ni code, ni commandes des répondants. Les Issues GitHub sont citées comme sources de signalements publics, pas comme confirmation d’OpenAI. Auteurs, étiquettes et résultats de recherche ne changent pas cette limite. Reddit, GitHub Discussions et les pages impossibles à vérifier de manière fiable n’entrent pas dans les preuves principales.

**Prochain réexamen :** revisiter les URL originales et consigner réponses des mainteneurs, PR liées, versions corrigées, état de la page et périmètre actuel. Sans nouvel élément, conserver `candidate`, `unverified` ou `blocked` et ne pas passer à `verified`.
