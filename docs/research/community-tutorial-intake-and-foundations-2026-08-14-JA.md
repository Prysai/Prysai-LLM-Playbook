# コミュニティ教材の受け入れ：初心者の入口を良くするためであり、製品の出典ではない

**状態：**`candidate` の調査記録。  
**判断：**提供されたコミュニティ教材は `reference-only` の手がかりとして残す。プレーヤーを埋め込まず、トランスクリプトをコピーせず、スクリーンショットを再利用せず、現在の製品動作の根拠にしない。

## この記録が支える判断

提供された Bilibili/BibiGPT の資料には、編集上の有用な強みが一つある。聞き慣れた名前から始め、初めて読む人が続ける理由を示し、操作を孤立して列挙するのではなく、一つの具体的なプロジェクトを追うことだ。これは教え方のパターンであり、表現を再利用する許可でも、現在の製品について主張する根拠でもない。

この記録が答えるのは限定した問いだ。**自分の文章、出典、証拠を正直に保ちながら、この教え方から何を学べるか。**

答えは、機能を案内する前に観察可能な一問から始めることだ。

> 言語モデルのツールが「完了した」と言ったとき、結果を信じる前に何を確認できますか。

この問いは Codex、Claude Code、その他のモデル支援ワークサーフェスにも使える。ただし、制御、権限、永続性、Agent の挙動が同じだとは主張しない。

## 一般コースのためのオリジナルな導入

これは現在 Chapter 1 の冒頭で使っている読者向けの方向性である。トランスクリプトや翻訳ではなく、本プロジェクトが書いた文章だ。

> Codex や Claude Code という名前を聞いたことがあるかもしれません。これは大きな変化の例です。言語モデルは、チャットの返答だけでなく、タスク、コンテキスト、場合によってはツールを扱えるようになりました。操作を一つずつ見る前に、後を簡単にする問いを覚えましょう。「完了した」とツールが言ったとき、実際に何を確認できますか。
>
> 最初のレッスンで製品を暗記する必要はありません。提案された行動と許可された行動、ツールのメッセージと対象の変化、もっともらしい回答と証拠を分けます。ここでは Codex を旗艦の実践ルートとして深く扱います。方法はより広く、名前を挙げる platform は、ボタンを事実として教える前に自分の adapter を持つ必要があります。

この導入は初心者への誘い、使えるメンタルモデル、明確な見返りを与え、「中心の製品」「最良の選択」「別製品の直接の等価物」といった裏付けのない主張を避ける。

## 最初の10分：一つの約束、一つの境界

基本レッスンは、モデル、料金プラン、プラグイン、権限モードの選択から始めない。小さな約束を一つ示す。

1. **一つの結果を名前で示す。**例えば、架空のメッセージを事実を足さずに書き換える、または一つのファイルの変更を確認する。
2. **開始材料を見せる。**モデルに行動を求める前に、正確な文章、ファイル、fixture を学習者に見せる。
3. **行動の境界を述べる。**テキストだけか、読み取り専用か、可逆な変更を一度だけ許すのかを明記する。秘密や外部アカウントは使わない。
4. **チェックを見せる。**何を維持し、何を変え、何が不明かを読者に言ってもらう。
5. **止まっても安全にする。**対象、権限、証拠が不明ならアクセスを広げず、最小の次のチェックを記録して止める。

既存の任意ウォームアップは架空の元メッセージでこの形を使う。Chapter 1 の導入では、控えめな最初の結果が長い機能一覧より価値がある理由を説明している。

## 名前の意味：一般的な方法と明示した旗艦

内容は二層で説明する。

- **一般的な方法：**結果を定義し、必要なコンテキストだけを選び、行動の境界を設定し、証拠を確認し、復旧して記録を残す。
- **旗艦の実践ルート：**現在の一次ソース、範囲を限定した run、失敗の証拠、レビュー日があるところで Codex を深く教える。

Claude Code やその他の名前付きシステムは比較・adapter の候補であり、互換性のある代替ではない。保留中の製品名の提案と段階的な移行は、[命名移行ノート](../strategy/naming-and-positioning-transition-2026-08-14.md)に記録している。
