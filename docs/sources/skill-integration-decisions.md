## 2. 采用原则

### 2.1 先转译能力，再决定组件

外部内容只能经过以下转换链进入 Field Guide：

```text
外部资产
  → 提取可迁移的概念、方法或失败模式
  → 核对来源、许可证、归属、依赖和权限
  → 用项目语言重新解释
  → 放入“问题—概念—决策—行动—证据—失败—反思”结构
  → 添加低风险实验、验收清单和迁移练习
  → 做正例/边界例/失败例/迁移例验证
  → 登记来源、改动、责任人和复核日期
```

仅改变措辞、翻译标题、拼接多个原 skill 或把提示词改成中文，不算原创转译。转译后的内容必须有 Field Guide 自己的教学目标、任务协议、停止条件、证据标准和失败处理。

### 2.2 采用的最小门槛

候选能力只有在同时满足以下条件后，才可进入 Field Guide 主线或作为 Field Guide skill 的实现依据：

- 任务触发范围清楚，并写明不适用范围；
- 输入、上下文、工具、网络、账户和权限要求可检查；
- 有主要路径、失败路径和停止条件；
- 有至少一个可检查的输出断言；
- 许可证、归属、嵌套文件、依赖和维护来源可追踪；
- 通过正例、边界例、失败例、迁移例和一次新鲜上下文验证；
- 不会把外部文本、工具结果或候选 skill 内的指令当作更高优先级命令；
- 外部副作用、秘密、不可逆动作和用户确认点已明确。

### 2.3 原创主线的保护原则

Field Guide 的核心资产是学习路径、解释、实验、评测、证据规范和项目团队方法。外部项目可以影响问题选择和验证假设，但不能决定 Field Guide 的叙事、章节结构、品牌表达、示例文本或发行内容。外部内容中出现的“已验证”“官方支持”“可以自动完成”等声明，必须重新核实，不能作为自身证据。

## 3. 采用原则下的各来源决策

## 4. 仅参考

以下材料当前只能用于研究、比较或教学设计启发：

- S01 整体：没有明确许可证信号，不能复制其正文、图像、代码、站点结构或品牌表达；
- S03 整体：它是索引，不是实现，不能把数量、排序或描述当作质量证据；
- S02 的原始实现和教学资产：即使许可证允许特定非商业使用，也不能在未确认 Field Guide 发行模式、归属和衍生边界前纳入发行版；
- S04、S05、S06 中尚未逐项完成许可证、依赖、触发、权限和评测审查的条目。

“仅参考”不等于来源不重要。它们可以帮助 Field Guide 发现学习问题、失败模式和候选实验，但最终内容必须由 Field Guide 重新定义目标、输入、行动、证据和反思。

## 5. 不采用

当前明确不采用以下集成方式：

1. **不直接复制写书内容。** S01 的教材、章节、图像和 PDF 可能包含受版权保护的表达；许可证不明确时，复制、翻译或轻度改写都不能视为安全。Field Guide 应从读者问题和能力目标出发，重新编写解释、例子和验收标准。
2. **不直接复制课程结构。** 外部课程的章节顺序、练习编排和叙事可能是其原创表达或产品资产。Field Guide 只抽取可迁移的主题与学习结果，再按“概念—判断—操作—实验—复盘—迁移”重新组织。
3. **不直接复制练习和评测。** 练习的具体情境、输入、期望答案、评分标准和失败案例可能构成受保护内容，也可能不适合 Field Guide 的安全边界。Field Guide 要为每个能力单元设计低风险、可观察、可恢复的新实验，并用自己的证据断言验收。
4. **不直接复制研究 workflow 或学术写作模板。** S02 的 CC BY-NC 4.0 与 NOTICE 只说明需要进一步遵守的许可条件，不自动允许商业发行、改编后去除归属或纳入本项目。研究方法应转译成问题收敛、来源计划、证据抽取、引用覆盖和局限披露的原创协议。
5. **不把外部 skill 当作 Field Guide 的同名实现。** 即使 MIT 或 Apache-2.0 信号存在，也要审查嵌套资产、依赖、工具权限、认证和实际行为；许可证允许复制不等于内容适配、安全或质量已经通过。
6. **不批量安装或批量合并候选目录。** 目录数量不能证明价值，批量操作会扩大触发冲突、供应链、权限、维护和许可证风险；选择必须由具体任务和最小有效组合驱动。
7. **不采用需要无条件外部写入或高权限动作的能力。** 部署、发版、批量删除、自动提交、发送消息、访问生产数据或使用秘密的候选，除非另有明确授权、范围限制、确认点、回滚和运行证据，否则保持 blocked。

## 6. 需逐项复核

### 6.1 复核字段

任何从“仅参考”升级为 `adaptation-candidate`、`vendored-with-notice` 或 `original-rewrite` 的条目，都必须补齐：

| 字段 | 要求 |
|---|---|
| 来源 | 上游 URL、仓库提交/版本、归档 SHA-256、访问日期 |
| 许可证 | 根目录许可证、嵌套许可证、NOTICE、第三方依赖及适用范围 |
| 内容边界 | 借鉴的是事实、概念、算法、接口、表达还是代码；哪些内容被排除 |
| 行为边界 | 触发、不触发、工具、网络、账户、权限、秘密和外部副作用 |
| 改写记录 | Field Guide 自有目标、结构、示例、实验、失败案例和修改责任人 |
| 证据 | 正例、边界例、失败例、迁移例、新鲜上下文测试和可检查输出 |
| 维护 | 上游变更监测、Field Guide 所属文件、负责人、版本和下次复核日期 |

### 6.2 来源级复核重点

- **S01：** 获取并记录权威许可证 URL 或授权证明；在此之前保持 `reference-only`。
- **S02：** 解决两个同名 `academic-research-suite` 路径的重复关系，确认实际发行树；逐一阅读主许可证、两个研究许可证、NOTICE 和实验代理许可证；确认 CC BY-NC 4.0 对 Field Guide 当前发行模式的适用性。
- **S03：** 核对 MIT 许可证与清单归属，避免把索引描述误写成已评测能力。
- **S04：** 为每个拟采用的 49 项候选记录上游版本、归属、触发边界、依赖和 Field Guide 改写差异；优先选择能支持营销轨且无外部写入的最小集合。
- **S05：** 从生命周期骨架中抽取方法，不以整套外部 skill 作为依赖；为每个 Field Guide 对应章节和实验建立独立证据。
- **S06：** 先清理重复、空描述、模板条目、命名异常和外部认证依赖；逐项确认嵌套许可证，不因根目录 Apache-2.0 自动放行；对部署、GitHub、支付、数据库、消息和生产服务动作默认提高门槛。

### 6.3 来源记录当前遗漏

现有 `docs/sources/asset-register.md` 已有六个来源、归档路径、结构摘要、许可证信号、决策和 SHA-256，但尚未为每个来源稳定记录：权威 URL、访问日期、许可证适用范围、复核负责人、下次复核日期、上游提交/版本和最终发行版许可证。上述字段必须在任何候选升级前补入台账或等价的逐项记录。

此外，S02 的同名双路径重复、S06 的根许可证与嵌套内容边界、S01 的无许可证状态，都是当前不能被“目录已生成”掩盖的已知缺口。候选目录中的 `unreviewed-candidate` 只能表示发现，不表示许可或质量通过。

## 7. 后续转译模板

每个要进入 Field Guide 的外部能力，先创建一份内部转译记录：

```text
能力问题：学习者/团队遇到的真实问题是什么？
外部观察：来源展示了什么方法或失败模式？
许可证边界：允许参考、改编、随产品发布到什么范围？
Field Guide 决策：采用原则 / 仅参考 / 不采用 / blocked
原创解释：用 Field Guide 领域词汇如何说明概念和取舍？
原创行动：最小安全任务、输入、允许动作和停止条件是什么？
原创证据：哪些文件、测试、日志、来源或人工验收可以证明结果？
失败实验：如何制造一个低风险失败，学习者如何发现和恢复？
迁移练习：如何迁移到工程、研究、营销、文档或团队场景？
维护责任：谁维护、何时复核、上游变化如何触发重审？
```

完成该记录并通过项目验证后，才可以考虑把能力从外部参考层提升为 Field Guide 的 `original-rewrite` 或经许可的外部组件。当前本文件和现有 7 个 skill 的整体状态仍为 `candidate`，不宣称生产就绪。
