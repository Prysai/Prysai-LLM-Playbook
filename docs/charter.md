# Prysai LLM Playbook — From First Task to Reliable Work 产品章程

**版本：** v0.1
**日期：** 2026-08-09
**维护组织：** Prysai Lab
**状态：** `candidate`；核心课程重构进行中

## 1. 愿景

让没有开发背景的人先理解语言模型的工作边界，完成一次低风险、可检查的对话实践，
再逐层进入 Codex、工具、Agent、Skill 和团队协作。高级内容继续存在，但不再决定第一条学习路径的复杂度。

## 1.1 产品定义

本项目是一套以 LLM 基础核心为默认入口、以 Codex Practice Track 为后续旗舰投影的学习与实践系统，而不是 Skill 目录。它先回答五个基础问题：

1. **它是什么：** LLM 如何根据上下文生成文字，以及为什么流畅不等于真实；
2. **它怎么开始：** 如何用目标、必要上下文、约束和输出形式发起一次小请求；
3. **它哪里会错：** 如何发现遗漏、无依据添加、歧义补全和过度自信；
4. **它是否满足任务：** 如何逐项检查、最小修正并说明仍未证明的部分；
5. **它能否迁移：** 如何在未见任务中独立重复定义、尝试、检查、修正和限制说明。

Codex、工具、Agent、Skill、专业轨和团队治理属于核心之后的选修或参考层。没有原理理解、
实验练习、证据审查和学习者观察，单独安装再多 Skill 也不等于掌握 LLM 协作。

## 2. 核心承诺

完成 LLM 基础核心后，学习者只能声明以下范围内的能力：

1. 用自己的话解释 LLM、上下文、模型、产品和工具的最小边界；
2. 写出一次包含目标、上下文、约束和输出形式的简短请求；
3. 对固定输出标出遗漏、添加、歧义和过度自信，并引用原文证据；
4. 用 `PASS / FAIL / UNSURE` 检查并最小修正一份输出，保存前后差异；
5. 在未见任务中完成一次独立检查，并披露使用的帮助和仍未证明的部分。

这些结果不代表长期掌握、生产力提升、职业能力、跨领域迁移或平台等价。Codex、Agent、Skill、
专业轨和团队治理必须在核心之后单独学习和验证。

## 3. 不做什么

- 不把本项目做成单纯的 skill 下载站；
- 不把某一模型、某一界面或某一价格写成永恒事实；
- 不以“输出像真的”代替运行证据、来源证据或用户验收；
- 不复制许可证不清晰的外部教材或 skill；
- 不鼓励把所有权限、所有仓库和所有连接一次性开放给 Agent；
- 不用大量术语制造学习门槛，先教可观察的行为，再解释背后的原理；Codex 和 Skill 不作为 LLM 基础前置知识。

## 4. 目标人群

### LLM 基础初学者

使用过 ChatGPT 或相似聊天产品，但不理解 LLM 为什么会出错，也没有稳定检查习惯。目标是完成第一次低风险、可检查的 LLM 实践。

### Codex 与专业进阶学习者

已经完成 LLM 基础核心，需要把同一方法用于文件、终端、研究、内容、工程或团队流程。该人群不再决定默认入口的复杂度。

### 创作者与独立开发者

希望从想法走到原型、网站、内容或自动化流程。目标是形成从需求到交付的闭环。

### 工程师与研究者

需要可复现、可审查、可验证的工作流。目标是把 Codex 纳入专业流程，而不是替代专业判断。

### 团队负责人

希望统一团队使用方式和安全边界。目标是建立组织级上下文、skills、评测、权限和贡献流程。

## 5. 产品原则

### 先建立判断，再增加能力

用户在不知道边界时，增加工具只会增加风险。每个能力都必须伴随适用范围、失败方式和验证方式。

### 解释和实践必须相邻

每个概念之后都要有一个小实验；每个实验之后都要有复盘，说明发生了什么、为什么发生、如何判断成功。

### 能力按生命周期组织

内容主线围绕 `定义 → 计划 → 执行 → 验证 → 复盘 → 交付 → 维护`，而不是围绕工具名称堆叠。

### 证据优先

“我让 Codex 做了”不是完成标准。完成标准必须说明可检查的文件、测试、日志、页面、来源、差异或用户验收证据。

### 对变化保持诚实

稳定原理和易变事实分开写。所有易变事实带来源、访问日期、适用范围和复核责任人。

## 6. 成功指标

本项目的成功不以文档字数或 skill 数量衡量，首批指标为：

- 初学者能否在不复制粘贴整段提示词的情况下完成首个安全实验；
- 学习者能否解释自己选择某个 skill、工具和权限的原因；
- 学习者能否发现一个故意植入的错误或未完成声明；
- 学习者能否用证据复现和审查一个工作流；
- 新版本发布时，易变事实能否被定位、复核和更新；
- 团队贡献者能否按规范新增一个章节、实验或 skill。

## 7. 当前关键假设

团队希望围绕 GPT-5.6 Luna 建立高性价比、低门槛的学习体验。这个假设必须拆成可验证指标：任务成功率、首次通过率、耗时、成本、返工率、用户主观满意度和不同任务类型的稳定性。本项目的模型章节会教如何进行这类比较，而不会提前宣布结论。
