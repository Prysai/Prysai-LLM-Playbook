# Prysai Codex Atlas 产品章程

**版本：** v0.1
**日期：** 2026-08-09
**所有者：** Prysai Lab
**状态：** 工作基线

## 1. 愿景

让任何人都能从“听说过 GPT”开始，逐层建立对 Codex 的正确认识、操作能力、判断能力和组织协作能力，最终能够把 Codex 变成可靠的工作伙伴，而不是偶尔生成漂亮答案的聊天窗口。

## 1.1 产品定义

Atlas 是一套 Codex GPT 能力系统，而不是 Skill 目录。它同时回答五个问题：

1. **它是什么：** GPT、模型、Codex、上下文、工具、Skill、Agent 和权限分别是什么，以及它们如何共同影响行为；
2. **它怎么用：** 如何把目标、背景、输入、约束和验收标准组织成可执行任务；
3. **它为什么这样工作：** 如何从可观察的上下文、工具调用、反馈和停止条件解释 Agent 行为；
4. **它是否真的有效：** 如何用运行、来源、视觉、安全、完整性和用户验收证据检查结果；
5. **它如何成为能力：** 如何把个人实践沉淀成 Skill、项目上下文、实验、评测和团队规范。

因此，Skill 只是 Atlas 的一个能力层。没有原理理解、实验练习、证据审查和持续更新，单独安装再多 Skill 也不等于掌握 Codex。

## 2. 核心承诺

完成 Atlas 主线后，学习者应当能够：

1. 解释 GPT、模型、Codex、上下文、工具、skill、Agent 和权限之间的关系；
2. 根据目标和风险选择合适的 Codex 入口、模型、工具和工作模式；
3. 把模糊目标转化为有边界、有输入、有验收标准的任务；
4. 让 Codex 在真实文件、代码、浏览器或外部服务上工作，并控制副作用；
5. 选择、安装、调用、组合、调试和评估 skills；
6. 识别 Agent 的计划、工具调用、反馈、重试和交付逻辑；
7. 对输出进行事实、运行、视觉、安全和完整性验证；
8. 将个人方法沉淀为团队可复用的 skill、AGENTS.md、实验和规范；
9. 在产品更新、模型变化和工具变化后，重新审查自己的方法。

完成主线的学习者应能把“会让 AI 生成内容”迁移为“会设计一套有边界、可观察、可验证、可恢复的协作流程”。

## 3. 不做什么

- 不把 Atlas 做成单纯的 skill 下载站；
- 不把某一模型、某一界面或某一价格写成永恒事实；
- 不以“输出像真的”代替运行证据、来源证据或用户验收；
- 不复制许可证不清晰的外部教材或 skill；
- 不鼓励把所有权限、所有仓库和所有连接一次性开放给 Agent；
- 不用大量术语制造学习门槛，先教可观察的行为，再解释背后的原理。

## 4. 目标人群

### 初学者

知道 ChatGPT，但不理解 Codex、代码项目、工具和权限。目标是完成第一个安全的真实任务。

### 创作者与独立开发者

希望从想法走到原型、网站、内容或自动化流程。目标是形成从需求到交付的闭环。

### 工程师与研究者

需要可复现、可审查、可验证的工作流。目标是把 Codex 纳入专业流程，而不是替代专业判断。

### 团队负责人

希望统一团队使用方式和安全边界。目标是建立组织级上下文、skills、评测、权限和贡献流程。

## 5. 产品原则

### 先建立判断，再增加能力

用户在不知道边界时，增加工具只会增加风险。每个能力都必须伴随适用范围、失败方式和验证方式。

### 解释和实践必须相邻

每个概念之后都要有一个小实验；每个实验之后都要有复盘，说明发生了什么、为什么发生、如何判断成功。

### 能力按生命周期组织

内容主线围绕 `定义 → 计划 → 执行 → 验证 → 复盘 → 交付 → 维护`，而不是围绕工具名称堆叠。

### 证据优先

“我让 Codex 做了”不是完成标准。完成标准必须说明可检查的文件、测试、日志、页面、来源、差异或用户验收证据。

### 对变化保持诚实

稳定原理和易变事实分开写。所有易变事实带来源、访问日期、适用范围和复核责任人。

## 6. 成功指标

Atlas 的成功不以文档字数或 skill 数量衡量，首批指标为：

- 初学者能否在不复制粘贴整段提示词的情况下完成首个安全实验；
- 学习者能否解释自己选择某个 skill、工具和权限的原因；
- 学习者能否发现一个故意植入的错误或未完成声明；
- 学习者能否用证据复现和审查一个工作流；
- 新版本发布时，易变事实能否被定位、复核和更新；
- 团队贡献者能否按规范新增一个章节、实验或 skill。

## 7. 当前关键假设

团队希望围绕 GPT-5.6 Luna 建立高性价比、低门槛的学习体验。这个假设必须拆成可验证指标：任务成功率、首次通过率、耗时、成本、返工率、用户主观满意度和不同任务类型的稳定性。Atlas 的模型章节会教如何进行这类比较，而不是提前宣布结论。
