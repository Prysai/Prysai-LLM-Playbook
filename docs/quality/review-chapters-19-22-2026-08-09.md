# 第 19–22 章 fresh-context 独立审查报告

**审查日期：** 2026-08-09  
**审查方式：** fresh-context 独立阅读；未读取其他代理结论、既有审查报告或历史运行摘要。  
**审查范围：** `AGENTS.md`、`docs/charter.md`、`docs/book-architecture.md`、`docs/research/openai-codex-baseline.md`，以及实际存在的：

- `book/chapters/19-evaluate-models-and-workflows.md`
- `book/chapters/20-personal-codex-work-system.md`
- `book/chapters/21-team-capability-system.md`
- `book/chapters/22-continuous-update-and-future-proofing.md`

**文件名说明：** 请求中的第 20、22 章名称与工作区实际文件名不同；本审查以章节编号对应的实际文件为准。

## 总结结论

四章都具备问题、学习目标、核心概念、部分行动建议、失败变体、迁移练习和验收清单，主题也与章程的评估、个人系统、团队治理、持续更新主线一致。但目前只能作为 `candidate`，不应标记为 `verified` 或 `production-ready`。

主要原因：

1. 四章的“决策”通常埋在说明段落中，没有明确写出输入、选项、选择规则和选择结果；
2. 四章实验都缺少统一、可复制的 `setup / task / evidence / failure variant / reflection` 执行协议，尤其缺少具体产物、通过阈值、运行次数、环境边界和安全前置条件；
3. 第 20、21 章没有独立的易变事实与来源段落；第 19、22 章虽然有来源，但没有完整记录访问日期、适用范围、责任人和下一次复核日期；
4. 第 21 章的失败变体要求“把所有外部服务权限全部打开”，没有明确限定为纸面模拟或不可执行的安全替代，存在误导学习者实际扩大权限的风险；
5. 第 20、21、22 章没有明确的实验复盘问题，难以满足项目章程要求的“实验之后说明发生了什么、为什么发生、如何判断成功”。

## 审查标准

本审查将项目约定转译为以下检查链：

```text
问题 → 概念 → 决策 → 行动 → 证据 → 失败/边界 → 复盘 → 迁移/验收
```

同时检查：

- 易变事实是否绑定权威 URL、访问日期、适用范围、责任人和下一次复核日期；
- 是否把草稿、候选、已验证和生产就绪混用；
- 实验是否低风险、可观察、可执行、可复现，并明确秘密与外部副作用边界。

项目依据：`AGENTS.md` 的内容顺序、证据和状态要求；`docs/charter.md` 的“解释和实践相邻”“证据优先”“对变化保持诚实”；`docs/book-architecture.md` 的章节模板；`docs/research/openai-codex-baseline.md` 的产品事实和官方来源边界。

## 第十九章：评估模型和工作流

**文件：** `book/chapters/19-evaluate-models-and-workflows.md`  
**判断：** 结构最完整，评估框架清楚；但实验仍不足以让另一位学习者按同一条件复现，且产品定位的来源元数据不完整。

### 严重问题

#### S19-01：实验没有形成可复现的最小评测协议

**位置：** 第 96–107 行。  
**问题：** 实验只要求选择“低风险任务”并运行两次，但没有规定输入样本、固定任务文本、运行次数、允许修改范围、工作面、权限、验证命令、通过阈值、日志格式或结果文件。第 103 行的“记录前置时间、变更范围、首次通过、返工……”是指标清单，不是可执行记录协议。第 107 行的失败变体能发现条件改变，却没有规定如何保存两次运行的原始证据和如何判定“不可直接比较”。

**影响：** 学习者可以得到一个主观比较，但无法复跑、审查或区分流程差异与环境差异；这直接削弱本章“从感觉到证据”的教学目标。

**可操作修正：** 增加一个完整实验协议，至少规定：

- 固定的脱敏输入文件和任务 ID；
- 两条工作流的完整提示/任务协议版本；
- 同一工作面、工具、权限和时间预算；
- 至少 3 次重复或明确说明为何只做一次 smoke test；
- `run-id`、开始/结束时间、实际 diff、验证输出、首次通过和返工记录；
- 明确通过标准，例如“输出结构满足字段表、原文件不变、验证命令退出码为 0”；
- 失败时保留原始日志、标记不可比较，并不得直接合并结论。

#### S19-02：Luna 产品定位的来源绑定不完整

**位置：** 第 122–124 行。  
**问题：** 第 124 行称官方文档将 5.6 Luna 描述为“适合清晰、可重复任务的快速低成本模型”，但只链接到通用 Models 文档，没有链接具体模型页面，也没有在本章记录访问日期、适用账户/入口范围、责任人和下一次复核日期。该句虽明确说“不是 Field Guide 的评测结论”，但仍是一个易变产品事实。

**影响：** 读者无法从本章判断这条定位在何时、对哪个产品入口和版本成立；“快速低成本”也可能被理解成事实性性能或成本承诺。

**可操作修正：** 改为“官方产品定位（截至 YYYY-MM-DD）”的记录格式，链接基线中对应的具体官方模型页面；同时写明适用范围、owner、next review，并把“快速/低成本”限制为官方描述，不把它转换成实测结论。若本章不需要这条产品事实，可删除，只保留评测方法。

### 一般问题

#### G19-01：决策点没有显式化

**位置：** 第 17–28、82–94 行。  
**问题：** 章节给出了四种决策类型和评估流程，但没有提供一个“决策卡”让学习者填写候选方案、最低门槛、风险红线、结论动作和不确定性。当前文本容易让读者记录很多指标，却仍不知道何时选择、保留、拒绝或继续评估。

**可操作修正：** 在流程前加入：`决策对象 / 候选 / 最低质量门槛 / 风险红线 / 可接受成本 / 结论动作 / 适用范围 / 下一次复核` 模板，并要求实验最后填写。

#### G19-02：复盘被压缩成迁移和验收，缺少实验后的解释问题

**位置：** 第 96–111 行。  
**问题：** 有故意失败变体和迁移练习，但没有明确要求学习者解释“发生了什么、为什么不能比较、下一次如何改进”。这不完全满足章程对实验复盘的要求。

**可操作修正：** 增加 `### Reflection`，要求比较两条工作流的差异、指出一个混杂变量、解释一次失败分类，并写出下一轮只改变的一个条件。

#### G19-03：章节状态说明不够精确

**位置：** 第 41 行。  
**问题：** “本章仍只能标为草稿”是诚实的，但没有明确这是模型评估结论/实验夹具状态，还是整章内容状态。项目的 `draft / candidate / verified / production-ready` 词汇分别对应不同门槛，容易产生范围歧义。

**可操作修正：** 明确写成：“`evals/task-set-v1.yaml` 和 Luna 评估当前为 `draft / not run`；本章方法内容为 `candidate`，尚未以完整学习者实验复核。”

## 第二十章：建立个人 Codex 工作系统

**文件：** `book/chapters/20-personal-codex-work-system.md`  
**判断：** 概念和个人实践建议清楚，但实验证据不足，来源更新边界缺失，且“个人工作系统”的最小交付没有真正闭环。

### 严重问题

#### S20-01：没有独立的易变事实与官方来源段落

**位置：** 第 101–103 行。  
**问题：** 章节最后只有“稳定原则”说明，称具体文件名、产品入口和记忆功能应以当前官方文档和组织规则为准，但没有官方 URL、访问日期、适用范围、owner 或 next review。第 9 行虽然链接了官方基线，却没有把任何具体易变断言与它绑定。

**影响：** 章节没有满足 `AGENTS.md` 和书籍架构要求的“来源与更新提示”；“记忆功能是否存在”本身就是易变产品事实，却被留在无来源的泛化表述中。

**可操作修正：** 将末节改为“易变事实与来源”，列出本章实际提到的产品入口、文件/上下文机制和记忆能力；每项绑定当前官方 URL、访问日期、适用入口/版本、维护人和下一次复核日期。若本章不需要具体产品能力，删除“记忆功能”并只保留稳定的方法论。

#### S20-02：个人系统实验无法产生足够的比较证据

**位置：** 第 75–86 行。  
**问题：** 实验要求连续完成两次任务，但没有定义同一任务是什么、第一次和第二次的基线、应建立哪些实际文件、如何记录重复说明、如何计算证据完整度、何时算“更好”，也没有明确临时目录/非生产环境、秘密和外部副作用边界。第 35–41 行列出五类资产，但实验只明确建立“项目地图、任务协议、状态日志和证据索引”，遗漏了复盘记录本身。

**影响：** 学习者可能只写几份模板并凭感觉说重复说明减少，无法证明个人系统改善了上下文质量或证据完整度；实验还可能在真实项目中误触外部动作。

**可操作修正：** 把实验写成低风险协议：指定脱敏任务和临时副本；明确第一次运行不使用个人系统、第二次使用四/五类记录；固定任务文本；记录输入长度、澄清轮数、实际变更、验证证据和复盘结果；规定至少两个运行样本和比较表；禁止生产、真实连接、秘密和发布动作；补充成功阈值和产物路径。

### 一般问题

#### G20-01：决策点隐含在“什么时候创建 Skill”中

**位置：** 第 63–73 行。  
**问题：** 五个问题是很好的判断提示，但没有把答案转成“创建 Skill / 保留任务协议 / 继续观察 / 拒绝保存”的行动规则，也没有说明由谁作出决定、决定证据是什么。

**可操作修正：** 增加决策表：若输入、决策点、输出连续三次稳定且有失败集，则进入 Skill 候选；若只有一次性需求，则保留任务协议；若含秘密或外部副作用未解决，则阻塞。

#### G20-02：复盘概念被定义了，但实验没有复盘输出

**位置：** 第 21–31、59–61、75–90 行。  
**问题：** 章节强调复盘记录和可迁移经验，却没有独立复盘问题或明确复盘文件。迁移练习记录的是“隐含知识缺口”，不等于实验复盘。

**可操作修正：** 增加 `Reflection` 产物，至少回答：哪条上下文被证明有用、哪条已经过时、哪个证据缺失、下次删除/保留/更新什么，以及这次经验能否迁移。

#### G20-03：真实问题入口不是现场问题记录

**位置：** 第 9 行。  
**问题：** 入口指向实验 001，而不是 `docs/research/field-problems-codex.md` 中的 FP 编号或现实问题记录。它能提供练习入口，但没有说明个人上下文系统如何回应真实失败，如认证阶段混淆、半成品恢复或过时环境。

**可操作修正：** 补充一个明确 FP 入口，并说明该 FP 只作为用户报告/研究证据，不是官方根因；将实验的失效地图或旧命令与该现实问题对应起来。

## 第二十一章：建立团队能力系统

**文件：** `book/chapters/21-team-capability-system.md`  
**判断：** 四层能力包和治理框架清楚，但当前失败实验存在安全表述缺口，团队能力包实验缺少可审查交付物，来源/更新段落也不完整。

### 严重问题

#### S21-01：失败变体可能误导学习者实际扩大外部权限

**位置：** 第 73–87 行，尤其第 85–87 行。  
**问题：** 失败变体要求“把所有外部服务权限全部打开”，但没有写“只做纸面模拟/静态配置审查，不得真实执行”，也没有定义安全的替代方式。

**影响：** 这与 `AGENTS.md` 的最小权限和不得扩大外部副作用要求冲突。学习者可能把“打开全部权限”当作可执行实验，造成数据暴露、外部写入或组织权限扩大。

**可操作修正：** 将变体改为：提供一份脱敏的权限清单或模拟配置，把所有外部能力标为 `requested`，不连接、不授权、不发送、不写入；要求学习者指出过宽权限、目标范围、审批人和回滚。明确写出“不得在真实账户、公共仓库、生产服务或带秘密环境执行”。

#### S21-02：团队能力包实验缺少可复现证据协议

**位置：** 第 73–87 行。  
**问题：** 实验列出一页上下文、一个协议/Skill、两个实验和三项证据，但没有规定能力包的目录结构、版本号、输入样本、执行步骤、另一位成员的独立运行记录、通过阈值、差异记录或失败后的处置。第 83 行的“记录隐含知识缺口”没有定义记录格式。

**影响：** 结果可能是团队成员口头反馈，而不是可审查的复现证据；“能力包交付”本身无法被另一个审查者验证。

**可操作修正：** 增加能力包最小清单：`README/上下文、任务协议或 SKILL.md、正例、失败例、证据索引、版本、owner、source、next_review、权限表、回滚说明`；规定独立成员在临时副本运行并保存日志/diff；给出三项通过标准和不通过条件。

### 一般问题

#### G21-01：没有独立的易变事实与来源段落

**位置：** 第 102–104 行。  
**问题：** “与 Field Guide 治理的连接”链接了项目治理文件，但没有官方基线链接、访问日期、适用范围、owner 或 next review；第 38 行的官方基线只是入口链接，不是本章易变断言的来源记录。

**可操作修正：** 增加“易变事实与来源”末节。若本章只讨论稳定治理方法，明确声明不引入产品事实；若保留 Codex、Skill、权限、发布等产品行为描述，则逐项绑定官方来源元数据。

#### G21-02：决策规则与责任分配仍偏概念化

**位置：** 第 40–71 行。  
**问题：** 章节区分了读取、编辑、运行、推送/发布和改权限，但没有把“谁能批准什么、什么证据允许升级、何时拒绝”写成操作决策表。学习者知道权限有层级，却未必能据此做一次真实审批。

**可操作修正：** 增加 `行动级别 / 数据范围 / 技术权限 / 任务授权 / 审批人 / 必需证据 / 回滚 / 复核频率` 表，并用一个沙盒、内部仓库、公共仓库三态例子填写。

#### G21-03：复盘只出现在迁移意图中

**位置：** 第 73–100 行。  
**问题：** 实验要求记录隐含知识缺口，但没有复盘问题来解释缺口为何出现、应改哪一层、如何验证修订有效。

**可操作修正：** 增加复盘步骤：按共同语言、方法、证据、治理四层分类缺口；选择一个缺口修订能力包；让第二位成员重新运行；比较修订前后的失败和证据。

## 第二十二章：持续更新与未来适应

**文件：** `book/chapters/22-continuous-update-and-future-proofing.md`  
**判断：** 更新生命周期和断言记录是四章中最接近可操作流程的部分；但实验边界、回滚、复盘和状态词汇仍不足，来源记录也没有满足项目的完整元数据要求。

### 严重问题

#### S22-01：实验允许在未限定目标的情况下修改文档和运行校验

**位置：** 第 85–91 行。  
**问题：** 实验要求“只修改需要修改的部分，然后运行项目校验和相关评测”，但没有指定临时分支/副本、具体文件、备份、允许副作用、评测是否真实运行、失败后的回滚方式或如何保存变更前后证据。

**影响：** 学习者可能直接在主工作树或生产资料中批量修改模型/工具事实。第 91 行的“恢复”也没有定义用什么可审查方式恢复，无法保证实验低风险、可逆和可观察。

**可操作修正：** 将实验限定为临时副本或独立分支，使用一条明确的脱敏断言和一个指定文件；先保存 hash/diff，再做最小修改；不使用真实凭据、不访问生产、不发布；记录影响表、来源记录、校验命令输出和回滚 diff；失败变体改为模拟批量替换并要求丢弃临时变更，而不是在工作区真实恢复。

#### S22-02：更新实验没有明确证据和复盘产物

**位置：** 第 85–104 行。  
**问题：** 有影响分析字段和失败变体，但没有要求保存更新前后的断言记录、影响矩阵、来源快照、变更 diff、验证结果、未验证项和下一次复核决定；也没有独立的复盘问题。

**影响：** 学习者可能完成一次“改名练习”，却不能证明自己正确定位了受影响范围，也不能解释为什么保留、迁移或下线某项能力。

**可操作修正：** 规定实验交付物：一份 `claim` YAML、影响矩阵、变更前后 diff、来源/访问日期、校验和评测日志、状态转换理由、回滚说明和复盘记录。复盘必须回答：漏掉了哪一层、哪个来源最关键、哪个未知仍未验证、下一次复核何时触发。

### 一般问题

#### G22-01：来源有 URL，但缺少项目要求的完整更新元数据

**位置：** 第 106–108 行。  
**问题：** 第 108 行链接了 Models 文档和内部生命周期文档，但没有在本章记录访问日期、适用范围、owner 和 next review。第 43 行的官方基线链接同样只是入口，没有绑定具体断言。

**可操作修正：** 直接使用第 45–57 行的 YAML 模板记录本章引用的每个易变事实，至少补齐 `source / checked_at / applies_to / owner / next_review / status`。若使用官方基线作为二级索引，应同时注明本章事实最终以哪个官方 URL 为准。

#### G22-02：`status` 词汇与项目内容状态可能混淆

**位置：** 第 45–59 行。  
**问题：** 本章为易变断言定义 `verified | stale | disputed | removed`；项目其他规范又使用 `draft / candidate / verified / production-ready` 描述内容和能力成熟度。当前没有说明两套状态分别作用于“断言”还是“章节/能力包”。

**可操作修正：** 明确命名空间，例如 `claim_status: current | stale | disputed | removed`，内容状态继续使用项目状态词汇；或者在模板旁写出两套状态的对象、转换条件和示例。

#### G22-03：决策出口没有足够明确

**位置：** 第 28–41、73–83 行。  
**问题：** 更新流程最后列出“发布、保留旧版或下线”，但没有给出选择规则、最低证据或批准人。例如来源消失时何时标记 `stale`，何时 `removed`，何时保留旧版并加迁移说明，都需要判断标准。

**可操作修正：** 增加决策表：来源仍有效→复核并保留；来源冲突→`disputed` 并暂停肯定性表述；无来源且无替代证据→`stale`；能力有安全/许可问题且无替代→`removed`；有兼容替代且迁移已验证→发布迁移说明。

#### G22-04：复盘没有独立位置

**位置：** 全章，尤其第 85–95 行。  
**问题：** 迁移练习有审查要求，但本章没有实验后的复盘问题；这使“持续更新”更像维护清单，而不是学习者能解释和改进的能力。

**可操作修正：** 在实验后增加复盘：变化属于哪一层、哪个假设被推翻、哪项证据不足、哪项变更可以删除、下次如何缩小更新范围。
