## 실제로 관찰한 내용

현재 Windows 작업 트리에서 저장소의 로컬 검사 일곱 가지를 같은 순서로 다섯 차례 연속 실행했습니다. 모든 실행이 성공적으로 끝났습니다. 차트는 각 검사의 중앙 실행 시간을 보여 주고, 표에는 다섯 번의 원시 측정값을 남겼습니다. 요약만 믿지 않고 직접 확인할 수 있게 한 것입니다.

## 이 결과가 말해 주는 것과 말해 주지 않는 것

유용한 엔지니어링 증거입니다. 지정한 일곱 가지 검사가 다섯 번의 연속적인 로컬 실행에서 안정적으로 통과했고, 이 작은 표본에서는 링크 감사가 가장 오래 걸렸습니다. 그러나 이것은 책, 모델 또는 Skill의 벤치마크가 아닙니다.

특히 이 수치만으로 독자가 더 빨리 배운다거나, Skill이 생산성을 높인다거나, 모델이 더 안전하고 정확하다고 말할 수 없습니다. 누구의 IQ가 변했다는 뜻도 아닙니다. 이 저장소에는 검증된 심리측정 도구, 자격을 갖춘 평가자, 그런 주장을 뒷받침할 윤리적 근거가 없으므로 IQ는 이 프로젝트의 운영 지표가 아닙니다.

별도의 [Shift Handoff 파일럿 프로토콜](shift-handoff-pilot-protocol-v1.md)은 훨씬 좁은 프로세스 결과를 관찰하기 위해 필요한 조건을 정의합니다. 승인된 비식별 실행 기록과 독립적인 채점자의 검토가 생길 때까지 초기 상태는 `candidate / not_run`으로 유지됩니다.

## 엔지니어링 관찰을 재현하는 방법

[AGENTS.md](../../AGENTS.md)에 기록된 프로젝트 환경을 사용하고, JSON 파일에 적힌 일곱 명령을 같은 순서로 다섯 번 실행하세요. 전체 출력, 종료 코드, 커밋 식별자, 운영 체제, 런타임, 로컬 작업 트리 상태를 보관하세요. 컴퓨터가 다르다는 이유만으로 실행 시간을 생산성 점수처럼 비교하지 마세요. 클린 체크아웃이나 CI 비교는 이번 관찰의 연장이 아니라 새로운 관찰입니다.

## 증거의 범위

이 관찰은 지정된 정적·구조 검사에만 한정됩니다. 검사를 통과해도 학습자의 이해, Skill의 런타임 동작, 자동 트리거, 출처 의미, 번역 품질, 브라우저 동작, 배포, 보안, 유용성 또는 출시 준비가 입증되는 것은 아닙니다.
