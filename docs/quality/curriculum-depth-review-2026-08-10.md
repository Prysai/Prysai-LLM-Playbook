# 课程含金量审查：从知道概念到能做决策

**审查日期：** 2026-08-10
**审查状态：** `candidate` 由于本报告只做结构和内容审查，没有运行学习者任务、模型评测或独立教学试验。
**审查范围：** 22 个章节、13 个实验、L0–L6 学习路径契约、`evals/task-set-v1.yaml` 的 39 项评测任务。
**审查目标：** 找出最容易停留在“理解术语/复述原则”的位置，并提出小而高价值、可直接落地的任务补强。

## 结论

课程的主线已经具备“概念—操作—失败—证据—迁移”的统一语言；L3 的 `lab-013` 也已经把完整的本地竖向切片写成了可执行规格。当前最影响含金量的不是缺少更多概念，而是三个高频决策仍没有足够小、足够具体的交付物：

1. 任务应该在哪个 Codex 工作面开始；
2. 一个外部 Skill 是否值得安装和启用；
3. 一个模型或工作流是否真的更适合当前任务。

这三处都已有章节、实验或评测的部分覆盖，但学习者仍可能只交出“选择理由”或“比较方案”，没有被迫留下能让另一人复核、恢复或否决的工作记录。

## 审查标准

把一个位置视为“能拿来做事”，至少要能产出以下六类东西：

1. **具体任务：** 有对象、范围和低风险目标；
2. **固定输入：** 学习者不需要临时猜文件、账户、版本或指标；
3. **可见输出：** 有决策卡、草稿、日志、差异或报告，而不是只有解释；
4. **失败变体：** 一个常见错误会迫使学习者停止、缩小范围或回滚；
5. **验收证据：** 第三方可以根据记录判断是否通过；
6. **迁移任务：** 能把判断规则改写到另一领域，而不是复制原答案。

## 最值得补强的三个位置

### 1. 第 5 章：选择工作面仍容易停在“分类题”

**涉及内容：** 第 5 章“选择正确的 Codex 工作面”、实验 007 的行动边界、章节中的“同一任务入口对照”实验，以及 `route-ownership-boundaries-032` 等评测任务。

**为什么含金量不足：** 章节已经给出上下文门、数据门、动作门、证据门和恢复门，也要求比较本地交互式入口、CLI 和 IDE。但它更像选择框架和比较表；学习者不一定需要真正为一个具体任务作出排除决定，也不一定需要交付“为什么某入口不适合”的可审查记录。真实用户最常见的错误是：能登录某入口，就把它当成能读目标仓库、能调用工具或能发布结果。

**最小补强任务：入口决策卡**

- **具体任务：** 对同一份脱敏 Markdown 发布说明，分别评估本地交互式入口、CLI 和 IDE；目标是只选择一个最小可行工作面完成本地草稿，不发布、不推送。
- **固定输入：** `input/brief.md`、`input/constraints.md`、一个没有远程地址的临时 Git 仓库；另附一张模拟的“浏览器登录成功但目标仓库不可读”状态卡。
- **必须输出：** `surface-decision.md`，至少包括任务目标、必须可访问的文件、不得离开的数据、允许副作用、入口支持状态、账户授权状态、本次实际可用状态、证据位置、恢复路径和最终选择；另附一张被否决入口的原因表。
- **失败变体：** 让登录页面显示成功，但目标仓库读取失败；或让 IDE 能看到文件却不能运行所需检查。正确结果是 `blocked` 或选择另一个入口，不能用登录成功补齐资源可读证据。
- **验收证据：** 相同输入和验收标准的三份入口记录；目标文件读取证据；实际 diff 或明确的“未执行”；检查输出；认证链路逐段 `passed / failed / not_observed`；第三方可仅凭记录解释为什么最终入口最合适。
- **迁移任务：** 把同一决策卡迁移到“需要浏览器查官方来源、终端生成本地证据、远程环境隔离客户数据”的研究任务，重写数据边界和最小证据，不复制工程入口结论。

**已有资产可复用：** 第 5 章的五道门、认证分段记录和入口对照实验；不需要新增章节或新 Skill。这个补强只需成为章节实验的一个固定任务版本，或作为现有 `permission-boundary` / 工作面评测的具体输入。

### 2. 第 7、14 章：Skill 安装前决策缺少真实“拒绝安装”产物

**涉及内容：** 第 7 章“Skill、Plugin、MCP 和工具如何分工”、第 14 章“发现、安装和审查外部 Skill”、实验 004、实验 005，以及 `skill-install-confirmation-rollback-037`、`route-explicit-over-implicit-031` 和 `source-conflict-license-boundary-036`。

**为什么含金量不足：** 这些内容已经正确区分推荐、安装、启用、认证和行为验证，也强调许可证和权限；但学习者仍可能只写“先检查许可证和回滚”，而不真正形成一个可以交给维护者批准或拒绝的安装前包。现实中最常见的错误不是不知道 Skill 是什么，而是把 GitHub 可访问、目录很大或文件存在误认为安全、可用和值得启用。

**最小补强任务：安装前审查包**

- **具体任务：** 从两个候选 Skill 中选择一个“推荐隔离试用”、一个“拒绝/暂不采用”；只做只读审查，不安装、不认证、不启用团队环境。
- **固定输入：** 候选仓库 URL、固定 revision、仓库目录清单、许可证/NOTICE 文件、Skill `SKILL.md` 的 frontmatter 摘要、工具/网络/凭据声明和当前项目的目标任务协议；其中至少一个候选故意缺少清晰许可证或回滚说明。
- **必须输出：** `skill-adoption-decision.md`，包含任务缺口、触发/不触发条件、来源与 revision、许可证结论、依赖、目标安装范围、潜在权限、副作用、隔离试运行计划、配置备份、回滚步骤、行为验证计划、负责人和最终状态：`recommendation-only`、`blocked` 或 `approved-to-install`。
- **失败变体：** 候选仓库能访问但许可证不明；或 Skill 文件存在但当前工作面未发现/未加载。正确结果是保留在审查或阻塞状态，不下载、不安装、不声称可用。
- **验收证据：** 来源和 revision 可复核；许可证结论指向实际文件；安装目标和回滚目标具体到路径/配置；批准点明确；至少一个正例、一个边界例、一个失败例和一个迁移例的行为验证计划；报告没有把“存在、可发现、已加载、已采用、已验证”混为一谈。
- **迁移任务：** 将审查包迁移到一个需要 MCP/connector 的研究任务，新增数据出口、认证、外部副作用和人工批准字段，并说明为什么原 Skill 的许可证判断不能直接替代连接器权限判断。

**已有资产可复用：** 第 14 章的审查卡、实验 004 的候选状态和实验 005 的 Skill 质量要求；评测 037 已覆盖安装批准与回滚，但应以该固定审查包作为真实学习产物，而不是只写方案段落。

### 3. 第 6、19 章：模型/工作流比较缺少可执行的最小 smoke 证据

**涉及内容：** 第 6 章“模型选择不是模型崇拜”、第 19 章“评估模型和工作流”、实验 009 的工程生命周期对照、实验 013 的验证记录，以及模型和证据相关评测任务。

**为什么含金量不足：** 章节对任务集、模型卡、首次通过、返工、成本、延迟、错误分类和 `not_comparable` 讲得较完整，但仍容易被读成“如何设计评测”。用户真正需要的是在信息有限时先做一个三任务 smoke，对照是否值得扩大；还要学会面对容量错误、运行中断、条件漂移时拒绝给出比较结论。若没有小规模实际记录，模型“快、便宜、适合重复任务”的官方定位很容易被误写成项目自己的性能结论。

**最小补强任务：三任务可比性 smoke**

- **具体任务：** 在两个候选模型或两条工作流之间完成三个固定低风险任务：结构化提取、受约束 Markdown 转换、证据缺口审查；目标只回答“是否值得扩大评测”，不回答总体排名。
- **固定输入：** 任务集版本、三份合成输入、同一上下文、同一工具和权限、同一验收表、每个任务固定一次初始运行和一次允许的受控返工；记录模型/工作流 ID、日期、工作面和配置。
- **必须输出：** `smoke-comparison.csv` 或等价 Markdown 表、两张模型/工作流卡、原始输出或日志索引、每项的首次通过、返工次数、耗时、成本口径、错误类别、人工评分、`comparable / not_comparable`、扩展/停止决定和限制说明。
- **失败变体：** 一次运行中发生容量错误、权限阻塞、输入被改变或工具版本不同；正确结果是该行 `not_comparable`，保存中断证据并决定补跑条件，不用空值或另一模型的结果补齐。
- **验收证据：** 另一位审查者可以重建三项的输入和条件；首次通过标准在运行前已冻结；至少有一项错误分类和一项未能比较的记录；结论只写“值得扩展/暂不扩展/证据不足”，不能写“总体最好”或“性价比最高”。
- **迁移任务：** 把 smoke 协议迁移到同一模型的两个工作面，或迁移到文档转换、研究来源审查和低风险代码检查三类任务；保留不可比条件，重新定义任务级验收，不把一个领域的优势外推到另一个领域。

**已有资产可复用：** 第 6 章的模型卡和指标定义、第 19 章的冻结任务集规则、实验 009/013 的 checkpoint 与日志字段；这不是新增完整评测框架，而是把“先做 smoke 再扩展”变成必须交付的最小运行记录。

## 依赖关系与落地顺序

三处补强不应并行修改所有正文。建议按以下顺序各做一个小切片：

```text
入口决策卡
    ↓ 提供“条件相同、证据分段、正确阻塞”的操作习惯
安装前审查包
    ↓ 提供“能力存在不等于可用/可采用”的状态模型
三任务可比性 smoke
    ↓ 将状态、证据、不可比和停止规则用于模型/工作流判断
```

每个切片只需要更新对应章节的实验说明或新增一个评测输入；不需要重写 22 章、增加新的学习等级或创建新的 Skill。lab-013 可以作为三处共同的证据格式参考，但不能替代三个决策的领域输入。

## 审查结论与状态边界

- 22 章的结构普遍包含目标、实验、失败、证据和迁移标题；标题存在不等于学习者已经产生对应证据。
- 13 个实验目前仍是 `draft`/未运行状态；本报告没有把任何实验称为已验证。
- 39 项评测任务已经覆盖大量边界和停止判断，但其中不少是静态决策输入；它们不能替代真实低风险运行日志。
- 本报告提出的是最小补强规格，不是已实施的课程改版；完成后仍需运行相应任务、保存输入/输出/复核记录，再决定是否提升内容状态。
