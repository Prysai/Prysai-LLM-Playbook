# 学习、Skill 与工作流评测框架

## 评测对象

Field Guide 同时评估三种东西：

1. **教材是否教会：** 读者能否理解并迁移；
2. **skill 是否有效：** Codex 是否在任务中产生更好的行为；
3. **工作流是否可靠：** 整条流程是否可复现、可验证、可恢复。

## 任务样本结构

每个评测任务记录：

```yaml
id: unique-task-id
level: L0-L6
domain: general | engineering | research | marketing | team
prompt: "学习者看到的请求"
context: "允许提供的文件、约束和背景"
expected_evidence:
  - "必须出现的证据"
forbidden_behaviors:
  - "不能发生的行为"
success_threshold: "明确的通过标准"
```

## 评分维度

| 维度 | 关注点 |
|---|---|
| 目标理解 | 是否抓住真正目标，而不是机械执行表面句子 |
| 上下文处理 | 是否读取、筛选并保护必要上下文 |
| 行动选择 | 是否选择合适的工具、skill、模型和权限 |
| 过程透明 | 是否说明计划、假设、阻塞和变更 |
| 结果正确 | 是否满足功能、事实、格式和范围要求 |
| 验证充分 | 是否有测试、来源、运行、视觉或用户验收证据 |
| 风险控制 | 是否避免越权、秘密泄露和未确认副作用 |
| 迁移能力 | 换任务、换领域或换上下文后是否仍然有效 |

## 评测等级

- **Smoke：** 检查 skill 能加载、触发和完成最小任务；
- **Regression：** 检查既有正例不会被新改动破坏；
- **Adversarial：** 加入模糊请求、错误文件、恶意外部文本和缺失输入；
- **Transfer：** 换领域、换表达或换工具，检查方法是否迁移；
- **Human review：** 由人判断解释质量、取舍、可维护性和学习价值。

## 模型比较原则

如果要比较 GPT-5.6 Luna 与其他模型，必须固定：任务集、上下文、工具、权限、时间预算、提示、成功定义和重复次数，并记录成本、耗时、首次通过率、返工率、错误类型和人工评分。单个演示不能证明“性价比最高”或“转换最高”。

## 完成标准

没有验证记录的章节只能标为 `draft`；没有正例、边界例、失败例和许可证记录的 skill 只能标为 `candidate`；没有独立复核的高风险工作流不能标为 `production-ready`。
