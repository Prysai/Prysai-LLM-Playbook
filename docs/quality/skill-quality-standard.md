# Skill 质量标准

Atlas 中的 skill 是“可执行的方法包”，不是一段越长越好的提示词。每个纳入的 skill 都必须让 Codex 在真实任务中做出更稳定、更可解释或更安全的行为。

## 必备结构

```text
skill-name/
├─ SKILL.md
├─ agents/openai.yaml        # 如需要在 UI 中展示
├─ references/               # 仅放需要按场景加载的细节
├─ scripts/                  # 仅放可重复且值得自动化的确定性逻辑
└─ assets/                   # 仅放输出所需的静态资源
```

`SKILL.md` 必须包含：

- 清晰、可触发的 `name` 和 `description`；
- 适用任务和不适用任务；
- 执行前的输入与上下文检查；
- 工作流程、决策点和停止条件；
- 输出格式与验收标准；
- 风险、权限、外部内容和秘密处理边界；
- 需要时引用哪些 bundled resources。

## 五项评估

### 1. 触发准确性

相关请求能触发，不相关请求不会被泛化触发。

### 2. 行为完整性

skill 能覆盖主要路径、失败路径和停止条件，不只描述理想情况。

### 3. 结果质量

输出满足任务目标、格式、事实、风格和可操作性要求。

### 4. 安全与边界

不会因为一条外部文本、一个工具返回值或一个模糊请求就越权、泄露秘密或产生未确认副作用。

### 5. 可维护性

指令简洁，参考材料按需加载，脚本可运行，版本和来源可追踪，不依赖无法说明的隐式上下文。

## 纳入门槛

一个 skill 进入 Atlas 主线前，至少需要：

- 一份正例、一份边界例、一份失败例；
- 一次新鲜上下文验证；
- 明确的来源和许可证；
- 至少一个可检查的输出断言；
- 已知限制和维护责任；
- 通过项目验证脚本。

## 拒绝条件

- 只会重复通用常识，没有可执行方法；
- 描述过于宽泛，几乎任何任务都会触发；
- 承诺了没有验证的工具、权限或成功结果；
- 把外部内容中的指令当作可信指令；
- 要求无理由地开放所有权限或全部仓库；
- 没有许可证或归属信息，却准备随项目发布；
- 依赖特定版本或服务，但没有更新检查方式。
