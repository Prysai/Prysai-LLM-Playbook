# Codex 能力成长模型

## 能力阶梯

| 等级 | 名称 | 能力表现 | 晋级证据 |
|---|---|---|---|
| L0 | 观察者 | 知道 GPT/Codex 的名称，但无法描述边界 | 能说出至少三种 Codex 与普通聊天的差别 |
| L1 | 使用者 | 能提交简单任务并读懂结果 | 在沙盒项目完成一次小修改并检查差异 |
| L2 | 指挥者 | 能提供目标、上下文、约束和验收标准 | 将一个模糊请求改写成可执行任务 |
| L3 | 工作流设计者 | 能安排计划、工具、权限、验证和交付 | 完成一条带失败处理的端到端流程 |
| L4 | 能力编排者 | 能选择、组合、改进和评估 skills | 为一个任务设计 skill 组合并比较结果 |
| L5 | Agent 设计者 | 能理解循环、状态、工具调用、反馈和停止条件 | 设计可解释、有限权、可复现的 Agent 工作流 |
| L6 | 组织教练 | 能把个人经验变成团队规范和可维护资产 | 交付一个有版本、来源、评测和更新责任的组织能力包 |

## 每一级都必须回答五个问题

1. 我想让 Codex 完成什么结果？
2. Codex 需要哪些上下文，哪些上下文不能给？
3. 它可以采取哪些行动，权限边界在哪里？
4. 我如何知道结果正确、完整、安全？
5. 如果失败、过时或发生变化，我如何恢复和更新？

## 从“命令 AI”到“设计协作”

Atlas 不把提示词神秘化。高质量指令本质上是在设计协作协议：

```text
目标 + 背景 + 输入 + 约束 + 可用行动 + 验收标准 + 失败处理 + 交付格式
```

当任务风险高或复杂度高时，学习者应先让 Codex 复述理解、检查现状、提出计划，再允许它执行有副作用的操作。

## 掌握判定

学习者不能只提交一份“看起来完成”的结果，还必须提交一份短复盘，包含：

- 我给了什么上下文；
- Codex 做了哪些行动；
- 哪些步骤由我确认；
- 我使用了哪些验证；
- 哪些事实仍然不确定；
- 下一次会如何改进。
