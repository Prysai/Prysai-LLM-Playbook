# Core-course observation experiments

**Status:** `candidate`  
**Run status:** `not_run`

These three small experiments make the core course's most important boundaries
observable without calling a model, using a real account, touching a file, or
collecting learner data in the repository. They are preparation materials for
an authorized observation; they are not results.

| Experiment | Question | Core outcome | Evidence kept by an authorized reviewer |
| --- | --- | --- | --- |
| [Context change and unknowns](context-change-and-unknowns.md) | Does the learner update a claim when the supplied context changes, while leaving unknowns unknown? | `identify` / `repair` | First classification, changed-context classification, source quotes, correction, help disclosure |
| [First-request contract](first-request-contract.md) | Does the learner make a first request observable before asking for a polished answer? | `initiate` | First request, field map, first response or no-model fixture, stop decision |
| [Tool boundary, authority, and evidence](tool-boundary-authority-evidence.md) | Can the learner distinguish a proposed action, granted authority, execution, and read-back evidence? | `explain` / `transfer` | State-by-state classification, authority decision, evidence boundary, stop reason |

## Shared conditions

- Use only the fictional records embedded in each protocol.
- Do not paste private, workplace, health, financial, credential, or account
  material.
- Do not browse, upload, send, publish, edit a real file, or call a tool.
- Show the task and supplied record before the first attempt, but do not show
  the answer key or a complete prompt template.
- Record help and withdrawals as they happened. Missing records remain
  `not_observed`; they are not converted to zero or success.
- A future run must name its candidate commit, conditions, reviewer roles,
  retention end date, and claim boundary before any participant starts.

## Interpretation boundary

These protocols can support only a bounded observation of the named task,
conditions, and rubric. They cannot establish course effectiveness, model
quality, prompt superiority, retention, general transfer, platform
equivalence, or production readiness. No result is recorded until an
authorized, privacy-bounded run supplies the required fields and independent
review.
