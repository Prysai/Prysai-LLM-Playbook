# 三任务冒烟比较 v1

**状态：** `candidate` 固定任务包 · **运行证据：** `not_run`

这是服务于第 6、19 章的共享离线任务包。让两个候选模型或工作流完成同样的三个小任务，再决定是否值得投入更大的评测。

本地验证器通过，只说明一份提交符合这个固定包的结构和验收规则；**不说明**模型质量、价格、安全性、通用价值、学习效果，或哪一个模型“总体更强”。

## 必须保持一致的条件

- `fixture.json` 中的任务 ID、说明、合成输入、期望输出和哈希；
- 每轮只变一个比较变量：模型、工作流或工作面；
- 两边使用相同的上下文、工具、权限、网络条件、时间预算和审阅者；
- 初次尝试后，最多一次预先声明的受控返工。

教学输入均为项目原创合成材料，不含客户数据、凭据、生产记录或外部原文。

## 运行一个任务

1. 不改动地把任务说明和输入交给每个候选项；人工修改前先保存原始输出。
2. 按要求的文件名把答案保存在本地。
3. 本地验证；验证器不会联网，也不会调用模型。

```powershell
$py = (Get-Command python -ErrorAction Stop).Source
& $py evals\candidates\three-task-smoke-v1\validate_submission.py `
  --task extract-01 `
  --submission <candidate-output>/candidate-a-extract-01.json
```

| 任务 | 提交 | 检查内容 |
| --- | --- | --- |
| `extract-01` | JSON 数组 | 结构化提取且不虚构事实 |
| `markdown-02` | Markdown 文件 | 受限转换且保留未知项 |
| `gap-review-03` | JSON 对象 | 识别证据缺口且不贬低已有证据 |

两位候选项共保留六份独立提交，并在 `run-record-template.yaml` 记录条件和验证结果。其中 `not_run` 是占位符，不是结果。

## 如实停止

若一方受到中断、权限阻断、输入哈希变化、工具版本变化或其他冻结条件变化影响，使用 `not_comparable`。不要用一次成功重试替换中断答案。即使有六份可比答案，也只能支持任务范围内的决定，不能推出通用模型排名。
