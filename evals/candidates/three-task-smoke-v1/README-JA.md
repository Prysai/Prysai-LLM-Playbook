# 三タスク・スモーク比較 v1

**状態：** `candidate` フィクスチャパッケージ · **実行証拠：** `not_run`

これは第 6 章と第 19 章のための共有オフラインタスク集です。大きな評価にコストをかける前に、二つの候補モデルまたはワークフローへ同じ三つの小タスクを渡します。

ローカル検証に通っても、固定されたスキーマと受け入れ規則に一件の提出物が合ったという意味だけです。品質、価格、安全性、一般的な有用性、学習成果、総合的な勝者は**証明しません**。

## 固定する条件

- `fixture.json` のタスク ID、指示、合成入力、期待出力、ハッシュ;
- 一回に変える比較変数は一つだけ（モデル、ワークフロー、または作業面）;
- 両者で同じコンテキスト、ツール、権限、ネットワーク条件、時間予算、レビュー担当者;
- 初回の後に事前宣言した制御付きやり直しは最大一回。

入力はプロジェクト独自の合成教材で、顧客データ、認証情報、本番記録、外部原文を含みません。

## 一つ実行する

1. 指示と入力を変更せず各候補へ渡し、人が編集する前に生の回答を保存します。
2. 指定されたファイル名でローカル保存します。
3. ローカルで検証します。検証器はネットワークもモデル呼び出しも使いません。

```powershell
$py = (Get-Command python -ErrorAction Stop).Source
& $py evals\candidates\three-task-smoke-v1\validate_submission.py `
  --task extract-01 `
  --submission <candidate-output>/candidate-a-extract-01.json
```

| タスク | 提出 | 確認すること |
| --- | --- | --- |
| `extract-01` | JSON 配列 | 事実を作らない構造化抽出 |
| `markdown-02` | Markdown ファイル | 未知を残した制約付き変換 |
| `gap-review-03` | JSON オブジェクト | 既存の証拠を下げない証拠ギャップ確認 |

二候補なら六つの独立提出物を残し、条件と検証結果を `run-record-template.yaml` に記録します。`not_run` は結果ではなくプレースホルダーです。

## 正直に止める

中断、権限ブロック、入力ハッシュ変更、ツール版変更などが片側に起きたら `not_comparable` を使います。中断した回答を成功した再試行で置き換えません。六件が比較可能でも、このタスク範囲の判断に限られ、一般的なモデル順位にはなりません。
