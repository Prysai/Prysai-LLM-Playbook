# 세 가지 작업 스모크 비교 v1

**상태:** `candidate` fixture 패키지 · **실행 증거:** `not_run`

이 공유 오프라인 작업 묶음은 6장과 19장을 위한 것입니다. 더 큰 평가 비용을 쓰기 전에 두 후보 모델 또는 워크플로에 동일한 세 가지 작은 작업을 줍니다.

로컬 검증을 통과해도 제출물 하나가 고정된 스키마와 수용 규칙에 맞았다는 뜻뿐입니다. 품질, 가격, 안전성, 일반적 유용성, 학습 결과, 전체 승자를 **증명하지 않습니다**.

## 고정할 조건

- `fixture.json`의 작업 ID, 지시, 합성 입력, 기대 출력, 해시;
- 라운드당 비교 변수 하나만 변경: 모델, 워크플로 또는 작업면;
- 양쪽에 동일한 맥락, 도구, 권한, 네트워크 조건, 시간 예산, 검토자;
- 첫 시도 후 사전에 선언한 통제된 재작업은 최대 한 번.

입력은 프로젝트의 원본 합성 교육 자료이며 고객 데이터, 자격 증명, 운영 기록, 외부 원문이 없습니다.

## 작업 하나 실행하기

1. 지시와 입력을 바꾸지 않고 각 후보에 주고, 사람이 편집하기 전에 원시 답변을 저장합니다.
2. 지정된 파일명으로 답변을 로컬에 저장합니다.
3. 로컬에서 검증합니다. 검증기는 네트워크나 모델 호출을 사용하지 않습니다.

```powershell
$py = (Get-Command python -ErrorAction Stop).Source
& $py evals\candidates\three-task-smoke-v1\validate_submission.py `
  --task extract-01 `
  --submission C:\temp\candidate-a-extract-01.json
```

| 작업 | 제출 | 확인 내용 |
| --- | --- | --- |
| `extract-01` | JSON 배열 | 사실을 지어내지 않는 구조화 추출 |
| `markdown-02` | Markdown 파일 | 미확인 정보를 보존하는 제한된 변환 |
| `gap-review-03` | JSON 객체 | 기존 증거를 낮추지 않는 증거 공백 검토 |

두 후보라면 독립 제출물 여섯 개를 보관하고 `run-record-template.yaml`에 조건과 검증 결과를 기록합니다. `not_run`은 결과가 아니라 자리표시자입니다.

## 정직하게 중단하기

한쪽에 중단, 권한 차단, 입력 해시 변경, 도구 버전 변경 또는 다른 고정 조건 변화가 있으면 `not_comparable`을 사용합니다. 중단된 답을 성공한 재시도로 바꾸지 마세요. 여섯 답변이 비교 가능해도 이 작업 범위의 결정만 지원하며 일반 모델 순위를 만들 수 없습니다.
