# 序：这不是一本提示词大全

很多人第一次接触 GPT 时，最自然的问题是：“我应该对它说什么？”

这个问题重要，但还不够。真正决定一次 Codex 任务能否稳定完成的，往往是另外一组问题：它理解了什么？哪些文件和规则属于上下文？它可以采取哪些行动？哪个 Skill 能减少遗漏？Agent 为什么继续、重试、暂停或停止？我凭什么相信它已经完成？

Prysai LLM Playbook 研究的正是这一整套关系。

## 你将学到什么

本项目从两个方向同时前进。

一条是理解路径：从 GPT 和模型开始，理解 Codex 如何把模型接入项目、文件、终端、浏览器、GitHub 和外部服务；再理解上下文、工具、Skill、Plugin、Connector、MCP、Agent 和权限如何共同改变行动空间。

另一条是能力路径：从一个低风险的小任务开始，练习任务表达、上下文筛选、计划、执行、验证、审查和交付；随后学习选择和设计 Skill、评估模型与工作流，建立个人工作系统，最后把方法变成团队可以共享、审查和更新的能力包。

这两条路径不能分开。只理解原理而不练习，容易停留在术语；只会调用工具而不理解边界，容易把偶然成功误认为可靠能力。

## 如何阅读

你可以顺读，也可以从一个真实任务跳入。每章都遵循同一条闭环：

```text
问题 → 概念 → 判断 → 操作 → 证据 → 失败 → 复盘 → 迁移
```

章节中的“实验”不是演示视频的替代品，而是学习者需要亲自完成的最小任务。实验会要求你留下结果、差异、日志、来源、截图或复盘；只有这样，阅读才会变成能力。

## 如何判断自己是否真的学会

本项目不用“输出看起来很漂亮”作为掌握标准。一次能力至少需要四类证据：

- 你能用自己的话解释概念和边界；
- 你能在真实或低风险环境中完成操作；
- 你能说明为什么选择这个模型、工具、Skill 或权限；
- 你能发现错误、风险、幻觉、未完成项或过时事实。

如果只能展示结果，不能解释过程和证据，你可能完成了一次练习，但还没有掌握方法。

## 关于 Luna

GPT-5.6 Luna 是本项目重点评估的模型之一。OpenAI 官方文档将它定位为速度快、成本较低、适合清晰且可重复任务的模型。这个定位可以形成一个值得验证的假设，但不能直接推出“它对所有任务性价比最高”。

本项目会教你如何固定任务集、上下文、工具、权限、时间预算、重复次数和成功标准，再比较首次通过率、返工率、耗时、成本、证据完整度和停止正确率。结论只对声明的任务集、环境和日期负责。

## 一条重要的安全原则

能力越强，边界越要清楚。不要因为 Codex 可以访问文件、终端、浏览器、GitHub 或外部服务，就一次性开放所有权限。先从只读、低风险、可回滚的任务开始；在证据证明确实需要时，再逐层增加能力。

愿这本书最终带给你的不是一套神秘的“万能指令”，而是一种可以解释、检查、改进和传授的工作方式。
