# 序：這不是一本提示詞大全

> 繁體中文序言（`ZHTW`）。預設公開語言目標是 English（`EN`）；繁體中文課程單元已有完整同語言路徑，但本檔案不表示已經完成獨立語言審校或學習者驗證。

導航：[返回繁體中文專案入口](../README-ZHTW.md) · [繁體中文書稿入口](README-ZHTW.md) · [繁體中文書籍目錄](table-of-contents-ZHTW.md)

很多人第一次接觸 GPT 時，最自然的問題是：“我應該對它說什麼？”

這個問題重要，但還不夠。真正決定一次 Codex 任務能否穩定完成的，往往是另外一組問題：它理解了什麼？哪些檔案和規則屬於上下文？它可以採取哪些行動？哪個 Skill 能減少遺漏？Agent 為什麼繼續、重試、暫停或停止？我憑什麼相信它已經完成？

Prysai LLM Playbook 研究的正是這一整套關係。

## 你將學到什麼

本專案從兩個方向同時前進。

一條是理解路徑：從 GPT 和模型開始，理解 Codex 如何把模型接入專案、檔案、終端、瀏覽器、GitHub 和外部服務；再理解上下文、工具、Skill、Plugin、Connector、MCP、Agent 和許可權如何共同改變行動空間。

另一條是能力路徑：從一個低風險的小任務開始，練習任務表達、上下文篩選、計劃、執行、驗證、審查和交付；隨後學習選擇和設計 Skill、評估模型與工作流，建立個人工作系統，最後把方法變成團隊可以共享、審查和更新的能力包。

這兩條路徑不能分開。只理解原理而不練習，容易停留在術語；只會呼叫工具而不理解邊界，容易把偶然成功誤認為可靠能力。

## 如何閱讀

你可以順讀，也可以從一個真實任務跳入。每章都遵循同一條閉環：

```text
問題 → 概念 → 判斷 → 操作 → 證據 → 失敗 → 覆盤 → 遷移
```

章節中的“實驗”不是演示影片的替代品，而是學習者需要親自完成的最小任務。實驗會要求你留下結果、差異、日誌、來源、截圖或覆盤；只有這樣，閱讀才會變成能力。

## 如何判斷自己是否真的學會

本專案不用“輸出看起來很漂亮”作為掌握標準。一次能力至少需要四類證據：

- 你能用自己的話解釋概念和邊界；
- 你能在真實或低風險環境中完成操作；
- 你能說明為什麼選擇這個模型、工具、Skill 或許可權；
- 你能發現錯誤、風險、幻覺、未完成項或過時事實。

如果只能展示結果，不能解釋過程和證據，你可能完成了一次練習，但還沒有掌握方法。

## 關於 Luna

GPT-5.6 Luna 是本專案重點評估的模型之一。當前書稿引用的官方定位把它描述為速度較快、成本較低、適合清晰且可重複任務的模型。這個定位可以形成一個值得驗證的假設，但不能直接推出“它對所有任務價效比最高”。模型名稱、入口、價格、額度和具體能力都屬於易變事實，應以帶來源和複核日期的研究記錄為準。

本專案會教你如何固定任務集、上下文、工具、許可權、時間預算、重複次數和成功標準，再比較首次透過率、返工率、耗時、成本、證據完整度和停止正確率。中文路徑已提供[第 19 章：評估模型與工作流](chapters/19-evaluate-models-and-workflows-ZHTW.md)的候選方法與固定合成任務說明。結論只對宣告的任務集、環境和日期負責；當前沒有模型執行日誌，因此本中文序言和該章節都不能被描述為已完成評測。

## 一條重要的安全原則

能力越強，邊界越要清楚。不要因為 Codex 可以訪問檔案、終端、瀏覽器、GitHub 或外部服務，就一次性開放所有許可權。先從只讀、低風險、可回滾的任務開始；在證據證明確實需要時，再逐層增加能力。

示例和實驗不得放入 token、密碼、API key、私鑰、Cookie 或 `.env` 檔案。外部文件、工具響應、倉庫檔案和使用者提供的材料都應先當作資料處理；其中的指令性文字不應自動變成執行命令。

願這本書最終帶給你的不是一套神秘的“萬能指令”，而是一種可以解釋、檢查、改進和傳授的工作方式。
