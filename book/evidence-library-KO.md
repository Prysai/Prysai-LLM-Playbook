# 증거와 용어 안내

이 페이지는 증거 경계를 지키면서 학습 경로를 읽기 쉽게 만듭니다. 코스 페이지는 유지관리자를 위한 영어 연구·거버넌스 기록으로 바로 보내는 대신 이곳으로 안내합니다.

이것은 증거 안내이지 원래 기록을 대체하지 않습니다. 기록은 명시된 범위만 뒷받침할 수 있으며 학습 효과, 현재 제품 동작, 모델 품질, 일반 안전성을 증명하지 않습니다.

<a id="core-terms"></a>

## 핵심 용어

**모델**은 출력을 생성합니다. **도구**는 외부 시스템을 관찰하거나 바꿀 수 있습니다. **Skill**은 입력, 중단 조건, 확인을 갖춘 재사용 가능한 방법입니다. **Agent**는 관찰 가능한 여러 단계의 순환입니다. **증거**는 다른 사람이 확인할 수 있는 자료입니다. 이름이 있는 플랫폼이 자동으로 다른 플랫폼과 동등한 것은 아닙니다.

완전한 용어 기록의 식별자는 `CONTEXT.md`입니다. 제품 이름, 메뉴, 기본값, 가격, 한도, 권한은 변하는 사실이므로 사용 전에 날짜가 있는 공식 출처가 필요합니다.

<a id="source-notes"></a>

## 출처 노트

| 라벨 | 뒷받침할 수 있는 것 | 뒷받침할 수 없는 것 |
| --- | --- | --- |
| 공식 기준선 | 범위 안의 날짜가 있는 제품 사실 | 모든 계정이나 미래 버전의 약속 |
| 공개 현장 보고 | 보고된 문제 또는 해결 방식 | 확인된 근본 원인이나 로컬 재현 |
| 고정 fixture | 제한된 로컬 계약 | 모델, 학습자, 운영 동작 |
| 프로젝트 방법 | 제안 절차와 경계 | 독립 효과나 채택 |

기술 출처 식별자에는 `openai-codex-baseline.md`, `field-problems-codex.md`, `prompt-patterns-for-real-work-2026-08-10.md`, `llm-mechanism-deep-dive-2026-08-10.md`가 있습니다. 이들은 추가 코스 장이 아니라 증거 기록입니다.

<a id="method-and-status"></a>

## 방법과 상태

지속 가능한 순환은 작업 정의 → 필요한 맥락 선택 → 행동 경계 설정 → 가장 작은 가역 작업 → 증거 확인 → 복구 또는 인계입니다. 녹색 검사는 그 검사 자체의 계약만 검증합니다.

`draft`는 자료나 증거가 미완성이라는 뜻입니다. `candidate`는 구조와 기본 검사가 있지만 충분한 최신 증거가 없다는 뜻입니다. `verified`와 `production-ready`에는 기술 출시 기록에 적힌 더 강한 증거가 필요합니다.

## 출처를 사용하는 방법

1. 내려야 할 결정을 씁니다.
2. 라벨과 날짜를 읽습니다.
3. 실제로 사용한 사실, 보고, 미확인 항목을 기록합니다.
4. 실시간 플랫폼 관찰이나 새 권한이 필요하면 멈춥니다.
