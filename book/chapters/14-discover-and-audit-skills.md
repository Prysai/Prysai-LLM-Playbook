# 第十四章：如何发现、安装和审查外部 Skill

## 本章要解决的问题

外部 skill 生态可以快速扩大 Codex 的能力，也可能扩大上下文、依赖、权限、网络和许可证风险。学习重点不是“安装更多”，而是把目录条目变成经过审查的候选能力。

## 1. 从任务出发

先写任务协议，再问：缺的是领域知识、重复流程、确定性脚本、外部数据，还是外部动作？如果只是缺少目标和验收，安装 skill 无法解决根本问题。

## 2. 候选审查卡

每个候选至少记录：

```text
名称与来源：
版本/提交：
触发范围：
不适用范围：
需要读取什么：
需要什么工具、网络、账号和权限：
会产生什么外部副作用：
许可证与 NOTICE：
正例/边界例/失败例：
维护与移除方式：
```

README 的宣传语、星标、目录数量和兼容性徽章只能作为发现线索，不能作为质量证据。

## 3. 安装前后的验证

安装前先读入口 skill 和 manifest，确认名称、路径和依赖。安装后检查元数据是否能触发，做一个低风险 smoke test，再做边界和失败测试。发现 skill 要求不必要的全部权限、秘密或外部上传时，标为 blocked 或缩小范围。

## 4. 管理大目录

像 S06 这样拥有大量自动化条目的目录应作为索引和候选池。按能力簇筛选：研究、文档、工程、数据、沟通、外部服务等；先维护少量有明确任务和证据的核心包，再为需要的团队逐步启用扩展。

## 实验：安装前审查

从任意外部目录选三个候选：一个本地纯文档 skill、一个需要外部服务的 skill、一个许可证或命名不清的 skill。为它们填写审查卡，只有第一个在无副作用条件下做 smoke test。比较“可用性”与“值得纳入”之间的差别。

## 本章验收

学习者能从一个真实任务推导 skill 需求；能完成候选审查卡；能解释许可证、依赖、权限、触发和维护的重要性；能拒绝仅凭目录热度安装全部 skills。
