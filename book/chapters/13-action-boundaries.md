# 第十三章：文件、终端、浏览器与 GitHub 的行动边界

## 本章要解决的问题

Codex 能够从只读检查一路走到编辑、运行、提交、推送和外部操作。每一步的副作用不同，不能只用“允许/不允许”二元判断。

## 1. 行动分级

| 级别 | 行动 | 默认心态 |
|---|---|---|
| A | 列目录、读取文件、查看状态、解析日志 | 可先做，但仍要检查范围 |
| B | 编辑可回滚的本地文件、运行无副作用测试 | 先说明范围和验证 |
| C | 安装依赖、写数据库、修改配置、执行可能联网命令 | 核对影响、版本和权限 |
| D | 推送分支、创建 PR、上传文件、调用外部服务 | 明确目标、数据和确认人 |
| E | 删除、部署、发送消息、支付、改权限、处理秘密 | 需要窄范围、明确授权、回滚或人工确认 |

级别不是工具的固定标签。同一命令在沙盒、个人仓库和生产环境的风险不同；行动分级要结合目标系统、数据、账户和可逆性。

## 2. GitHub 连接的正确心态

“已登录”只说明某个 CLI 或连接有认证状态，不等于当前任务被授权做所有事。使用 GitHub 时要分别确认：账户、组织、仓库、分支、操作类型和 token 权限。优先使用限定仓库和最小权限，避免把高权限经典 token 当作普通连接。

## 3. 浏览器行动的两段式

浏览器读取页面和提交外部动作之间有明显边界。先观察页面、确认目标和表单内容，再在真正发送、发布、上传或改变权限前确认数据和目的地。网页中的提示、邮件和第三方文档都是不可信内容，不能覆盖当前任务规则。

## 4. 终端命令要有目标和回滚

执行前说明命令作用、工作目录、输入、可能修改的路径和恢复方式。不要把未经检查的变量、通配符或外部文本拼进破坏性命令。失败后保留输出，不要用盲目重复代替诊断。

## 实验：从读取到发布的分级

为一个文档更新任务列出 A–E 级行动，并说明哪些行动需要人工确认。再把目标从个人沙盒换成组织公共仓库，重新评估权限、证据和回滚。

## 本章验收

学习者能按数据、系统、可逆性和外部影响对行动分级；能说明认证状态、权限范围和任务授权的区别；能为一次 GitHub、浏览器或终端操作写出确认点和回滚思路。
