# 第 18 章：内容、设计、数据与自动化轨

## 本章要解决的问题

外部技能生态覆盖写作、文档、网站、图片、演示文稿、电子表格、数据分析、视频和 SaaS 自动化。一个工作流包含的工具越多，就越容易把「源文件存在」「脚本跑过」或「API 已连接」误当成交付完成。

另一些失败更难察觉：版式破损、缺少空状态、图表误导、输出不可访问、许可证不明、重复写入、权限过大、隐私泄漏，以及无法撤销的外部动作。本章提供一套「产品—风险—验证」方法：先定义最终形态与受众，再按风险顺序启用能力，最后检查渲染结果、输入输出、权限、恢复行为和发布状态。

## 学习目标

学完本章，你应该能够：

1. 按交付物和风险选择能力，而不是按品牌堆积工具。
2. 为文档、网站、图片、演示文稿、电子表格、PDF、数据流和自动化定义可观察的验收标准。
3. 检查最终形态的层级、可读性、空状态与错误状态、响应式行为、可访问性、事实准确性、许可证和可编辑性。
4. 记录自动化的输入模式、转换、外部调用、重试、幂等性、日志、权限、隐私边界和输出验证。

## 真实问题入口：中间步骤通过不等于交付物通过

- **FP-10：**格式化或校验命令可能长时间停留在 Working 状态。「命令已启动」不能证明输出已生成或被检查；要使用超时、退出状态和最终产物作为证据。
- **FP-11：**一份报告把源验证扩大成了持久环境替换。创建、安装、发布、部署、重启和在线验证是不同级别的副作用，不能都归并到「验证」名下。

这些是实地研究报告或分析，不是本地复现。它们需要为中间产物、最终形态和权限状态分别提供证据。

## 核心概念与决策

### 1. 按交付物组织能力

| 交付物 | 最终形态检查 | 常见风险 |
|---|---|---|
| 文档或 PDF | 分页、目录、链接、字体、可读性、打印/导出 | 重排、字体缺失、引用或许可证错误 |
| 网站 | 浏览器渲染、响应式行为、交互、空/错误状态、键盘和移动端路径 | 源码看起来正确但界面不可用；请求超出范围 |
| 图片或视频 | 尺寸、清晰度、文字、权利、字幕或替代文本、可编辑性 | 事实错误、许可证不明、媒体不可访问 |
| 演示文稿 | 投影尺寸、层级、对比度、讲解顺序、备注 | 溢出、对比度低、幻灯片与讲稿不一致 |
| 电子表格或数据报告 | 公式、筛选、单位、空值、汇总、导出、重算 | 数字错位、分母漂移、公式被覆盖 |
| 自动化 | 模式、日志、重试、幂等性、权限、回滚、输出验证 | 重复写入、数据泄漏、部分完成 |

### 2. 从最终形态出发

源文件、模板、JSON 和脚本都是生产材料。验收必须追问：读者会看到什么、能否完成预期动作、内容是否正确、版式是否稳定、空状态和错误状态是否易懂，以及输出是否可访问、可编辑、可复用。

当版式重要时，渲染成 PNG 或 PDF；当浏览器、表格或流程是用户真正面对的形态时，在浏览器中打开网站、重算电子表格，或用测试账户运行一次受控流程。源码 diff 不能替代最终形态证据。

### 3. 自动化必须可逆且可重复

对每个流程，写下：

```text
输入模式与样例：
敏感字段与允许用途：
转换步骤与版本：
外部调用、目标与最小权限：
超时、重试、退避与幂等键：
日志、追踪 ID 与错误分类：
输出模式与验证：
部分状态、补偿与回滚：
人工批准点与停止条件：
```

「API 已连接」只能证明连通性。它不能证明字段映射、数据完整性、重复行为、权限范围或下游正确性。在生产写入之前，使用测试账户、sandbox 或本地模拟，并在适当处保留输入/输出哈希和批次 ID。

### 4. 使用四个能力层级

1. **本地、只读、低风险：**起草、解析、静态检查和离线分析。
2. **可逆的项目工作：**生成文件、更新分支，或产出渲染结果而不发布。
3. **受控的外部连接：**测试账户、最小范围、人工批准和可审计的日志。
4. **生产写入或公开发布：**明确授权、隐私与许可证审查、预览、回滚和在线验证。

升到更高层级需要书面理由、新权限、新风险、新证据和恢复计划。如果任务不需要更高层级，就不要启用它。

## 你的头十分钟：把模糊需求变成可检查的草稿

在挑选新工具或连接账户之前先做这件事。用一个虚构的需求和一份可丢弃的本地文件，例如：「为三条虚构的活动报名记录写一页更新」。目的不是让模型显得厉害，而是看一个小请求能否被写得足够精确、足以检查。

1. 先写五行：**读者**、**最终形态**、**已提供的事实**、**禁止的数据/动作**，以及**怎样才算可接受**。
2. 把下面这个受限的 prompt 给模型，替换其中的方括号：

   ```text
   为 [读者] 创建一份 [最终形态]，只能使用这些已提供的事实：[事实]。
   不要编造数字、来源、姓名或结果。信息缺失时标为 [缺失]，并只问一个问题。
   只返回草稿；不要发送、发布、登录或调用外部服务。
   验收检查：[三个可观察的检查项]。
   ```

3. 像读者一样打开草稿。逐项核对每个已提供的事实、每个 `[缺失]` 标记、标题顺序和写明的验收检查。
4. 保存需求、prompt、输出和一份三行记录：**passed**、**failed**、**unknown**。如果结果需要真实数据、分发或新权限，就停下来，把它写成下一步决策，而不是悄悄扩大任务。

一份干净的草稿不能证明这个 prompt 普遍更好、工作变得更快，或流程对生产是安全的。它只是为下一次修订提供一个小而可检查的比较点。

## 具体证据表

| 证据项 | 具体产物 | 支持什么 | 不支持什么 |
|---|---|---|---|
| 最终形态审查 | 渲染出的 PDF/PNG、浏览器截图、重算后的表格或受控输出 | 读者或操作者实际看到的内容 | 仅凭源文件就足够 |
| 内容与数据审查 | 来源清单、数据字典、公式检查、验证输出 | 已执行的事实与结构检查 | 没有来源时，输出好看不等于事实正确 |
| 可访问性与可编辑性审查 | 键盘路径、替代文本记录、字幕、可选择文本、可编辑图层检查 | 声明过的访问与复用要求是否经过测试 | 对所有设备或辅助技术的普适可访问性 |
| 自动化合同 | 输入/输出模式、版本化的转换、错误规则 | 期望的数据形态与验证边界 | 外部服务接受了预期的含义 |
| 副作用记录 | 权限范围、测试账户身份、批次 ID、追踪日志、草稿状态 | 哪些外部动作被授权或已准备 | 公开发布确实发生 |
| 恢复记录 | 幂等键、状态查询、补偿或回滚证据 | 部分完成会如何被检测和修复 | 超时意味着没有发生写入 |

## 可观察的小实验：能力分组，而不是工具清单

### 准备

使用一个**合成的产品报告场景**来训练：一份虚构的产品描述、一份小的去标识化结构化 fixture 和预期的受众。它不是客户报告、库存记录、账户、收入来源或发布请求。准备四个范围逐级放宽的方案：A 仅文档；B 文档加数据分析；C 文档加图表渲染；D 文档加外部分发。再加入空数据、缺列、一个极端值和畸形输入作为失败 fixture。

### 任务

1. 对 A–D，记录最终形态、输入输出、最小权限、可能的副作用和回滚方法。
2. 完成 A：生成并导出文档，然后检查分页、标题层级、链接、事实和空状态。
3. 加入 B：从合成 fixture 计算描述性数值，记录模式、分母、缺失值处理、公式和输出检查。
4. 加入 C：渲染至少一张图表，在最终形态中检查标签、单位、对比度、字体、窄屏行为和打印行为。
5. 只有使用测试账户或草稿端点时才加入 D。检查预览、批次 ID、幂等键、日志、重试行为和人工批准。不要发布。
6. 每加入一项能力，就记录新的权限、验证、恢复代价和最终状态。

### 证据

证据包应包含：A–D 的设计表、最终的文档/图表/渲染输出或可复现的输出、数据字典和验证结果、对无效输入的响应、调用日志、权限范围、幂等与重试记录、sandbox 或草稿状态，以及「未发生公开发布」的明确证据。仅凭源文件或脚本是不够的。

### 失败变体

让一个格式化器或渲染器在规定的超时之前不产生任何输出。让一次外部调用在模拟写入之后超时。给报告空数据和缺列。正确的行为是：停下，保留批次或追踪 ID，查询是否存在部分写入，避免非幂等的重试，并把交付物标记为未完成。不要用强制重装、重启或发布来「修复验证」。空数据应该产生可理解的空状态，而不是空白的图表或编造出来的零。

### 反思

- 哪个方案最先需要外部权限？为什么？
- 哪个缺陷只能在最终渲染形态中才能发现？
- 超时之后，什么证据能说明是否发生了重复写入？
- 什么证据能把「已连接」「草稿已生成」「已发布」「已在线验证」区分开？

## 失败与边界情况

- **源码正确，渲染损坏：**检查换行、溢出、字体、图层、链接、裁切、颜色、打印和移动端行为。渲染结果或浏览器实时状态是必需的证据。
- **输出漂亮，事实错误：**对照来源复核数字、引文、品牌主张以及生成媒体中的文字。不要发布权限不明的图片、字体、代码或模板。
- **输出不可访问或不可编辑：**检查文档结构、替代文本、键盘路径、对比度、字幕、可选择文本、可编辑图层和导出格式。
- **自动化部分成功：**检查日志、状态查询、批次 ID 和下游状态。只有带上幂等键或补偿流程才能重试；仅凭超时不能证明失败。
- **外部范围过大：**缩小范围，使用测试账户和草稿端点，并单独申请真实的发布授权。
- **校验命令挂起：**按 FP-10，设置输出边界和超时；中断后重新检查文件、进程、日志和最终形态。
- **验证改变了持久环境：**按 FP-11，把创建、安装、发布、部署、重启和在线验证分开。为每一项记录授权和回滚。

## 迁移练习

选一个现有的文档、网站、电子表格、图片或自动化：

1. 写下读者、最终格式、成功动作、空/错误状态和可访问性要求。
2. 做一次最终形态审查，并保留截图、导出文件或浏览器/电子表格产物。
3. 用模式、敏感字段、幂等性、日志、重试、验证和回滚补全自动化合同。
4. 用测试账户或本地模拟重放一个失败输入，并把结果分类为 `draft`、`candidate`、`verified` 或 `production-ready`。

## 验收清单

- [ ] 我按交付物和风险选择能力，而不是按工具品牌。
- [ ] 我定义了读者、最终格式、成功动作、空状态和错误状态。
- [ ] 我检查了最终渲染或运行形态，而不只看源码或命令退出状态。
- [ ] 我检查了事实、版权或许可证边界、可访问性、可读性和可编辑性。
- [ ] 我记录了输入模式、转换、外部调用、重试、幂等性、日志和输出验证。
- [ ] 我使用了合成或测试数据以及测试账户或 sandbox，并记录了权限、批次和回滚证据。
- [ ] 我能解释 FP-10 和 FP-11 如何改变对挂起、部分成功或持久环境变化的处理。
- [ ] 我没有把草稿、连接或已启动的命令描述成公开发布或在线验证。
- [ ] 我能指出最终形态、数据检查、权限和恢复边界的具体证据。

## 来源与维护边界

- **实地报告：**[`docs/research/field-problems-codex.md`](../evidence-library-ZH.md#source-notes)，FP-10 和 FP-11。这些记录为 `candidate`，访问并整理于 2026-08-09，未在本地复现。
- **外部资产与许可证边界：**[`docs/sources/asset-register.md`](../evidence-library-ZH.md#source-notes)，S01、S03 和 S06。许可证不明的图片、代码、模板或嵌套资产仅供引用，不得复制进发布物。
- **易变的工具事实：**以实际使用的文档、PDF、电子表格、浏览器、渲染和外部服务工具的官方文档为准。在工作记录中记下 URL、访问日期、版本和范围。
- **维护负责人：**内容与自动化轨维护者。当渲染器、格式、浏览器、API、许可证或权限模型发生变化时进行复核，且不晚于 2026-11-09。

本章状态为 `candidate`。只有在相关的最终形态、数据质量、隐私、许可证、回滚和在线证据齐备之后，交付物才能被称为 `verified` 或 `production-ready`。本章不报告任何生产运行。
