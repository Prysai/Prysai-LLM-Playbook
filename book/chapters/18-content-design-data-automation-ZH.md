# 第 18 章：内容、设计、数据与自动化

**状态：**`candidate`。**实验状态：**`draft / not_run`。本章讲交付验证，不记录任何生产运行。

## 问题

工具越多，越容易把“源文件存在”“脚本跑过”或“API 已连接”误当成完成交付。版式、空状态、无障碍、许可证、公式、隐私、权限、重复写入和恢复都可能失败。

先定义最终形态和受众；再按风险启用能力；最后验证渲染结果、输入输出、权限、恢复和发布状态。

| 交付物 | 最终形态检查 | 常见风险 |
|---|---|---|
| 文档或 PDF | 分页、目录、链接、字体、可读性、打印 | 重排、字体缺失、引用或许可证错误 |
| 网站 | 浏览器渲染、响应式、交互、空/错误状态、键盘、移动端 | 源码正确，界面不可用 |
| 图片或视频 | 尺寸、清晰度、文字、权利、字幕/替代文本、可编辑性 | 事实错误、授权不清、不可访问 |
| 表格或报告 | 公式、筛选、单位、空值、导出、重算 | 数字错位、分母漂移、公式被覆盖 |
| 自动化 | 模式、日志、重试、幂等、权限、回滚、输出 | 重复写入、数据泄漏、半完成 |

源码差异不能替代最终形态证据：要看真实形态，就渲染 PDF/PNG、在浏览器中打开网站、重算表格或在测试账户运行受控流程。

## 可逆、可重复的自动化

```text
输入模式与样例；敏感字段和允许用途；转换与版本；
外部调用、目标和最小权限；超时、重试、退避和幂等键；
日志、追踪 ID、错误分类；输出模式与验证；部分状态、补偿与回滚；
人工批准点和停止信号。
```

“API 已连接”只证明连通性，不证明字段映射、完整性、重复行为、权限范围或下游正确性。生产写入之前使用测试账户、沙盒或本地模拟；必要时保留输入/输出哈希和批次标识。

## 前十分钟：把模糊需求变成可检查的草稿

先做这一步，再考虑新工具或连接账户。使用虚构需求和可丢弃的本地文件，例如：“为三条虚构活动报名记录写一页更新”。目标不是让模型显得厉害，而是看看能否把一个小任务说清楚、查得清楚。

1. 先写五行：**读者**、**最终形态**、**已提供事实**、**禁止的数据或动作**、**可接受的标准**。
2. 把下面提示中的方括号替换为你的任务：

   ```text
   为[读者]创建一份[最终形态]，只能使用这些已提供事实：[事实]。
   不要编造数字、来源、姓名或结果。信息缺失时标为[缺失]，并只提一个问题。
   只返回草稿；不要发送、发布、登录或调用外部服务。
   验收检查：[三个可观察的检查项]。
   ```

3. 像读者一样打开草稿，逐项核对已提供事实、每个 `[缺失]` 标记、标题层级和验收检查。
4. 保存需求、提示、输出和三行记录：**通过**、**失败**、**未知**。若下一步需要真实数据、分发或新权限，先停下，把它写成下一项决策，不要悄悄扩大任务。

一次干净的草稿不能证明提示词普遍更好、工作已经更快，或流程适合生产。它只为下一次修订留下一个小而可检查的比较点。

## 小练习与验收

使用虚构产品报告、去标识化结构化 fixture 和虚构受众。A 是文档，B 是文档加分析，C 是文档加渲染图表，D 是文档加外部分发。加入空数据、缺列、极端值和坏输入。只在本地运行 A/B/C；D 只能用测试账户或草稿端点，且必须有预览、批次 ID、幂等键、日志和批准，不能发布。

- [ ] 我验证了用户实际看到的最终形态，而不只看源码。
- [ ] 我为外部调用记录目标、最小权限、日志、停止与回滚。
- [ ] 超时后先读取部分状态，而不是盲目重试写入。
- [ ] 我能指出哪些证据仍缺失，且未把连接状态说成完成交付。

在真实最终形态证据和独立复核出现前，本章的练习仍是 `candidate / not_run`。

## 一条自动化合同：先定义数据，再定义动作

以离线“把汇总计数生成一页报告”为例。它只读取一个合成 JSON 文件，写入可丢弃目录；不联网、不登录、不发送。

```text
输入：report-input.json，字段为 date、category、count；count 必须是非负整数。
敏感边界：不接受姓名、邮箱、IP、聊天记录、token 或外部 ID。
转换：按 category 汇总 count；保留输入版本和转换脚本版本。
输出：report.md，含时间范围、分母、缺失字段说明和空数据状态。
验证：重新读取输出；逐项核对总数、类别数、输入哈希和空/坏输入结果。
重试：仅在同一 idempotency key 和可读回输出下重试；未知写入先查询输出状态。
停止：模式不符、数据敏感、目标目录不明确、输出已存在且覆盖规则未确认。
```

“脚本退出为 0”只能证明脚本按自身定义结束。它不证明字段映射正确、图表标签可读、报告有正确受众，或任何外部系统收到预期结果。

### 最终形态检查表

| 交付物 | 打开后要看什么 | 常被遗漏的失败 |
|---|---|---|
| 文档/PDF | 标题层级、分页、链接、空状态、可选择文本 | 源文件正常但打印/导出断行 |
| 网站 | 390px 和桌面宽度、键盘、空/错误状态、目标链接 | 编译成功但按钮不可用或跳错语言 |
| 图表/图片 | 单位、分母、标签、对比度、替代文本、权利 | 漂亮但误导、裁切或无来源 |
| 表格 | 公式、筛选、空值、单位、重算和导出 | 公式被覆盖或分母漂移 |
| 自动化 | 输入/输出模式、日志、批次、幂等键、读回 | 超时后重复写入或半完成被说成成功 |

## 小实验：离线报告流与两个失败变体

1. 建立合成输入：正常数据、空数组、缺少 `count`、负数 `count` 和极端值。不要使用真实客户、个人或生产数据。
2. 先只生成 Markdown 报告，检查标题、数据范围、总数、类别和空状态；再选择是否渲染为 PDF/PNG，并检查最终形态而不只看源码。
3. 为每一次运行保存输入哈希、转换版本、输出路径、退出码、原始日志和读回结果。
4. 模拟“写后超时”：不要立即再次写入；先用同一批次标识读取输出，判断是否存在部分报告。未知则标 `unverified` 并停止。
5. 模拟缺列或坏数据：输出应说明无法生成的原因，而不是编造零值、图表或成功。

若未来要把报告发送到邮件、CRM、云盘或网站，那是新的外部写入动作：需要测试账户或草稿端点、目标与受众确认、人工批准、批次记录、撤回/回滚和在线读回。当前离线练习不授权这些动作。

## 本章验收补充

- [ ] 我能写出输入字段、敏感边界、转换版本、输出模式、验证、重试和停止条件。
- [ ] 我会打开最终交付物，检查空/错误状态和可访问性，而不只看命令或源码。
- [ ] 超时或响应丢失时，我先查询批次和输出状态，不重复可能写入的动作。
- [ ] 我知道本地生成、草稿、已发送、已发布和在线可读回是不同状态。
