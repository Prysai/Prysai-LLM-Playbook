# 第十八章：内容、设计、数据与自动化轨

## 本章要解决的问题

外部技能生态覆盖写作、文档、网页、图像、演示、表格、数据分析、视频和 SaaS 自动化。工具和 Skill 越多，越容易把“源文件存在”“脚本运行过”“接口连接成功”误当成最终交付。真正的风险还包括渲染错位、空状态缺失、图表误读、不可编辑、无障碍问题、版权不清、重复写入、权限过宽、隐私泄露和无法回滚的外部操作。

本章提供统一的产物—风险—验证方法：先定义最终形态和受众，再按风险分层启用能力，最后检查渲染结果、输入输出、权限、失败恢复和发布状态。

## 学习目标

完成本章后，你应能：

1. 按最终产物和风险选择能力，而不是按工具品牌堆叠 Skill。
2. 为文档、网页、图像、演示、表格、PDF、数据流程和自动化流程定义可观察验收标准。
3. 通过最终形态检查布局、层级、可读性、空状态、移动端、可访问性、品牌一致性、事实和可编辑性。
4. 为自动化流程记录输入 schema、转换、外部调用、重试、幂等性、日志、权限、隐私和输出校验。

## 现实问题入口：中间步骤通过，不代表产物或流程通过

- **FP-10**：格式化/验证命令可能长时间停在 Working。它提醒我们，自动化“启动了命令”不等于结果已生成，更不等于结果已检查；必须有超时、退出状态和最终产物。
- **FP-11**：源码验证被报告扩大为持久环境替换。它提醒我们，制作、安装、发布、部署、重启和在线验证属于不同的外部副作用等级，不能由“为了验证”自动合并。

这些记录是现场问题研究中的用户报告/分析，未做本地复现。它们要求学习者把中间产物、最终形态和权限状态分别留下证据。

## 核心概念与决策

### 1. 先按产物组织能力

| 产物 | 最终形态检查 | 典型风险 |
|---|---|---|
| 文档/PDF | 分页、目录、链接、字体、可读性、打印/导出 | 内容错位、字体缺失、引用/版权问题 |
| 网页 | 浏览器渲染、响应式、交互、空/错状态、键盘和移动端 | 源码正确但界面不可用、外部请求越权 |
| 图像/视频 | 尺寸、清晰度、文字、版权、字幕/替代文本、可编辑性 | 事实错误、素材许可不明、不可访问 |
| 演示 | 投影尺寸、层级、对比度、讲述顺序、备注 | 溢出、低对比、静态文件与讲稿不一致 |
| 表格/数据报告 | 公式、筛选、单位、空值、汇总、导出和重算 | 数字错位、分母漂移、公式被覆盖 |
| 自动化 | schema、日志、重试、幂等、权限、回滚、输出校验 | 重复写入、数据泄露、失败后半完成 |

### 2. 最终形态优先

源文件、模板、JSON 和脚本都只是生产材料。验收应至少检查：最终读者看到什么、能否完成目标动作、内容是否正确、布局是否稳定、空状态/错误状态是否可理解、是否可访问、是否可编辑或可复用。必要时渲染为 PNG/PDF、在浏览器打开、重算表格或用测试账号执行一次流程。

### 3. 自动化需要可逆和可重复

对每条流程写出：

```text
输入 schema 与样例：
敏感字段与允许用途：
转换步骤和版本：
外部调用、目标和最小权限：
超时、重试、退避与幂等键：
日志、追踪 ID 和错误分类：
输出 schema 与校验：
失败后的部分状态、补偿和回滚：
人工批准点与停止条件：
```

“接口连接成功”只证明连接，不证明字段映射、数据完整性、重复写入、权限范围和下游结果正确。生产写入前用测试账号、沙盒或本地模拟，保存输入/输出哈希和批次 ID。

### 4. 四层启用模型

1. 本地、只读、低风险：草稿、解析、静态检查、离线分析。
2. 可回滚的项目操作：生成文件、更新分支、输出渲染物，但不发布。
3. 受控外部连接：测试账号、最小 scope、人工批准、可审计日志。
4. 生产写入与公开发布：明确授权、隐私/许可证审查、预览、回滚和在线验证。

升级一层要说明新增权限、风险、证据和恢复成本；没有任务就不要启用更高层。

## 可观察小实验：能力簇而不是工具清单

### Setup

选择目标“制作并发布一份产品报告”，准备脱敏的结构化数据、一个产品说明和一个预期受众。建立四个逐步方案：A 纯文档；B 文档 + 数据分析；C 文档 + 图表渲染；D 文档 + 外部发布。每次只新增一个能力。准备空数据、缺列数据、超大值和错误格式数据作为失败输入。

### Task

1. 为 A–D 写出最终形态、输入输出、最小权限、可能副作用和回滚方式。
2. 先完成 A：生成文档，导出最终格式，检查分页、标题层级、链接、事实和空状态。
3. 增加 B：用脱敏数据生成统计，记录 schema、分母、缺失处理、公式和输出校验。
4. 增加 C：渲染至少一张图表，在最终页面检查标签、单位、对比度、字体、移动/窄屏或打印状态。
5. 增加 D 但只使用测试账号或草稿端点；验证预览、批次 ID、幂等键、日志、失败重试和人工批准，不执行公开发布。
6. 记录每次新增的权限、验证、失败恢复成本和最终状态。

### Evidence

证据包至少包含四种方案的设计表、最终文档/图表/渲染截图或可复现输出、数据字典和校验结果、错误输入响应、调用日志、权限范围、幂等/重试记录、草稿或沙盒状态以及“未发布”的明确证据。不能只提交源文件或脚本。

### Failure variant

让格式化/渲染命令无输出并超过预设时间；让一次外部调用在写入后返回超时；让报告出现空数据和缺列字段。正确行为是停止、保留批次/追踪 ID、检查是否已部分写入、避免无幂等地重试，并把产物标记为不完整；不要 force reinstall、重启或直接发布来“修复验证”。对空数据，最终产物应呈现可理解的空状态，而不是空白图表或虚构的零。

### Reflection

回答：

- 哪个方案首次需要外部权限？为什么？
- 哪个检查只能在最终渲染形态发现？
- 一次超时后你如何证明没有重复写入？
- “连接成功”“草稿生成”“已发布”“在线验证”分别需要什么证据？

## 失败与边界案例

- **源文件正确、渲染结果错误**：检查换行、溢出、字体、图层、链接、裁切、颜色、打印和移动端；渲染截图或实际浏览器状态是必要证据。
- **成品漂亮、事实错误**：对数字、引文、品牌主张、图像中的文字和生成素材做事实与来源审查；未经许可的图片、字体、代码和模板不能直接发布。
- **不可编辑或不可访问**：检查文档结构、替代文本、键盘路径、颜色对比度、字幕、可复制文本、可编辑图层和导出格式。
- **自动化部分成功**：查看日志、状态查询、批次 ID 和下游结果；重试必须使用幂等键或补偿流程，不能仅凭超时判断失败。
- **外部服务写入过宽**：缩小 scope，使用测试账户和草稿 endpoint；需要真实发布时单独请求授权和人工批准。
- **验证命令卡住**：参照 FP-10，设置超时/输出边界；中断后重新检查文件、进程、日志和最终形态。
- **为了验证而改持久环境**：参照 FP-11，区分制作、安装、发布、部署、重启和在线验证，记录每项授权和回滚。

## 迁移练习

选一个你已经生成的文档、网页、表格、图像或自动化：

1. 写出读者、最终格式、成功动作、空/错状态和可访问性要求。
2. 做一次最终形态检查并留下截图、导出文件或浏览器/表格证据。
3. 为自动化部分补齐 schema、敏感字段、幂等、日志、重试、输出校验和回滚。
4. 用测试账号或本地模拟重放一次失败输入，判断状态是 draft、candidate、verified 还是 production-ready。

## 验收清单

- [ ] 我按产物和风险选择能力，没有按工具品牌堆叠 Skill。
- [ ] 我定义了最终读者、最终格式、成功动作、空状态和错误状态。
- [ ] 我检查了最终渲染/运行形态，而不是只看源文件或脚本退出。
- [ ] 我检查了事实、版权/许可证、可访问性、可读性和可编辑性。
- [ ] 我为数据/自动化记录了输入 schema、转换、外部调用、重试、幂等、日志和输出校验。
- [ ] 我使用了测试数据/账号或沙盒，并记录了权限、批次和回滚证据。
- [ ] 我能针对 FP-10 或 FP-11 说明卡住、部分成功和持久环境变更的处理方式。
- [ ] 我没有把草稿生成、连接成功或命令启动描述成公开发布或在线验证。
