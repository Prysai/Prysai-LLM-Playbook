# 第六章：模型选择不是模型崇拜

## 本章要解决的问题

模型选择很容易被一句“这个模型最好”替代。真实工作需要的是：在特定任务、上下文、工具、时间和预算下，哪个模型足够好、更加稳定、返工更少。

## 1. 用任务类型描述需求

先把任务分类，而不是先挑模型：

- **理解与提取：** 从材料中找出结构化信息；
- **转换与生成：** 按固定格式改写、归纳或生成；
- **规划与判断：** 处理多约束、权衡和不确定性；
- **代码与工具：** 读取项目、编辑、运行和修复；
- **研究与审查：** 找来源、核对证据、暴露缺口；
- **创作与设计：** 需要风格、审美和多轮反馈。

不同任务对速度、上下文、工具调用、长程一致性、视觉能力、成本和人工复核的权重不同。

## 2. 建立选择函数

```text
可接受质量
+ 任务稳定性
+ 工具/上下文适配
+ 可验证性
- 成本
- 延迟
- 返工
- 风险
```

这不是要计算出一个神奇分数，而是强迫团队把“最好”拆开。某模型在结构化摘要中便宜稳定，不代表它在复杂重构或高风险审查中就是最佳选择。

## 3. GPT-5.6 Luna 的正确学习方式

官方资料把 GPT-5.6 Luna 描述为面向成本敏感工作负载优化的模型，Codex 文档强调它适合清晰、重复性较强的工作。团队当前提出了“性价比高、适合扩大使用”的待验证假设。

Field Guide 会教用户验证这个假设，而不会把它写成永久结论。至少要固定：

- 同一批任务和输入；
- 同一套工具、权限和上下文；
- 同一验收标准；
- 每个任务的重复次数；
- 运行时间、成本、首次通过率、返工率和错误类型；
- 人工对正确性、完整性和可维护性的评分。

如果只比较一次 demo 的文案观感，不能推出“性价比最高”。

## 4. 先选择最低足够能力

对低风险、重复性任务，优先选择成本和延迟更合适的模型；对高不确定性、高风险或需要复杂工具编排的任务，提高验证强度，必要时换更强模型或增加人工检查。模型更强不等于可以取消边界和验收。

## 实验：固定任务集比较

## 本章验收

学习者能把“模型好不好”改写成一个有任务集、指标、约束和复核日期的比较问题；能区分产品官方描述、团队假设和实验证据；能说明何时降低模型能力、何时提高验证强度。
