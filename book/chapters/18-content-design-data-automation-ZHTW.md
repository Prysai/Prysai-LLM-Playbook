# 第 18 章：內容、設計、資料與自動化軌

## 本章要解決的問題

外部技能生態涵蓋寫作、文件、網站、圖片、簡報、試算表、資料分析、影片和 SaaS 自動化。一個工作流程包含的工具越多，就越容易把「原始檔存在」「腳本跑過」或「API 已連線」誤當成交付完成。

另一些失敗更難察覺：版面破損、缺少空狀態、圖表誤導、輸出不可存取、授權條款不明、重複寫入、權限過大、隱私洩漏，以及無法撤銷的外部動作。本章提供一套「產品—風險—驗證」方法：先定義最終形態與受眾，再按風險順序啟用能力，最後檢查渲染結果、輸入輸出、權限、復原行為和發布狀態。

## 學習目標

學完本章，你應該能夠：

1. 按交付物和風險選擇能力，而不是按品牌堆積工具。
2. 為文件、網站、圖片、簡報、試算表、PDF、資料流和自動化定義可觀察的驗收標準。
3. 檢查最終形態的層級、可讀性、空狀態與錯誤狀態、響應式行為、無障礙性、事實準確性、授權條款和可編輯性。
4. 記錄自動化的輸入格式、轉換、外部呼叫、重試、冪等性、日誌、權限、隱私邊界和輸出驗證。

## 真實問題入口：中間步驟透過不等於交付物透過

- **FP-10：**格式化或校驗指令可能長時間停留在 Working 狀態。「指令已啟動」不能證明輸出已產生或經過檢查；要使用逾時、退出狀態和最終產物作為證據。
- **FP-11：**一份報告把來源驗證擴大成了持久環境替換。建立、安裝、發布、部署、重啟和線上驗證是不同級別的副作用，不能都歸併到「驗證」名下。

這些是實地研究報告或分析，不是本機重現。它們需要為中間產物、最終形態和權限狀態分別提供證據。

## 核心概念與決策

### 1. 按交付物組織能力

| 交付物 | 最終形態檢查 | 常見風險 |
|---|---|---|
| 文件或 PDF | 分頁、目錄、連結、字型、可讀性、列印／匯出 | 重排、字型缺失、引用或授權條款錯誤 |
| 網站 | 瀏覽器渲染、響應式行為、互動、空／錯誤狀態、鍵盤和行動版路徑 | 原始碼看起來正確但介面不可用；請求超出範圍 |
| 圖片或影片 | 尺寸、清晰度、文字、權利、字幕或替代文字、可編輯性 | 事實錯誤、授權條款不明、媒體不可存取 |
| 簡報 | 投影尺寸、層級、對比度、講解順序、備註 | 溢位、對比度低、投影片與講稿不一致 |
| 試算表或資料報告 | 公式、篩選、單位、空值、彙總、匯出、重算 | 數字錯位、分母漂移、公式被覆蓋 |
| 自動化 | 格式、日誌、重試、冪等性、權限、回滾、輸出驗證 | 重複寫入、資料洩漏、部分完成 |

### 2. 從最終形態出發

原始檔、範本、JSON 和腳本都是生產材料。驗收必須追問：讀者會看到什麼、能否完成預期動作、內容是否正確、版面是否穩定、空狀態和錯誤狀態是否易懂，以及輸出是否可存取、可編輯、可重複使用。

當版面重要時，渲染成 PNG 或 PDF；當瀏覽器、試算表或流程是使用者真正面對的形態時，在瀏覽器中開啟網站、重新計算試算表，或用測試帳號執行一次受控流程。原始碼 diff 不能替代最終形態證據。

### 3. 自動化必須可逆且可重複

對每個流程，寫下：

```text
輸入模式與樣例：
敏感欄位與允許用途：
轉換步驟與版本：
外部呼叫、目標與最小權限：
逾時、重試、退避與冪等鍵：
日誌、追蹤 ID 與錯誤分類：
輸出模式與驗證：
部分狀態、補償與回滾：
人工批准點與停止條件：
```

「API 已連線」只能證明連通性。它不能證明欄位對應、資料完整性、重複行為、權限範圍或下游正確性。在生產寫入之前，使用測試帳號、sandbox 或本機模擬，並在適當處保留輸入／輸出雜湊和批次 ID。

### 4. 使用四個能力層級

1. **本機、唯讀、低風險：**起草、解析、靜態檢查和離線分析。
2. **可逆的專案工作：**產生檔案、更新分支，或產出渲染結果而不發布。
3. **受控的外部連線：**測試帳號、最小範圍、人工批准和可稽核的日誌。
4. **生產寫入或公開發布：**明確授權、隱私與授權條款審查、預覽、回滾和線上驗證。

升到更高層級需要書面理由、新權限、新風險、新證據和復原計畫。如果任務不需要更高層級，就不要啟用它。

## 你的頭十分鐘：把模糊需求變成可檢查的草稿

在挑選新工具或連線帳號之前先做這件事。用一個虛構的需求和一份可丟棄的本機檔案，例如：「為三筆虛構的活動報名紀錄寫一頁更新」。目的不是讓模型顯得厲害，而是看一個小請求能否寫得足夠精確、足以檢查。

1. 先寫五行：**讀者**、**最終形態**、**已提供的事實**、**禁止的資料/動作**，以及**怎樣才算可接受**。
2. 把下面這個受限的 prompt 給模型，替換其中的方括號：

   ```text
   為 [讀者] 建立一份 [最終形態]，只能使用這些已提供的事實：[事實]。
   不要編造數字、來源、姓名或結果。資訊缺失時標為 [缺失]，並只問一個問題。
   只返回草稿；不要傳送、釋出、登入或呼叫外部服務。
   驗收檢查：[三個可觀察的檢查項]。
   ```

3. 像讀者一樣開啟草稿。逐項核對每個已提供的事實、每個 `[缺失]` 標記、標題順序和寫明的驗收檢查。
4. 儲存需求、prompt、輸出和一份三行記錄：**passed**、**failed**、**unknown**。如果結果需要真實資料、分發或新權限，就停下來，把它寫成下一步決策，而不是悄悄擴大任務。

一份乾淨的草稿不能證明這個 prompt 普遍更好、工作變得更快，或流程對生產是安全的。它只是為下一次修訂提供一個小而可檢查的比較點。

## 具體證據表

| 證據項 | 具體產物 | 支援什麼 | 不支援什麼 |
|---|---|---|---|
| 最終形態審查 | 渲染出的 PDF/PNG、瀏覽器截圖、重算後的表格或受控輸出 | 讀者或操作者實際看到的內容 | 僅憑原始檔就足夠 |
| 內容與資料審查 | 來源清單、資料字典、公式檢查、驗證輸出 | 已執行的事實與結構檢查 | 沒有來源時，輸出好看不等於事實正確 |
| 無障礙性與可編輯性審查 | 鍵盤路徑、替代文字紀錄、字幕、可選取文字、可編輯圖層檢查 | 宣告過的存取與複用要求是否經過測試 | 對所有裝置或輔助技術的普遍無障礙性 |
| 自動化契約 | 輸入／輸出格式、版本化的轉換、錯誤規則 | 期望的資料形態與驗證邊界 | 外部服務接受了預期的含義 |
| 副作用紀錄 | 權限範圍、測試帳號身分、批次 ID、追蹤日誌、草稿狀態 | 哪些外部動作已獲授權或準備好 | 公開發布確實發生 |
| 復原紀錄 | 冪等鍵、狀態查詢、補償或回滾證據 | 如何偵測和修復部分完成 | 逾時意味著沒有發生寫入 |

## 可觀察的小實驗：能力分組，而不是工具清單

### 準備

使用一個**合成的產品報告場景**來訓練：一份虛構的產品描述、一份小型去識別化結構化 fixture 和預期的受眾。它不是客戶報告、庫存紀錄、帳號、收入來源或發布請求。準備四個範圍逐級放寬的方案：A 僅文件；B 文件加資料分析；C 文件加圖表渲染；D 文件加外部分發。再加入空資料、缺欄、一個極端值和畸形輸入作為失敗 fixture。

### 任務

1. 對 A–D，記錄最終形態、輸入輸出、最小權限、可能的副作用和回滾方法。
2. 完成 A：生成並匯出文件，然後檢查分頁、標題層級、連結、事實和空狀態。
3. 加入 B：從合成 fixture 計算描述性數值，記錄模式、分母、缺失值處理、公式和輸出檢查。
4. 加入 C：渲染至少一張圖表，在最終形態中檢查標籤、單位、對比度、字型、窄屏行為和列印行為。
5. 只有使用測試帳號或草稿端點時才加入 D。檢查預覽、批次 ID、冪等鍵、日誌、重試行為和人工批准。不要發布。
6. 每加入一項能力，就記錄新的權限、驗證、復原代價和最終狀態。

### 證據

證據包應包含：A–D 的設計表、最終的文件／圖表／渲染輸出或可重現的輸出、資料字典和驗證結果、對無效輸入的回應、呼叫日誌、權限範圍、冪等與重試紀錄、sandbox 或草稿狀態，以及「未發生公開發布」的明確證據。僅憑原始檔或腳本是不夠的。

### 失敗變體

讓一個格式化器或渲染器在規定的逾時之前不產生任何輸出。讓一次外部呼叫在模擬寫入之後逾時。給報告空資料和缺欄。正確的行為是：停下，保留批次或追蹤 ID，查詢是否存在部分寫入，避免非冪等的重試，並把交付物標記為未完成。不要用強制重灌、重啟或發布來「修復驗證」。空資料應該產生容易理解的空狀態，而不是空白圖表或編造出來的零。

### 反思

- 哪個方案最先需要外部權限？為什麼？
- 哪個缺陷只能在最終渲染形態中才能發現？
- 超時之後，什麼證據能說明是否發生了重複寫入？
- 什麼證據能把「已連線」「草稿已生成」「已釋出」「已線上驗證」區分開？

## 失敗與邊界情況

- **原始碼正確，渲染損壞：**檢查換行、溢位、字型、圖層、連結、裁切、顏色、列印和行動版行為。渲染結果或瀏覽器即時狀態是必要證據。
- **輸出漂亮，事實錯誤：**對照來源複核數字、引文、品牌主張以及生成媒體中的文字。不要發布權限不明的圖片、字型、程式碼或範本。
- **輸出不可存取或不可編輯：**檢查文件結構、替代文字、鍵盤路徑、對比度、字幕、可選取文字、可編輯圖層和匯出格式。
- **自動化部分成功：**檢查日誌、狀態查詢、批次 ID 和下游狀態。只有帶上冪等鍵或補償流程才能重試；僅憑逾時不能證明失敗。
- **外部範圍過大：**縮小範圍，使用測試帳號和草稿端點，並單獨申請真實的發布授權。
- **校驗指令掛起：**按 FP-10，設定輸出邊界和逾時；中斷後重新檢查檔案、程序、日誌和最終形態。
- **驗證改變了持久環境：**按 FP-11，把建立、安裝、發布、部署、重啟和線上驗證分開。為每一項記錄授權和回滾。

## 遷移練習

選一個現有的文件、網站、試算表、圖片或自動化：

1. 寫下讀者、最終格式、成功動作、空／錯誤狀態和無障礙性要求。
2. 做一次最終形態審查，並保留截圖、匯出檔案或瀏覽器／試算表產物。
3. 用格式、敏感欄位、冪等性、日誌、重試、驗證和回滾補全自動化契約。
4. 用測試帳號或本機模擬重放一個失敗輸入，並把結果分類為 `draft`、`candidate`、`verified` 或 `production-ready`。

## 來源與維護邊界

- **實地報告：**[`docs/research/field-problems-codex.md`](../evidence-library-ZHTW.md#source-notes)，FP-10 和 FP-11。這些紀錄為 `candidate`，於 2026-08-09 查閱並整理，未在本機重現。
- **外部資產與授權條款邊界：**[`docs/sources/asset-register.md`](../evidence-library-ZHTW.md#source-notes)，S01、S03 和 S06。授權條款不明的圖片、程式碼、範本或巢狀資產僅供引用，不得複製進發布物。
- **易變的工具事實：**以實際使用的文件、PDF、試算表、瀏覽器、渲染和外部服務工具的官方文件為準。在工作紀錄中記下 URL、查閱日期、版本和範圍。
- **維護負責人：**內容與自動化軌維護者。當渲染器、格式、瀏覽器、API、授權條款或權限模型發生變化時進行複核，且不晚於 2026-11-09。

本章狀態為 `candidate`。只有在相關的最終形態、資料品質、隱私、授權條款、回滾和線上證據齊備之後，交付物才能被稱為 `verified` 或 `production-ready`。本章不報告任何生產執行。
