# 第二十二章：持续更新与未来适应

## 本章要解决的问题

Codex 的入口、模型、推理设置、权限、Skill 分发方式和外部服务都会变化。一套今天有效的流程，如果没有来源、复核和迁移设计，几个月后可能变成误导。持续更新不是不停追逐新功能，而是知道什么稳定、什么易变、什么必须重新验证，以及什么时候应该删除能力。

## 学习目标

读者完成本章后应当能够：

- 将知识分成稳定原理、产品用法、领域方法和实例事实；
- 为易变断言建立来源、日期、范围、责任人和状态；
- 设计模型、工具或 Skill 变化后的影响分析与迁移流程；
- 识别过时、低价值、高风险和无人维护的能力；
- 用评测结果而不是目录规模决定保留、更新或下线。

## 1. 四层知识的不同寿命

| 层 | 例子 | 更新方式 |
|---|---|---|
| 稳定原理 | 上下文影响理解、工具改变行动空间、证据支持完成声明 | 通过教学和实验复查 |
| 产品用法 | Codex 入口、Skill 调用、权限模式和配置方式 | 对照官方文档复核 |
| 领域方法 | 工程、研究、营销、文档和数据工作流 | 用实践任务和人工审查更新 |
| 实例事实 | 模型 ID、价格、额度、命令参数、第三方 API | 带来源和日期，必要时迁移或删除 |

不要为了追求“永不过时”而把所有内容写得模糊；应该明确每条内容的适用范围和复核责任。

## 2. 一条更新事件的处理流程

```text
发现变化
  → 判断影响层级和风险
  → 定位受影响的章节、Skill、实验和任务集
  → 读取权威来源或运行事实
  → 更新内容、来源和迁移说明
  → 重跑相关评测与实验
  → 新鲜上下文复核
  → 发布、保留旧版或下线
```

发现变化不等于立即全量修改。先建立影响范围，避免把一个产品名称变化误写成整个方法论失效。

真实问题入口：[研究问题收敛实验](../labs/lab-008-research-question.md)。评测夹具入口：[评测框架/任务字段规范](../../docs/quality/evaluation-framework.md)。研究档案入口：[OpenAI Codex 官方基线](../../docs/research/openai-codex-baseline.md)。

## 3. 为每条易变断言建记录

最小记录应包括：

```yaml
claim: "当前断言"
source: "官方或上游权威 URL"
checked_at: "YYYY-MM-DD"
applies_to: "产品、版本、地区、账户或组织范围"
owner: "维护者"
next_review: "YYYY-MM-DD"
status: "verified | stale | disputed | removed"
```

当来源无法访问、账户范围不明或运行结果与文档冲突时，状态应变成 `disputed` 或 `stale`，而不是继续以肯定语气发布。

## 4. 模型和 Skill 的迁移

模型迁移不能只替换一个字符串。至少重新检查：

- 任务集中的首次通过率和错误类型；
- 推理强度、上下文长度、工具支持和耗时；
- 提示、Skill 触发和输出格式是否仍然有效；
- 权限、隐私和外部服务行为是否发生变化；
- 失败处理、回滚和用户说明是否需要更新。

Skill 迁移也不能只复制目录。要检查来源许可证、依赖、命名、认证、真实副作用、维护人和评测结果。

## 5. 何时删除能力

下列情况足以启动下线审查：

- 关键来源消失或许可证不再允许当前分发方式；
- 正例通过率下降，且维护成本高于价值；
- 能力触发过宽或产生不可接受的副作用；
- 已被更小、更清晰、更可验证的能力替代；
- 没有维护人，也没有可复现的评测证据。

下线不是失败。删除过时能力可以减少错误触发和维护负担，但应保留迁移说明，告诉使用者替代路径。

## 实验：处理一次假设的产品变化

选取一个带日期的模型或工具事实，假设官方资料发生变化。建立影响表：受影响的章节、Skill、实验、任务集、权限说明、来源记录和用户提示。只修改需要修改的部分，然后运行项目校验和相关评测。

### 故意失败变体

把一个新模型名称直接批量替换到所有文档，不更新任务集、适用范围和来源。通过标准是发现这种迁移不充分，并恢复为有影响分析的变更。

## 迁移练习

把一条外部候选 Skill 从“未审查”推进到“阻塞”或“适配候选”，说明许可证、依赖、触发、风险和维护证据各缺什么。不要因为名称看起来合适就批准它。

## “我真的学会了吗？”

- [ ] 我能区分稳定原理、产品用法、领域方法和实例事实；
- [ ] 每条易变断言都有来源、访问日期、适用范围和责任人；
- [ ] 模型迁移包含评测、工具、权限、Skill 和失败路径检查；
- [ ] 我知道什么时候把状态标为过时、有争议或删除；
- [ ] 我能解释为什么目录增加不等于能力系统变好；
- [ ] 更新后有新鲜上下文复核和可追踪的变更记录。

## 易变事实与来源

模型选择、Codex 入口、推理设置和弃用时间以 [OpenAI 官方 Models 文档](https://learn.chatgpt.com/docs/models) 及相关官方变更文档为准。Field Guide 的 [`docs/governance/content-lifecycle.md`](../../docs/governance/content-lifecycle.md) 规定了本项目的更新与复核流程。
