# 第十二章：Agent 的循环、状态和停止条件

## 本章要解决的问题

用户常说“让 Agent 自主完成”，却没有说明它如何观察、如何决定下一步、什么时候重试、什么时候询问人、什么时候停止。没有这些约束，自主性很容易变成不可审查的连续动作。

## 1. 一个可观察的循环

```text
读取目标与上下文
       ↓
形成当前计划/假设
       ↓
选择一个允许的工具动作
       ↓
观察返回结果与错误
       ↓
更新状态、风险和下一步
       ├─ 已满足验收 → 交付
       ├─ 缺少输入/权限 → 暂停询问
       ├─ 可恢复失败 → 缩小范围重试
       └─ 风险/重复失败 → 停止并报告
```

这是一种行为模型，不是对模型隐藏推理的猜测。学习者要审查的是请求、可用上下文、规则、工具、结果和停止行为。

## 2. 状态要显式化

复杂任务至少区分：目标、当前假设、已读取、已改变、已验证、未验证、阻塞、待确认和下一步。状态越清楚，交付和恢复越可靠。

## 3. 重试不是无限循环

重试前要说明失败类别和变化点。相同输入、相同工具、相同权限和相同假设的重复尝试通常不会产生可靠的新证据。更好的动作可能是补充上下文、缩小范围、换验证方式或请求人类判断。

## 4. 停止条件

常见停止条件包括：验收已经满足、输入不足、权限不匹配、出现未授权副作用、发生重复失败、发现任务目标冲突、达到风险或时间预算。停止是能力，不是失败。

## 实验：缺失输入与重复失败

设计一个需要文件或命令才能完成的任务，但故意不给出该输入。观察 Agent 是否澄清而不是猜测。再让验证命令连续失败两次，检查它是否改变诊断策略、缩小范围并报告阻塞。

## 本章验收

学习者能画出一条 Agent 循环；能为每个分支写出状态和停止条件；能解释如何从可观察证据判断 Agent 为什么继续、暂停或停止；能区分自主执行和无边界执行。
