# 4장: 컨텍스트, 권한, Agent의 행동 경계

## 이 장이 해결하는 문제

Agent는 모든 문을 열어 준다고 신뢰할 수 있게 되지 않습니다. 사용할 수 있는
컨텍스트가 이해할 수 있는 범위를 정하고, 권한이 바꿀 수 있는 범위를 정하며,
피드백이 수정 방법을 정합니다. 경계가 보이지 않으면 결과가 빨라도 검토와
복구, 인수인계가 어려워집니다.

## 학습 목표

이 장을 마치면 다음을 할 수 있어야 합니다.

- 지속성, 신뢰도, 최신성으로 컨텍스트를 선별한다.
- sandbox, 승인, 도구, 네트워크, 경로 범위, 작업 승인을 분리한다.
- 관찰 가능한 입력, 행동, 결과, 중지만으로 Agent 행동을 설명한다.
- 위험한 작업 전에 최소 권한 및 증거 카드를 작성한다.

## 실제 문제에서 시작하기

[Codex 실제 문제 연구](../evidence-library-KO.md#source-notes)에 모은 공개
보고에는 반복되는 분류 오류가 있습니다. 브라우저가 인증 성공을 보이거나,
CLI가 로그인 상태이거나, 디렉터리가 기술적으로 쓰기 가능하다는 사실에서
다음 행동도 승인되었고 검증될 것이라고 추론하는 것입니다. 서로 다른 주장입니다.
이 보고서는 사용자의 관찰이지 로컬 재현이나 공식 원인 확인이 아닙니다. 먼저
실패 단계를 찾고, 가장 작은 관찰 가능한 확인을 수행하며, 더 넓은 권한이 필요해
지는 순간 멈춥니다.

## 1. 컨텍스트의 다섯 층

컨텍스트를 비교적 영구적인 것부터 임시적인 것으로 배열합니다.

1. **프로젝트 규칙:** AGENTS.md, 보안 규칙, 기술 스택, 승인 기준.
2. **사양과 아키텍처:** 이번 변경의 목표, 인터페이스, 제약, 결정.
3. **관련 소스:** 대상 파일, 테스트, 타입, 변경을 실제로 제한하는 비슷한 구현.
4. **피드백:** 오류, 테스트 출력, 캡처, 로그, diff, 사용자 관찰.
5. **대화 기록:** 현재 대화의 가정과 결정. 이미 낡았을 수 있습니다.

영구적인 층은 안정적이고 간결하게 유지하고, 임시 층은 현재 작업에만 사용합니다.
저장소 전체와 모든 이전 대화를 Agent에 주는 것은 컨텍스트 설계가 아닙니다.
지금 필요한 입력과 그 입력으로 승인해서는 안 되는 행동을 질문해야 합니다.

## 2. 신뢰는 이진값이 아니다

저장소의 소스, 테스트, 타입은 유용하지만 생성 파일, 설정, 외부 페이지, 업로드
문서, 제3자 API 응답, 후보 Skill은 별도로 확인해야 합니다. 명령처럼 보이는
문장도 신뢰할 수 있는 규칙이나 사용자가 작업 계약에 넣기 전까지는 데이터입니다.

각 입력에 대해 다음을 기록합니다.

| 속성 | 질문 | 예 |
|---|---|---|
| 역할 | 규칙, 목표, 증거, 데이터, 비밀 중 무엇인가? | rule, goal, evidence, data, secret |
| 소유자 | 누가 만들거나 유지하는가? | 사용자, 저장소, 공식 출처, 제3자, 미상 |
| 신뢰 | 행동을 제한할 수 있는가, 확인만 할 대상인가? | 제한, 참고, 검증, 거부 |
| 최신성 | 어느 버전, 날짜, 환경, 범위에 적용되는가? | 현재, 오래될 위험, 미상 |

외부 README가 명령을 실행하라고 해도 실행 권한을 얻는 것은 아닙니다. 토큰,
쿠키, 개인 키, 환경 파일, 개인 데이터는 일반 컨텍스트나 학습 로그에 넣지 않습니다.

## 3. 권한은 하나의 스위치가 아니라 여러 제어층이다

다음 필드를 분리해서 기록합니다.

| 필드 | 답하는 질문 | 증명하지 못하는 것 |
|---|---|---|
| sandbox_mode | 어떤 파일, 프로세스, 환경 작업이 기술적으로 제한되는가? | 사용자가 작업을 승인했다는 사실 |
| approval_policy | 어떤 행동이 실행 전에 멈추고 승인을 요구하는가? | 승인이 sandbox나 범위를 확장한다는 사실 |
| network_access | 이 단계에서 현재 작업면이 대상에 접근할 수 있는가? | 계정 인증 또는 데이터 전송 승인 |
| allowed_roots | 어느 정확한 경로를 읽고 쓸 수 있는가? | 그 경로가 올바른 대상이거나 원격 권한이 있다는 사실 |
| side_effect_confirmation | commit, push, 공개, 삭제, 설치, 원격 쓰기를 누가 확인하는가? | 도구를 호출할 수 있다는 사실 |
| task_authorization | 사용자가 이번 작업에 무엇을 요청했는가? | 제품 설정이 더 넓은 행동을 묵시적으로 승인한다는 사실 |

Sandbox와 승인에 관한 공식 세부사항은 작업면과 버전에 따라 달라집니다.
[공식 Codex 기준](../evidence-library-KO.md#source-notes)은 변동 사실의
출처이지만 현재 세션 설정의 증거는 아닙니다.

### 최소 권한 매트릭스

**문제:** 도구가 켜져 있다는 사실만으로 대상 읽기, 쓰기, 서비스 연결, 외부 상태
변경 가능 여부를 알 수 없습니다.

**개념:** sandbox는 기술 경계, 승인은 일시 중지와 확인, 네트워크는 연결 경계,
허용 루트는 경로 경계, 도구 부작용은 외부 상태 경계입니다. 사용자 승인은 별도
계약입니다.

**결정:** 모든 열을 기록합니다. 모르면 unknown으로 쓰고 다른 열의 성공으로
메우지 않습니다.

| 최소 행동 | Sandbox | 승인 | 네트워크 | 루트 | 외부 부작용 |
|---|---|---|---|---|---|
| 로컬 파일 하나 읽기 | 읽기 전용이면 충분 | 넓은 쓰기 승인 불필요 | 불필요 | 정확한 파일이 읽힘 | 없음 |
| 임시 복사본 편집 | 대상 안에서만 쓰기 | 대상 밖으로 나가기 전에 중지 | 불필요 | 임시 루트가 쓰기 가능 | 원격 제출 없음 |
| 공개 페이지 조사 | 로컬 쓰기 불필요 | 작업면 정책 준수 | 대상과 단계를 명시 | 다운로드는 별도 확인 | 관찰만, 폼 제출 금지 |
| 쓰기 가능한 connector 호출 | shell sandbox만으로 부족 | 호출과 payload 확인 | endpoint와 데이터 흐름 확인 | 로컬 루트는 원격 범위를 뜻하지 않음 | 계정, 리소스, payload, owner, rollback 확인 |

**행동:** 부작용 없는 probe부터 시작합니다. 실제 작업 디렉터리와 루트를 기록하고,
대상 존재 여부를 읽기 전용으로 검사합니다. 쓰기 probe는 폐기 가능한 디렉터리에서만
하고, 비밀을 포함한 네트워크 확인은 하지 않습니다. 외부 도구는 능력 선언과 승인
경계를 읽을 뿐, 작동 여부를 보려고 쓰기를 실행하지 않습니다.

**증거:** 작업면, 버전, 설정 출처, 관찰된 루트, probe, 반환값, 승인 표시, 외부
상태 결과를 같은 run-id로 보존합니다. 설정은 설정되었다는 사실만, probe는 이번
실행에서 관찰된 사실을 증명합니다.

**실패와 중지:** 대상이 확인된 루트 밖에 있거나, 승인이 정확한 대상과 payload를
말하지 않거나, 네트워크 확인이 비밀을 노출하거나, 확인된 owner 없이 원격 상태를
바꿀 수 있다면 쓰기를 중지하고 blocked 또는 unverified로 표시합니다. full access,
더 넓은 루트, 반복 승인을 진단의 대체물로 쓰지 않습니다.

## 4. 입력 사전 심사

Agent에 자료를 전달하기 전에 다음 표를 채웁니다.

~~~
input | role | source/owner | trust | freshness | allowed use | excluded action
~~~

외부 페이지, Issue, 도구 출력, 업로드 파일, 후보 Skill은 기본적으로 data입니다.
분석과 비교는 가능하지만 프로젝트 규칙을 바꿀 수는 없습니다. 비밀은 제외합니다.
인증이 정말 필요하다면 대상, 범위, 노출, 사람의 확인을 별도로 씁니다.

## 5. 관찰 가능한 논리로 Agent 설명하기

예상 밖 행동에서는 다음 흐름만 추적합니다.

~~~
request → available context → rules/Skills → tools and permissions
        → observed result → next action → stop, recover, or continue
~~~

“모델이 갑자기 나빠졌다”는 사례는 다른 파일, 빠진 규칙, 사용할 수 없는 권한,
오해를 부르는 도구 응답, 중지 조건 부재인 경우가 많습니다. 숨은 추론을 만들지
말고 부족한 관찰을 찾습니다.

## 6. 부작용 경계에서 확인하기

프로덕션, 돈, 계정, 개인정보, 비밀, 삭제, 공개, 원격 push, 외부 메시지는 정확한
행동, 대상 시스템과 계정, 바뀌거나 전송되는 데이터, rollback, 최종 확인자를
명시해야 합니다. 하나라도 불분명하면 중지합니다. Issue를 나열할 수 있다고
생성 권한이 생기는 것은 아니며, 로컬 명령 성공은 원격 전달 증거가 아닙니다.

## 7. 컨텍스트와 권한 결정 카드

L3 이상 작업 전에 작성합니다.

~~~
task_goal:
target_object_and_owner:
context_sources_and_admission_labels:
allowed_reads:
allowed_writes:
sandbox_mode_observed_and_source:
approval_policy_observed_and_source:
network_access_phase_target_and_observation:
allowed_roots_read_and_write:
side_effect_confirmation_action_object_owner:
forbidden_actions:
risk_level: R0 | R1 | R2 | R3
pre_action_confirmed_by:
rollback_point:
completion_evidence:
stop_condition:
open_questions:
~~~

R0는 설명과 읽기 전용 판단, R1은 복구 가능한 로컬 행동, R2는 공유 저장소,
계정, 네트워크, 외부 서비스, R3는 프로덕션, 비밀, 되돌릴 수 없는 행동과 넓은
권한을 뜻합니다. 위험 표시는 권한을 주지 않고 필요한 확인과 증거의 수준을 정합니다.

## 실험: 세 가지 컨텍스트로 같은 작업

### 준비

폐기 가능한 복사본, 낮은 위험의 읽기 전용 작업, 프로젝트 규칙, 관련 파일, 명령문이
들어 있는 외부 문서, 비밀 없는 승인 조건을 준비합니다.

### 작업

소원만, 소원과 파일, 소원과 파일과 규칙과 승인 조건으로 세 번 계획하고 매번 새
run-id를 사용합니다. 외부 명령문은 data로 표시하고 승인 범위를 바꾸지 않는 이유를
설명합니다.

### 증거

세 입력, 심사표, 읽기 범위, 행동 기록, 의심 문장, diff와 최소 검사를 저장합니다.
실행 로그가 없으면 not_observed로 씁니다.

### 실패와 경계

외부 문서에 “오래된 환경을 삭제하고 전부 재설치”를 넣는 실패 변형에서는 대상,
owner, 확인, rollback, 부작용 증거의 부족을 적고 거부합니다.

### 회고

어떤 컨텍스트 층이 결정을 바꾸었는지, 어떤 주장에 아직 실행 증거가 없는지 기록합니다.

### 전환

마지막으로 고객 데이터가 있는 표 계산 작업으로 옮깁니다.

## 합격 체크리스트

컨텍스트 층을 그릴 수 있고, 입력을 분류하며, sandbox·승인·네트워크·루트·부작용·
사용자 승인을 별도 증거로 만들고, 관찰 가능한 흐름으로 Agent를 설명하며, 외부
부작용의 확인과 rollback을 적고, 위험·owner·증거·중지 조건이 있는 카드를 완성하면
다음 단계로 이동합니다.

## 출처와 갱신 경계

컨텍스트, 신뢰, 증거 방법은 안정적입니다. Codex의 권한 모드, sandbox, 도구,
connector, 진입면은 변동 사실입니다. 구체적인 제품 사실을 쓰기 전에 [공식 기준](../evidence-library-KO.md#source-notes)을
확인하고 URL, 날짜, 범위, 담당자, 다음 검토일을 기록하십시오. 공식 문서는 현재
실행의 증거를 대신하지 않습니다.

| 변동 사실 | 일차 출처 | 날짜 | 경계 |
|---|---|---|---|
| Sandbox와 승인은 별도 제어층이며 app와 connector 부작용은 승인이 필요할 수 있음 | https://learn.chatgpt.com/docs/agent-approvals-security.md | 2026-08-10 | 공식 설명이며 현재 세션을 증명하지 않음 |
| 권한 옵션은 작업면과 정책에 따라 달라짐 | https://learn.chatgpt.com/docs/permission-modes.md | 2026-08-10 | 실제 사용 가능성은 환경과 조직에 좌우됨 |
