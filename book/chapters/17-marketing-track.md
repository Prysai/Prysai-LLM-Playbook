# 第十七章：营销轨——从产品理解到增长实验

## 本章要解决的问题

营销任务常因缺少产品、受众、定位、证明材料和目标行动而变成泛泛的文案。另一个危险是：团队先埋大量事件、生成漂亮图表，再追问这些数据能改变什么决策。更严重时，营销 Skill 会把个人信息、客户名单、组织权限或外部平台写入权限带入不必要的实验。

本章把营销工作定义为可复核的决策系统：先建立版本化产品上下文，再写假设和最小测量计划，最后在尊重隐私、样本边界和归因不确定性的条件下生成内容和行动。

## 学习目标

完成本章后，你应能：

1. 创建包含产品、受众、问题、替代方案、差异化、反对意见、客户语言、品牌语气、证明材料和目标行动的产品上下文。
2. 从一个具体决策反推最小事件、指标、样本、窗口、命名和停止规则。
3. 识别营销结论中的样本偏差、归因过度、选择性报告、隐私风险和不确定性。
4. 在不暴露个人数据、不绕过平台权限、不自动发布的前提下使用营销 Skill 设计增长实验。

## 现实问题入口：外部身份、组织与数据都需要上下文

- **FP-03**：Enterprise-only 用户在 PR 入口被错误探测到 `github.com`。它说明域名、组织、账号和渠道上下文不能由界面默认值代替；营销或增长流程同样不能把“默认 host/默认受众”写成用户事实。
- **FP-04**：同一用户对两个组织有权限，但 connector 复用第一个组织。它说明“有账号权限”不等于“当前实验获准访问该组织数据”，也提醒我们分离身份、组织、安装范围和数据用途。

两条记录均为现场研究中的用户报告，未有官方确认或本地复现。它们在本章中用于训练上下文、权限和证据边界，不构成对 connector 行为的普遍断言。

## 核心概念与决策

### 1. 产品上下文是共享资产，不是一次性提示词

至少记录：

```text
产品/版本与非目标：
目标受众与排除受众：
核心问题与使用场景：
替代方案和切换成本：
差异化主张与证明材料：
常见反对意见和客户原话（已脱敏）：
品牌语气、禁用表达和合规边界：
目标行动与行动前提：
渠道、地区、语言和时间范围：
版本、变更原因、负责人和复核日期：
```

没有证明材料的主张只能写成假设；没有受众范围的“客户喜欢”不能作为普遍结论；没有目标行动的文案不能判断是否有效。

### 2. 为决策而测量

先写“如果看到结果 X，我们会做什么”，再决定数据：

```text
要做的决策：
关键假设：
最小需要知道的问题：
指标定义与命名：
分母、样本、时间窗口和分群：
触发、去重、缺失和延迟处理：
隐私、同意、保留期和访问控制：
停止规则与下一步行动：
```

例如，“按钮点击率更高”只有在明确分母、去重、曝光条件、统计窗口和下一步动作后才是可复核指标。不要把个人邮箱、完整 IP、聊天全文或跨站标识符作为默认分析输入；优先使用聚合、脱敏、短期保留和测试数据。

### 3. Agent 的角色是辅助，不是归因权威

Agent 可以整理产品上下文、产生变体、检查事件命名、计算描述性统计和提出下一轮实验，但不能凭文案差异直接断定因果，不能把样本偏差藏在图表中，也不能擅自向广告平台、CRM、邮件系统或社交平台发布内容。外部写入要使用测试账户、沙盒、人工批准和可回滚批次。

### 4. 营销能力簇而不是工具目录

将候选 Skill 归入五类：产品上下文、内容与定位、转化实验、分发与增长、测量与归因。每类都绑定输入、输出、权限和证据。例如“分发”需要渠道授权和发布记录；“测量”需要事件 schema、隐私说明和数据质量检查；“归因”需要假设、对照或明确的观察性限制。

## 可观察小实验：同一产品的两种请求

### Setup

选择一个不含真实客户数据的虚拟或内部产品，准备脱敏的产品说明、目标受众、三个反对意见、一个可核实证明和一个目标行动。建立一个本地数据表，只有聚合计数，不包含姓名、邮箱、完整 IP、设备标识或跨平台 ID。定义一个短时间窗口和两个内容变体。

### Task

1. 向 Agent 提出请求 A：“为产品写一段高级介绍。”保存输出。
2. 向 Agent 提出请求 B：提供版本化产品上下文、受众、反对意见、证明、目标行动和测量计划，要求生成两种变体、假设、主要指标、分母、样本限制和下一步决策。
3. 对比 A/B 是否更具体、可核实、符合受众和可行动；标出任何无来源主张。
4. 要求 Agent 检查事件命名、去重、缺失值、时间窗口和隐私边界，不上传数据、不调用真实渠道。
5. 用聚合样例做描述性比较；不把差异直接称为因果，不在样本不足时宣布赢家。

### Evidence

保留两次请求、产品上下文版本、变体、假设表、指标定义、样本/分母、脱敏数据字典、隐私决策、数据质量检查和下一步决策。证据要说明哪些内容是产品事实，哪些是营销假设，哪些指标会触发什么行动。

### Failure variant

提供一个默认组织为 `github.com`、实际只授权 Enterprise host 的模拟渠道；再提供两个组织的汇总数据，但只授权其中一个组织。观察 Agent 是否自行跨组织读取或将默认 host 当成事实。正确行为是暂停、确认 host/组织/授权范围，使用最小数据或测试数据；不能因为用户“有权限”就扩大实验范围。再把少量样本和高点击差异输入模型，检查它是否声明样本不足和观察性限制。

### Reflection

回答：

- A 与 B 的差异来自哪些上下文字段？
- 哪个指标真正会改变下一步决策？
- 哪些数据可以聚合或删除，仍足以回答问题？
- FP-03/04 如何改变你对 host、组织、受众和数据访问的默认假设？

## 失败与边界案例

- **虚构证明或客户语言**：没有来源的评价、客户数字和“行业第一”必须改为待核实主张或删除。
- **样本小却宣布赢家**：记录样本量、分母、时间窗口、分群和缺失；若无法支持稳定判断，输出“方向性信号”或继续收集，不伪造统计确定性。
- **把相关写成因果**：同期改了标题、渠道、价格和受众时，不能把转化差异归因给单一变量；拆分变量或明确是观察性结果。
- **平台权限错配**：FP-03/04 的 host、组织和安装范围应成为每个外部渠道实验的前置检查；不要用默认账号、缓存权限或已有 connector 代替当前授权。
- **隐私越界**：营销分析中不要默认输入个人信息、敏感属性、私密对话、未同意联系人或可跨场景追踪的标识符；使用最小化、脱敏、聚合、访问控制和保留期限。
- **自动发布不可回滚**：发送邮件、投放广告、修改 CRM、发社交内容或改变埋点前，先在沙盒/草稿状态验证，保留人工审批、批次 ID 和撤回/回滚方法。
- **漂亮图表掩盖数据质量**：检查重复事件、时区、延迟、机器人流量、分母漂移、缺失和渠道筛选；图表不是证据本身。

## 迁移练习

选一个真实营销目标，但只使用脱敏或聚合数据：

1. 写一页产品上下文，标出事实、假设和需要补证的主张。
2. 选择一个可改变的决策，设计最小测量计划和停止规则。
3. 为每个字段写隐私理由、访问范围、保留期限和删除方式。
4. 设计一个沙盒实验和一个失败变体，让同事检查是否会越过 host、组织或发布授权。

## 验收清单

- [ ] 我有版本化产品上下文，并记录负责人、变更原因和复核日期。
- [ ] 我区分产品事实、营销假设、客户证据和待核实主张。
- [ ] 我能从决策反推最小指标、分母、样本、窗口和停止规则。
- [ ] 我检查了重复、缺失、延迟、时区、机器人或选择偏差等数据质量问题。
- [ ] 我没有把相关性写成因果，也没有用小样本宣布稳定赢家。
- [ ] 我使用了最小化、脱敏/聚合、访问控制和保留期限，未暴露个人数据。
- [ ] 我能针对 FP-03 或 FP-04 说明 host、组织、connector 和实验授权的区别。
- [ ] 我没有在未批准、未沙盒验证或不可回滚的条件下发布或写入外部平台。
