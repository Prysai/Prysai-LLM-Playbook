# 第十六章：工程轨——从想法到可靠软件

## 本章要解决的问题

工程工作最容易让 Agent 直接进入代码，跳过定义、测试和审查。成熟的工程 skill 不是让 AI 写更多代码，而是把资深工程师的质量门槛变成每个阶段都能执行的工作流。

## 1. 工程生命周期

```text
定义 → 规格 → 计划 → 增量实现 → 测试/调试
     → 运行验证 → 审查/简化 → 发布/维护
```

每个阶段都要有进入条件和退出证据。没有清楚的规格时先澄清；没有可验证的切片时继续拆分；没有失败原因时先诊断，不要直接改更多代码。

## 2. 工程轨的三条纪律

- **来源驱动：** 框架、API、库和版本决策以官方文档或代码为准；
- **怀疑驱动：** 对无法由类型系统、编译器或单元测试证明的非平凡断言做反向审查；
- **增量驱动：** 每个切片保持小、可运行、可回滚，定期检查差异和维护成本。

## 3. “通过测试”不是完成

还要检查需求、运行时行为、错误处理、边界、性能、安全、可观察性、文档和发布回滚。测试策略应与风险匹配；一条绿灯不能证明所有用户路径都正确。

## 实验：工程生命周期对照

同一个小功能，先让 Codex 按“直接实现”完成一次，再按完整生命周期完成一次。比较提问数量、变更范围、首次通过率、发现问题的阶段和最终交付证据。

## 本章验收

学习者能为工程任务写出进入/退出条件；能把官方文档验证、增量实现、测试、审查和发布纳入同一条工作流；能区分编译成功、测试通过、运行正确和生产可用。
