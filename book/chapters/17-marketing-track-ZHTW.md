# 第 17 章：行銷路線——從產品理解到成長實驗

## 本章要解決的問題

當請求缺少產品、受眾、定位、證據與期望行動時，行銷工作就會變得含糊不清。若團隊在決定資料應該改變什麼之前，就先去收集大量事件流或做出漂亮的儀表板，也會帶來風險。更嚴重的失誤是：讓一個行銷 Skill 把個人資料、客戶名單、組織權限或發佈權限帶進一個根本不需要它們的實驗。

本章把行銷當作一個可複核的決策系統：建立有版本的產品脈絡，陳述假設，定義最小而有用的測量計畫，然後在尊重隱私、樣本限制與歸因不確定性的前提下製作內容或採取行動。

## 學習目標

學完本章後，你應該能夠：

1. 建立涵蓋產品、受眾、問題、替代方案、差異化、異議、客戶語言、語氣、證據與期望行動的產品脈絡。
2. 從決策出發倒推，得出最小而有用的事件、指標、分母、樣本、時間窗、命名方式與停止規則。
3. 識別行銷結論中的抽樣偏差、過度歸因、選擇性報告、隱私風險與不確定性。
4. 用行銷 Skill 設計一個成長實驗，而不暴露個人資料、繞過平台權限或自動發佈。

## 真實問題入口：身份、組織與資料都需要上下文

- **FP-03**：據報導，一名僅限企業（Enterprise）的使用者在 `github.com` 上被探查，儘管相關入口是一個 Enterprise 主機。這說明預設主機或預設受眾不能被當成使用者事實。
- **FP-04**：據報導，同一使用者可以存取兩個組織，而某個連接器被重複用於其中第一個組織。這說明帳號存取權限不等於獲得授權，可以把某個特定組織的資料拿來做指定實驗。

這些是實地研究的使用者報告，不是官方確認，也不是本機重現。本章用它們來練習區分身分、組織、安裝範圍與允許的資料用途。它們不是連接器行為的普遍結論。

## 核心概念與決策

### 1. 產品脈絡是共享、而且有版本的資產

產品脈絡比一次性的 prompt 更有用，因為它讓假設可見、可複核。至少應記錄：

```text
產品與版本；明確的非目標：
目標受眾與排除的受眾：
核心問題與使用情境：
替代方案與轉換成本：
差異化主張與可用證據：
常見異議與匿名化的客戶語言：
品牌語氣、禁用表述與合規邊界：
期望行動與該行動的前提條件：
通路、地區、語言與時間範圍：
版本、變更原因、負責人與複核日期：
```

### 合成產品脈絡：訓練用 fixture，不是客戶紀錄

本章的練習使用一個**合成產品脈絡**。它是為練習而虛構的，不描述任何真實公司、客戶、庫存狀況、受眾規模、價格、轉換率、客戶見證或活動結果。

```yaml
context_id: synthetic-product-context-v1
product: "面向小型專案團隊的本機規劃工作區"
audience: "透過共享任務清單協調小型專案的人"
non_goals: ["不宣稱市場份額", "不宣稱客戶成果"]
problem: "團隊在會議與任務更新之間丟失了決策的脈絡"
alternative: "共享文件加上手動提醒"
proof: "沒有提供客戶證據；產品主張仍屬假設"
objections: ["設定成本", "資料存取", "又要多維護一個工具"]
desired_action: "檢視本機範例工作區"
data_boundary: "僅合成紀錄；不含姓名、電子郵件地址、IP 位址或外部 ID"
status: candidate
```

這個 fixture 的意義在於演示上下文欄位與證據邊界。它並不是允許編造證據。沒有證據的主張必須保持為假設、被弱化，或被刪除。

### 2. 為決策而測量

先寫出決定，再選擇資料：

```text
要做的決定：
關鍵假設：
必須回答的最小問題：
指標定義與事件名稱：
分母、樣本、時間窗與分群：
去重、缺失資料與延遲處理：
同意、隱私、保留期與訪問控制：
停止規則與下一步行動：
```

「變體 B 的點選率更高」這句話，在沒有說明曝光條件、分母、去重規則、人群、時間窗與下一步行動之前，是不可複核的。不要把完整的電子郵件地址、完整的 IP 位址、聊天紀錄或跨站識別碼設為預設輸入。應優先使用彙總、去識別化、短保留期的測試資料。

### 3. Agent 輔助判斷，但不擁有歸因

Agent 可以整理產品脈絡、起草變體、檢查事件名稱、計算描述性統計並建議下一個實驗。但它不能從文案差異中推斷因果，不能在圖表中掩蓋樣本偏差，也不能在沒有單獨授權、可複核的動作下發佈到廣告平台、CRM、電子郵件系統或社群通路。外部寫入需要測試帳號或 sandbox、人工批准、批次識別碼以及回滾或撤回路徑。

### 4. 用能力分組代替工具目錄

按候選 Skill 所支援的決定分組：

| 能力分組 | 典型輸出 | 需記錄的邊界 |
|---|---|---|
| 產品脈絡 | 有版本的脈絡與主張帳本 | 事實、假設、負責人、複核日期 |
| 內容與定位 | 繫結受眾與異議的變體 | 證據、語氣、禁用主張 |
| 轉換實驗 | 假設、曝光規則與停止規則 | 樣本、分母、同意、時間窗 |
| 分發與成長 | 草稿或 sandbox 批次 | 通路範圍、批准、回滾 |
| 測量與歸因 | 彙總報告與限制 | 事件結構、資料品質、因果邊界 |

## 具體證據表

| 證據項 | 具體產物 | 支援什麼 | 不支援什麼 |
|---|---|---|---|
| 產品脈絡 | 帶變更原因與負責人的 `synthetic-product-context-v1` | 練習使用了哪些主張與受眾 | 產品有真實客戶或成果 |
| 主張帳本 | 標記為 `fact`、`hypothesis`、`unverified` 或 `not applicable` 的行 | 某句話是否有明確的證據狀態 | 對標記為 `unverified` 的主張的證明 |
| 測量計畫 | 指標定義、分母、時間窗、樣本規則、停止規則 | 擬議的測量是否可重現 | 僅憑自身即為統計顯著性或因果 |
| 資料字典 | 彙總欄位、保留期、存取範圍、缺失資料規則 | 哪些資料進入了分析 | 收集更多個人資料的許可 |
| 變體記錄 | 輸入、輸出文字、審閱者與版本 | 實際比較了什麼 | 某個變體導致了某個結果 |
| 分發記錄 | sandbox 或草稿狀態、批次 ID、批准、回滾路徑 | 是否準備了受控動作 | 有任何內容被公開傳送 |

## 可觀察的小實驗：針對同一合成產品的兩次請求

### 準備

使用上面的合成產品脈絡。準備一份脫敏的產品描述、三個合成的異議、沒有客戶見證、沒有庫存、沒有業績數字。建立一個只含計數的本機彙總表。表中不能包含姓名、電子郵件地址、完整的 IP 位址、裝置識別碼或跨平台 ID。選擇一個短時間窗和兩個內容變體，但不要宣稱其中任何一個變體已經執行過。

### 任務

1. 向 Agent 發出請求 A：「為這個產品寫一段精煉的介紹。」儲存輸出。
2. 向 Agent 發出請求 B，附上帶版本管理的上下文、受眾、異議、缺失的證據、期望行動與測量計劃。要求給出兩個變體、假設、主要指標、分母、樣本限制與下一個決定。
3. 從具體性、受眾契合度、證據狀態與可行動性幾個方面比較 A 和 B。標出每一個沒有證據支援的主張。
4. 請 Agent 檢查事件名稱、去重、缺失值、時間窗與隱私邊界。不要上傳資料，也不要呼叫真實渠道。
5. 如果使用匯總樣本資料，只能將其報告為描述性 fixture。當樣本不足時，不要把差異說成因果，也不要宣佈贏家。

### 證據

保留兩個請求、上下文版本、生成的變體、假設表、指標定義、分母與樣本說明、去標識化的資料字典、隱私決定、資料質量檢查與下一決定記錄。每一句話都應能識別為產品事實、營銷假設或未驗證的主張。

### 失敗變體

提供一個模擬通路，其預設主機是 `github.com`，儘管練習只授權了 Enterprise 主機。然後提供來自兩個組織的彙總資料，卻只授權其中一個。檢查 Agent 是否把預設主機或現有帳號存取當成充分條件。正確的行為是暫停，確認主機、組織與授權範圍，並使用最小被允許的資料或合成資料。接著，提供一份很小但表面差異很大的樣本，檢查 Agent 是否說明了樣本限制與結果的觀察性質。

### 反思

- 哪些欄位讓請求 B 比請求 A 更具體？
- 哪個指標會真正改變下一個決定？
- 哪些欄位可以在不丟失答案的前提下被彙總或刪除？
- FP-03 和 FP-04 如何改變你對主機、組織、受眾與資料存取的假設？

## 失敗與邊界情形

- **編造證據或客戶語言：**沒有依據的客戶見證、客戶數字或「市場領導者」式的主張，必須變成假設或被刪除。
- **把小樣本宣佈為贏家：**記錄樣本量、分母、時間窗、分群與缺失資料。如果證據不足以支撐穩定的判斷，就報告方向性訊號或繼續收集。
- **平台權限不匹配：**把主機、組織、安裝範圍與實驗授權做成預檢。快取的連接器或預設帳號並不等於目前已獲批准。
- **隱私越界：**不要把個人資訊、敏感屬性、私人對話、未同意聯絡人或跨情境識別碼設為預設。使用最小化、彙總、存取控制與保留期限制。
- **沒有復原路徑的發佈：**電子郵件傳送、廣告修改、CRM 寫入、社群發佈與追蹤變更，都需要草稿或 sandbox 檢查、人工批准、批次識別碼以及撤回或回滾方法。
- **漂亮的圖表掩蓋薄弱資料：**檢查重複事件、時區、延遲、機器人、分母漂移、缺失值與通路選擇。圖表本身不是證據。

## 遷移練習

選擇一個真實的行銷決策，但只使用脫敏或彙總的資料：

1. 寫一頁產品脈絡，並標出事實、假設與需要證據的主張。
2. 選擇一個可能改變的決策，設計最小的測量計畫與停止規則。
3. 對每個欄位，記錄其隱私理由、存取範圍、保留期限與刪除方法。
4. 設計一個 sandbox 實驗與一個失敗變體，用來測試主機、組織與發佈授權。

## 驗收清單

- [ ] 我有一個有版本的產品脈絡，包含負責人、變更原因與複核日期。
- [ ] 我能區分產品事實、行銷假設、客戶證據與未驗證的主張。
- [ ] 我能從一個決定推匯出最小有用的指標、分母、樣本、時間窗與停止規則。
- [ ] 我在相關處檢查了重複、缺失資料、延遲、時區、機器人流量與選擇偏差。
- [ ] 我沒有把相關性變成因果，也沒有從小樣本宣佈穩定的贏家。
- [ ] 我使用了最小化與去識別化或彙總、存取控制與保留期限制。
- [ ] 針對 FP-03 或 FP-04，我能解釋主機、組織、聯結器與實驗授權之間的區別。
- [ ] 沒有批准、sandbox 證據與復原路徑，我不會向外部平台發佈或寫入。
- [ ] 我能為練習中的每一條實質性主張指出具體的證據產物。

- **易變的平台與隱私事實：**使用適用平台的官方開發者文件與隱私文件、組織政策與目前的設定。在實驗紀錄中記下 URL、查閱日期、地區、資料負責人與保留政策。
