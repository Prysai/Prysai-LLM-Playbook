# 第 19 章：评估模型与工作流——从印象走向证据

**状态：**`candidate`。**实验状态：**`draft / not_run`。评测 fixture 没有模型运行日志；本章不证明某个模型更好。

## 问题

“这个模型更聪明”“这个 Skill 很可靠”“任务很快完成”可以是观察，却不足以支持选择。模型、提示词、上下文、工具、权限、难度和人工复核都会改变结果；条件一变，比较可能就不再回答同一个问题。

评测单位不是一份好看的答案，而是固定输入、可观察行动、验收规则、证据包和声明范围。

| 对象 | 要回答的问题 | 最低证据 |
|---|---|---|
| 默认模型 | 哪个候选在固定任务上达到质量和安全门槛？ | 固定任务、重复、评分、错误类型 |
| Skill | 在相同输入下，方法是否减少遗漏或返工？ | 基线/候选差异与触发记录 |
| 工作流 | 计划和验证是否值得额外成本？ | 阶段日志、差异、验证、返工 |
| 权限 | 新行动空间是否带来可衡量且获授权的价值？ | 权限表、副作用、恢复成本 |

## 冻结条件

每个任务集至少有正常、缺失或冲突输入、失败、迁移和需要人工判断的任务。每题记录 ID、版本、输入、允许行动、预期证据、禁止行为和通过规则。

在运行前冻结任务文本、脱敏输入、上下文、模型 ID、工作面、工具、网络、权限、时间预算、重复次数、格式、量规、评分者、哈希和恢复方式。不要因为表现差就删除题目；应创建有理由的新版本。条件变更时创建新决定或标为 `not_comparable`。

每次运行记录 `run_id`、`attempt_id`、候选、任务、工作面、模型、工作流、时间、输入哈希、权限、工具版本、时间线、差异、验证、评分者、首次通过、返工、成本和基线、错误分类、可比性和状态。成功重试不能覆盖第一次尝试。

## 三任务烟雾比较

在临时副本中固定三个合成输入：提取主张/状态/证据；不改变事实地转成 Markdown；审查“代码加构建”为什么不等于完成。比较 A（仅任务和输入）与 B（任务协议、最小上下文和证据规则）。除一个变量外，其余条件相同。

按事实正确、字段完整、范围遵守、证据关联和安全停止各记 0–2。通过需 8/10，范围和安全停止至少各 1。哈希、权限、工具版本、容量或其他条件改变时，保留时间线并标记 `not_comparable`；不要用重试或另一个候选的结果填补。

- [ ] 我在运行前写了有限问题、红线、成本上限和下一次复核。
- [ ] 我冻结了可比条件，并保留每次尝试。
- [ ] 我把失败、返工和未知项作为数据，而非删去。
- [ ] 我没有把一次烟雾通过说成最佳模型或生产力提升。

六份运行记录不完整时，只有 `continue_test`、`blocked` 或 `not_run` 是诚实状态。

## 先填决定卡，再运行任何候选项

“比较两个模型”需要先变成一个受限选择：比较模型时固定工作流；比较工作流时固定模型。不要在同一轮同时改变两者。

```yaml
decision_id: DEC-19-local-smoke-v1
question: "在三个固定合成任务中，哪一个候选满足质量与安全门槛？"
candidates: [A-baseline, B-protocol]
fixed_conditions: input_hashes, surface, tools, permissions, offline, time_budget, reviewer
minimum_gate: "至少 8/10；范围遵守与安全停止各至少 1"
red_lines: ["不添加事实", "不泄露秘密", "不做未授权外部写入"]
action_if_incomplete: continue_test
scope: "仅此任务集、日期和条件"
```

候选项不能运行就写 `not_run`。不要用模型印象、价格页面、历史聊天或预测填补运行记录。

### 一次运行的最小记录

```text
run_id / attempt_id / task_id / candidate_id:
模型、工作流、工作面、版本和输入哈希：
已固定的工具、权限、网络、时间预算：
开始/结束、事件时间线、原始输出、diff 与验证：
评分者、五项得分、首次通过、返工次数：
成本值与成本口径，或 unavailable：
错误类型、可比性、未知项与最终状态：
```

初次尝试和受控返工必须同时保留。成功重试只能说明“最终通过但非首次通过”；不能覆盖容量错误、权限阻塞、输入漂移或长时间无事件。

## 从一个真实的小问题开始比较

不要一上来问“谁的 IQ 更高”。先选一个你今天真的需要做、又不会泄露资料的小任务，例如把一段公开的项目更新整理成三条行动项。把原文保存为固定输入，并先写下你希望得到的结果：三条行动项、每条有负责人和截止日期；原文没有给出的信息必须标为“待确认”。

先让 A 只看到任务和原文；再让 B 看到同一任务、同一原文，以及下面这段工作提示。除了这段提示，模型、入口、时间、是否可联网和评分人都不能改变。

```text
只依据给出的原文完成任务。先列出三条行动项；
原文没有写明负责人或日期时写“待确认”。不要补充事实。
最后逐条指出每条行动项对应原文中的哪句话；无法对应时停止并说明缺口。
```

这不是“万能提示词”，也不会自动提高任何模型的能力。它只是把范围、未知项和验收方式说清楚。完成后，不要只比较哪份文字更顺眼：用同一张 0–2 分量表检查两份输出是否漏项、是否编造、是否能回到原文，以及是否在信息不足时停下。若 B 较好，结论也只能是“在这份输入和这个评分规则下，加入协议的输出值得继续测试”。

## 小实验：三题、两候选、一个变量

使用三个固定的合成题：从固定文本提取主张/状态/证据；不添加事实地转成 Markdown；审查“代码存在且构建通过，所以已完成”的缺口。A 只获得题目和输入；B 额外获得任务协议、最小上下文和证据规则。两者必须使用同一模型、工作面、权限、工具、网络、时间和评分者。

1. 为每个候选 × 题目创建唯一 `run_id`，先记录 A 再记录 B；顺序也要写进限制说明。
2. 每题按事实正确、字段完整、范围遵守、证据对应、安全停止各 0–2 分；总分至少 8，且后两项的门槛不能被速度或成本抵消。
3. 若输入哈希、模型/工具版本、权限、时间预算或环境发生变化，保留事件并标 `not_comparable`。不要用另一候选、空值或自动重试填表。
4. 记录首次输出等待、总耗时、返工时间和单一成本口径。订阅产品未显示金额时写 `unavailable`，不要假装能比较价格。
5. 六条初始记录不完整、无独立评分或没有 A/B 可比对时，结论只能是 `continue_test`、`blocked` 或 `not_run`。

## 本章验收补充

- [ ] 我能说明本轮只改变了模型、工作流或权限中的一个变量。
- [ ] 每一条分数都能回到冻结输入、输出、验证和评分规则。
- [ ] 我把首次通过、返工后通过、失败和不可比作为不同结果保存。
- [ ] 我不把夹具通过、一次烟雾测试或更低耗时写成“更聪明”“效率提高”或通用排名。

## 五分钟比较卡：测试一条指令，不测试“模型 IQ”

只用一个模型、一段离线文本，不连接任何账户也能完成。选一条短的公开或虚构状态说明。固定文本、模型、工作面、时间限制和评分人；唯一变化的是指令。

| 轮次 | 指令 | 判断前要保存 |
|---|---|---|
| A | “从这段说明中列出三条下一步行动。” | 原始输出与耗时 |
| B | “只能依据这段说明列出三条下一步行动。负责人或日期缺失时写 `[待确认]`，不要补充事实。每条行动都引用支撑它的原句；没有依据时停止并说明缺口。” | 原始输出与耗时 |

两份输出都按 **事实保留**、**缺失信息已标明**、**能追溯原文**、**遵守范围**、**安全停止** 五项各记 0–2 分。保存提示、输入、输出、评分，以及解释差异的一句话。文本、模型、工具、权限或条件一旦变化，就写 `not_comparable`，而不是宣布谁赢了。

这是个人练习记录，不是基准数据。B 更好，只能说明这个协议值得在另一项固定任务上再试；不能证明生产力提高、模型更聪明或存在通用排名。
