# 사실을 꾸며내지 않는 업무 업데이트: 여섯 가지 연습 메시지

가상의 사실만 사용하세요. 짧은 업데이트를 점검하기 쉽게 만드는 텍스트 연습이며, 정확성·전문성·승인·실제 업무 적합성을 증명하지 않습니다. 개인정보, 고객 정보, 고용 정보, 재무 정보 또는 운영 환경 정보가 필요하면 멈추세요.

## 1. 독자와 사실 정하기
```text
가상의 업무 업데이트를 연습하고 싶습니다. 독자 한 명, 확인된 사실 세 개 이하, 미확인 사항이나 막힘 한 가지, 가능한 요청 한 가지를 차례로 물어보세요. 진척, 날짜, 원인, 승인, 약속을 만들어 내지 마세요. 짧은 사실 목록만 돌려주고 제 초안을 기다리세요.
```
## 2. 예시를 보기 전에 쓰기
```text
저장한 가상의 사실만 사용해 지정된 독자에게 보낼 60단어 이내의 업데이트를 제가 쓰게 해 주세요. 대신 작성하거나 다듬거나 제목을 추가하지 마세요. 제가 보낸 뒤에는 첫 시도를 그대로 보존하세요.
```
## 3. 중요한 빈틈 하나 찾기
```text
다음 기준으로 제 첫 시도를 비교하세요. 독자가 확인된 사실, 미확인 사항 또는 막힘, 요청을 찾을 수 있고 근거 없는 진척이나 약속이 없어야 합니다. 중요한 빈틈을 하나만 지적하고 해당 표현을 인용하세요. 사실만으로 판단할 수 없으면 “알 수 없음”이라고 하세요. 업데이트를 다시 쓰지 마세요.
```
## 4. 내 말로 고치기
```text
그 한 가지 빈틈에 대한 부분 힌트 하나만 주고 제 수정을 기다리세요. 제가 시도한 뒤 명시적으로 요청하지 않는 한 대체 업데이트를 쓰지 마세요. 첫 시도, 당신의 힌트, 제 수정을 분리해 보관하세요.
```
## 5. 독자 바꾸기
```text
가상의 사실은 완전히 같게 두고 동료용에서 관리자용으로 바꾸세요. 힌트 없이 새 업데이트를 쓰게 한 뒤, 어조·세부 사항·요청이 어떻게 달라졌는지 표시하세요. 미확인 사항을 사실로 바꾸거나 어느 버전이 승인되었다고 말하지 마세요.
```
## 6. 작은 기록 남기기
```text
연습 기록을 돌려주세요: 가상의 사실 | 첫 시도 | 힌트 하나 | 학습자 수정 | 독자를 바꾼 시도 | 확인할 추가 사항 | 미확인 사항. 마지막 상태는 template_selected, practised, not_run, blocked 중 정확히 하나만 쓰세요. 생산성, 글쓰기, 업무 준비도, 기억이 좋아졌다고 주장하지 마세요.
```

두 초안과 기록을 함께 보관하세요. 기록된 한 번의 순환은 연습일 뿐, 독립 평가나 모델 피드백의 정확성 증거가 아닙니다.
