# 証拠と用語の案内

このページは、証拠の境界を保ちながら学習ルートを読みやすくするためのものです。コースページは、保守担当者向けの英語の研究・ガバナンス記録へ直接送る代わりに、ここへ案内します。

これは証拠への案内であり、元の記録の代わりではありません。記録が支えられるのは明記された範囲だけで、学習効果、現在の製品挙動、モデル品質、一般的な安全性は証明しません。

<a id="core-terms"></a>

## 基本用語

**モデル**は出力を生成します。**ツール**は外部システムを観察または変更できます。**Skill** は入力、停止条件、確認を持つ再利用可能な方法です。**Agent** は観察可能な複数ステップのループです。**証拠**は他者が確認できる材料です。名前のあるプラットフォーム同士が自動的に同等になることはありません。

完全な用語記録の識別子は `CONTEXT.md` です。製品名、メニュー、既定値、料金、上限、権限は変わりやすい事実なので、使用前に日付付きの公式情報源が必要です。

<a id="source-notes"></a>

## ソースノート

| ラベル | 支えられること | 支えられないこと |
| --- | --- | --- |
| 公式ベースライン | 範囲内の日付付き製品事実 | 全アカウントや将来版への約束 |
| 公開フィールド報告 | 報告された問題や対処 | 確定した根本原因やローカル再現 |
| 固定フィクスチャ | 限定されたローカル契約 | モデル、学習者、本番の挙動 |
| プロジェクト手法 | 提案手順とその境界 | 独立した有効性や採用 |

技術的なソース識別子には `openai-codex-baseline.md`、`field-problems-codex.md`、`prompt-patterns-for-real-work-2026-08-10.md`、`llm-mechanism-deep-dive-2026-08-10.md` があります。これらは追加のコース章ではなく、証拠記録です。

<a id="method-and-status"></a>

## 方法と状態

持続するループは、タスク定義 → 必要な文脈の選択 → 行動境界の設定 → 最小の可逆操作 → 証拠確認 → 回復または引き継ぎ、です。緑のチェックはそのチェック自身の契約だけを検証します。

`draft` は教材または証拠が未完成、`candidate` は構造と基本確認があるが新しい十分な証拠がない状態です。`verified` と `production-ready` には技術リリース記録にある、より強い証拠が必要です。

## 情報源を使う手順

1. 必要な決定を書く。
2. ラベルと日付を読む。
3. 実際に使った事実、報告、不明点を記録する。
4. ライブのプラットフォーム観察や新しい権限が必要になったら止める。

記録後に章へ戻ります。一次情報源を再確認せず、古いノートを現在の製品事実へ昇格させないでください。
