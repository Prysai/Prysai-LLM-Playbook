# Universal LLM collaboration: one safe first task, then four foundations

**Status:** `candidate`. **Run status:** `not_run`.

Start here when you want to use an ordinary text chat but do not yet need a
product-specific setup. You can make the first attempt below in a chat surface
without treating ChatGPT, Claude, Grok, Gemini, Codex, or any other product as
the same product. This route teaches a small shared decision layer only: a
clear task, bounded material, a visible check, and a stop point. It does not
claim that platforms share tools, permissions, memory, accounts, prices, or
Agent behavior.

## Do one safe first task now

Use only the fictional notice below. Do not paste private messages, customer
material, credentials, unpublished work, or real files. Keep browsing, tool
use, uploads, account changes, and sending or publishing out of this attempt.

Copy this request into the text chat you chose:

```text
Result: rewrite this fictional club notice for new members.
Material: "The club meets Tuesday at 6. Bring a notebook. The room will be
confirmed later."
Response shape: write two sentences. Keep every stated fact. Put any missing
detail in [brackets]. Then list the facts you preserved.
Check: compare the source and rewrite. No new time, room, fee, contact, or
promise may appear.
Stop: do not browse, send, publish, or assume an unknown detail.
```

Then check three things yourself:

1. Can you point to every statement in the rewrite in the supplied notice?
2. Did the reply obey the two-sentence limit and show what it preserved?
3. Did it add a detail that should remain `[unknown]`?

If the answer to the last question is yes, remove the added detail or ask for
one correction. If the chat offers to search, send, publish, use a tool, or
requests more material than this small exercise needs, stop. A polished reply
is not proof that its facts are true or that the method works on every product.

This is a candidate exercise, not a universal prompt formula or a result
claim. It has no cross-model run, learner, or effectiveness evidence. For more
text-only starter cards, use the [Beginner Practice Pack](../communication-clinic-EN.md).

## Build the foundation from that first task

Once you have made one attempt, use the four units below to understand why the
small request had a result, material, check, and stop line. They become more
important when a task grows beyond a text-only exchange.

1. [Turn an intention into a task contract](../chapters/03-task-protocol-EN.md#core-task-contract) — define the result, relevant context, action boundary, acceptance, stop rule, and hand-off.
2. [Match claims to evidence and recover in bounded order](../chapters/09-verification-and-recovery-EN.md#core-evidence-recovery) — test the narrow claim and stop at the first unsupported layer.
3. [Plan one evidence-bearing slice](../chapters/10-planning-and-slicing-EN.md#core-evidence-bearing-slice) — choose the smallest outcome another person can inspect and continue.
4. [Separate capability, authorization, confirmation, and evidence](../chapters/13-action-boundaries-EN.md#core-action-boundary) — keep a possible action distinct from an allowed or verified action.

Named-product instructions belong in a platform adapter; domain exercises
belong in application routes.

## Practise one seam before choosing a platform

Open the [Universal Seam Fixture](../../examples/universal-seam-v1/README-EN.md):
four fictional records covering a latest-request mismatch, wrong target,
missing tool receipt, and changed structured value. For each, name what the
visible text fails to prove, choose the smallest safe check, and stop before a
live behavior needs an adapter.

![Four evidence seams: task identity, target identity, execution receipt, and structured round trip, each ending at a check or stop point.](../../assets/teaching/universal-seams-red-black.svg)

Its verifier checks only fixed fictional-record consistency:
`verified_in_fixture` is not a product run, `not_run` is not execution
evidence, and `inferred` needs an adapter before live diagnosis. It adds no
chapter, Lab, Skill, model evaluation, or compatibility claim.

## What this route proves

The map proves only canonical ownership, stable anchors, valid consumers,
acyclic dependencies, and compact projection. The fixture validator proves
only its data contract. Neither establishes platform behavior, learner or
transfer evidence, security results, or a live product run.
