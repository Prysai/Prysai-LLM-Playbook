# LLMプラットフォームの選び方：中核は共通、アダプターは一つずつ

**状態:** `candidate`. **実行状態:** `not_run`.

ChatGPT、Claude、Gemini、DeepSeek、Grok、Codexは、どれも会話で応答して
くれますが、同じ製品ではありません。このルートは
[Universal Core Foundationsルート](universal-core-foundations-JA.md)の
転用可能な中核を維持したまま、正直なアダプターを一度に一つずつ加えます：
各プラットフォームで実際に何が違うのか、今日すぐ安全に試せることは何か、
そしてプラットフォーム固有の主張を信頼する前に公式ソースで何を確認すべきか。

Playbookの主力実践トラックはCodexですが、この方法は一つのベンダーに
縛られません。以下に挙げる各プラットフォームは**候補アダプター
(candidate adapter)**です：普遍的な中核は適用されますが、プラットフォーム
固有の制御項目は、それぞれ日付入りの一次ソースが揃って初めて教材の事実に
なります。

## ルールゼロ：名前だけから同等性を推測しない

モデル名、ログイン、見慣れたボタンがあるだけでは、二つのプラットフォームが
ツール、権限、メモリ、アカウント、価格、データ管理、Agentの動作を共有して
いるとは証明されません。プラットフォームの主張を繰り返す前に、三つの質問を
してください：

1. **正確にはどの製品サーフェスか**（ウェブチャット、アプリ、CLI、IDE、API、エージェント）？
2. **どの一次ソースを、いつ確認したか**が、今日これを真実だと述べているか？
3. **主張が間違っていたら、何が目に見えて変わるか**？

三つすべてに答えられなければ、その主張は`unknown`のままにし、次の確認
時期を記録してください。このルールの背後にある維持方法は、
Platform Adapter Review Skillと
Platform Fact Watchを
参照してください。

## 一枚で分かるプラットフォームマップ

| プラットフォーム | 代表的なサーフェス | 中核と通常異なる点 | このページで安全な最初の一歩 |
|---|---|---|---|
| ChatGPT | ウェブチャット、アプリ、API | アカウントのスコープ、メモリ設定、ファイルアップロード、ブラウジング切り替え、共有リンク | [ChatGPTの最初のタスク](#chatgpt-first-task) |
| Claude / Claude Code | ウェブチャット、CLIエージェント、IDE | ターミナル＋ファイルエージェント、権限プロンプト、CLAUDE.mdプロジェクトメモリ | [Claude Codeの最初のタスク](#claude-code-first-task) |
| Gemini | ウェブチャット、アプリ、API | Googleアカウントのスコープ、Google Workspace連携、アプリ拡張 | [Geminiの最初のタスク](#gemini-first-task) |
| DeepSeek | ウェブチャット、アプリ、API | モデルの選択肢とコンテキストウィンドウはリリースごとに異なる；公式モデルページで確認 | [DeepSeekの最初のタスク](#deepseek-first-task) |
| Grok | ウェブチャット、アプリ | Xアカウント連携、リアルタイム投稿へのアクセス、モデルリリースのペース | [Grokの最初のタスク](#grok-first-task) |
| Codex | デスクトップ、CLI、IDE、クラウド、API | Playbookの主力トラック：ファイル、ツール、Skills、Agents、権限 | [Codexパス](../routes/first-safe-change-JA.md) |

この表は方向づけであり、同等性の証明ではありません。どの行も、レッスンが
依存する前に、それぞれ最新のソースが必要です。サーフェスの利用可否、価格、
権限のデフォルトは頻繁に変わるため、変動しやすい事実として扱ってください。

## どのプラットフォームでも安全な最初のタスク

選んだプラットフォームにこの依頼をコピーしてください。架空の素材を使い、
ツールを使わず、アカウントデータも必要ありません。同じタスクがどこでも
機能する——それがまさに中核の要点です。

```text
結果：この架空のクラブの案内文を、新入会員向けに書き直してください。
素材：「クラブは火曜日の6時に集まります。ノートを持参してください。部屋は
後で確認されます。」
応答形式：文を二つ書いてください。記載されている事実はすべて保持して
ください。不明な詳細は[brackets]に入れてください。その後、保持した事実を
列挙してください。
確認：元の文と書き直しを比較してください。新しい時間、部屋、会費、連絡先、
約束が登場してはいけません。
停止：ブラウジング、送信、公開、未知の詳細の推測をしないでください。
```

次に、以下の三つを自分で確認してください：

1. 書き直しのすべての文を、提示された案内文の中に指し示せるか？
2. 回答が二文という制限を守り、保持した内容を示したか？
3. `[unknown]`のままにすべき詳細を追加しなかったか？

チャットが検索、送信、公開、ツールの使用を提案したり、この小さな演習に
必要な以上の素材を要求したりしたら、停止してください。プラットフォームが
それらの動作を実行できたとしても、能力があることはそれを使う指示では
ありません。

## ChatGPTの最初のタスク

任意のChatGPTサーフェスを開き、上記の安全な最初のタスクを実行して
ください。その後、実際に観察できるプラットフォームの違いを一つ記録します：
回答がブラウジング、メモリ、共有リンクに言及しましたか？推測したことでは
なく、見たことを記録してください。ChatGPTの主張をソースに基づいて確認
するには、製品事実の所有者として公式OpenAIヘルプページを使う
Source Investigator Skillを
利用してください。

## Claude Codeの最初のタスク

Claude Codeはターミナルエージェントです：起動したプロジェクト内のファイル
を読み取り、編集できます。何かを実行する前に、使い捨てフォルダを作成し、
そこで安全な最初のタスクを実行してください。権限プロンプトに注目します：
ファイルの編集やコマンドの実行の前に確認を求めますか？そのプロンプトこそが
チャットとエージェントの違いであり、選択の分岐点でもあります。プロジェクト
メモリについて、Claude Codeは`CLAUDE.md`ファイルを読み取ります。そこに
書かれたものはすべてモデルが従う可能性のある指示なので、プロジェクトの
ルールと同様にレビューしてください。資格情報、本番データ、破壊的なコマンド
がある実際のリポジトリでは、[First Safe Changeルート](first-safe-change-JA.md)の
規律を完了するまでClaude Codeを起動しないでください。

## Geminiの最初のタスク

Geminiのチャットサーフェスで安全な最初のタスクを実行してください。どの
アカウントスコープが有効か、アプリ拡張（Google Workspace、YouTube、
Maps）がUIに表示されるかを記録します。拡張は外部への影響を伴います：
あなたの代わりに読み書きできるため、拡張に関するGeminiのレッスンは中核
トピックではなく、プラットフォームアダプターのトピックです。テキストのみの
練習タスクのために拡張を有効にしないでください。

## DeepSeekの最初のタスク

DeepSeekのチャットまたはアプリサーフェスで安全な最初のタスクを実行して
ください。モデルの命名、コンテキストウィンドウ、利用可否はリリースごとに
変わり、公式モデルページがそれらの事実の所有者です。実際に使用したモデル名
と日付を記録し、実行が再現可能な状態を保ってください。APIキー、非公開
コード、社内文書をウェブチャットに貼り付けないでください。

## Grokの最初のタスク

Grokのチャットサーフェスで安全な最初のタスクを実行してください。アカウント
がXにリンクされている場合、投稿やリアルタイムコンテンツが会話のスコープに
入り得ることに注意してください。それはプラットフォームの違いであり、
同時にプライバシーの判断でもあります。ソーシャルグラフに届き得る会話に、
非公開メッセージや下書きを貼り付けないでください。現在の投稿を引用する
Grokの回答は、プラットフォームの検索（retrieval）動作に関する主張です。
繰り返す前に、公式のX/Grokヘルプページで照合してください。

## Codexの最初のタスク

Codexは、コンテキスト、ツール、権限、Skills、Agents、検証という完全な
ループを公開しているため、Playbookの主力トラックです。使い捨てプロジェクト
で[First Safe Changeルート](first-safe-change-JA.md)と
[Lab 001](../labs/lab-001-first-safe-task-JA.md)から始めてください。
編集前検査（inspect-before-edit）の習慣が身につくまでは、クラウド
サーフェスや実際のリポジトリに飛びつかないでください。

## 最初のタスクの後：どのトラックを選ぶべきか

- テキストのみの入門練習が欲しい場合：[Beginner Practice Pack](../communication-clinic-JA.md)。
- ファイルとツールを使う本格的な主力トラックが欲しい場合：[First Safe Change](first-safe-change-JA.md)。
- まずプラットフォーム中立の土台を固めたい場合：[Universal Core Foundations](universal-core-foundations-JA.md)。
- 二つのプラットフォームを公平に比較したい場合：LLM Comparison Protocol。
- プラットフォームのレッスンをカリキュラムに含めるべきか判断したい場合：Platform Adapter Review。

## 証拠の状態と境界

このルートは`candidate / not_run`です：構造とチェック項目は存在しますが、
学習者の実行、プラットフォーム間の実行、独立レビューの記録はありません。
上記のプラットフォーム別の説明は、一次ドキュメントと日付入りの調査レシート
（cross-LLM beginner prompting source receipt、
platform teaching boundary card）から
導出された方向づけです。これは、あるプラットフォームが他と同一に動作する
こと、タスクがどこでも成功すること、製品機能が同等であることの証拠では
ありません。プラットフォーム固有のコマンド、権限、価格、利用可否は変動し
やすい事実です：依存する前に、アクセス日付を添えて公式ソースを確認して
ください。

- [ ] 私は架空の、公開された、または許可されたテキストのみを使用した。
- [ ] 私は実行時の正確なサーフェス、見える場合はモデル名、日付を記録した。
- [ ] 私は一方のプラットフォームの動作を他方のプラットフォームの証明として扱わなかった。
- [ ] 私は秘密、非公開メッセージ、未公開ファイルを貼り付けなかった。
- [ ] ツール、ブラウジング、アップロード、送信、公開が提示されたとき、私は停止した。
