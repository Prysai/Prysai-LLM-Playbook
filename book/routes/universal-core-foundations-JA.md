# 汎用 LLM 協働：安全な最初の一歩と四つの基礎

**状態：**`candidate`。**実行状態：**`not_run`。

ふだんのテキストチャットを使いたいが、まだ特定製品向けの設定は必要ないときは、ここから始めてください。下の最初の試行は、ChatGPT、Claude、Grok、Gemini、Codex などを同じ製品だと見なさずに行えます。このルートで扱う共通部分は小さな判断層だけです。課題を明確にし、材料を限定し、確認方法と停止点を見える形にします。各プラットフォームでツール、権限、記憶、アカウント、料金、Agent の振る舞いが同じだとは主張しません。

## いま安全な最初の課題を一つ行う

下の架空の案内だけを使ってください。私的なメッセージ、顧客資料、認証情報、未公開の作業、実際のファイルは貼り付けません。この試行では、ブラウズ、ツール、アップロード、アカウント変更、送信、公開を行いません。

次の依頼を選んだテキストチャットにコピーします。

```text
目的：この架空のクラブ案内を新しい会員向けに書き直す。
材料：「クラブは火曜日の6時に集まります。ノートを持参してください。部屋は後で確定します。」
回答形式：二文で書く。書かれている事実はすべて残す。不足している詳細は [角括弧] に入れる。その後、残した事実を列挙する。
確認：元の案内と書き直しを比べる。新しい時刻、部屋、料金、連絡先、約束を加えない。
停止：ブラウズ、送信、公開、未知の詳細の推測をしない。
```

次の三点を自分で確認します。

1. 書き直しの各記述について、元の案内で根拠を示せますか。
2. 二文という制限を守り、残した事実を示していますか。
3. 未知のままにすべき詳細を事実として足していませんか。

最後の答えが「はい」なら、追加された詳細を削除するか、その一点だけの修正を求めてください。チャットが検索、送信、公開、ツール使用を提案したり、この小さな練習に不要な追加資料を求めたりしたら、止まります。読みやすい回答は、その事実が正しいことや、この方法がすべての製品で有効であることの証明ではありません。

これは候補段階の練習であり、万能のプロンプト形式や成果の主張ではありません。モデル間の実行、学習者、効果についての証拠はありません。

## スペイン語を一文だけ練習したい場合

最初の課題の後なら、次の架空の書き取り練習を試せます。実在の相手へ送ったり、
語学レベルの証明に使ったりしないでください。

```text
駅でスペイン語の切符を一枚頼むための、一文だけの書き取りを練習したいです。
今使える語は [hola, por favor, un billete, para, gracias] だけです。

あなたは窓口係として待ち、私が一文を書く前に模範解答を出さないでください。
私が書いた後は、次だけをしてください。
1. 「通じる」または「見直す必要がある」だけを示す。
2. 理解に最も影響する変更を一つだけ示す。
3. その理由を日本語で説明する。
4. 私自身の書き直しを待つ。

レベル判定や流暢さの主張をせず、確認せずに新しい単語を足さないでください。
```

最初の一文、一つの指摘、自分の書き直しを残します。これは書かれた一回の試行を
残すだけであり、学習、発音、会話、保持、転移を示すものではありません。

## 最初の課題から四つの基礎へ

一度試した後で、次の四単位を使い、小さな依頼にも目的、材料、確認、停止行があった理由を理解します。課題がテキストだけのやり取りを超えると、これらの判断はさらに重要になります。

1. **意図をタスク契約に変える**――成果、関連する文脈、行動境界、受け入れ条件、停止規則、引き継ぎを定めます。
2. **主張を証拠に対応させ、境界内で復旧する**――狭い主張から確認し、裏付けのない最初の層で止まります。
3. **証拠が残る一つの小さな切片を計画する**――他者が点検でき、続きも進められる最小の成果を選びます。
4. **能力、許可、確認、証拠を分ける**――可能であること、許可されていること、実行済み・検証済みであることを混同しません。

固有製品の操作はプラットフォーム・アダプターへ、分野ごとの練習はアプリケーション・ルートへ置きます。

## プラットフォームを選ぶ前に、一つの接続点を練習する

このルートに対応する練習には、最新要求の不一致、誤った対象、ツール受領書の欠落、構造化値の変更を扱う四つの架空記録があります。各記録について、見えている文章が何を証明できないかを挙げ、最小で安全な確認を選びます。実際の挙動にアダプターが必要になった時点で止めてください。日本語版の練習が完成するまでは、ここから英語ページへ移動させません。

![四つの証拠の接続点：タスクの同一性、対象の同一性、実行受領書、構造化された往復。それぞれ確認または停止で終わる。](../../assets/teaching/universal-seams-red-black.svg)

検証器が確認するのは固定された架空記録の整合性だけです。`verified_in_fixture` は製品の実行を意味せず、`not_run` は実行証拠ではありません。`inferred` から実際の診断へ進むにはアダプターが必要です。この練習によって章、Lab、Skill、モデル評価、互換性の主張が追加されることはありません。

## このルートが証明すること

この地図が示すのは、正規の担当、安定したアンカー、有効な参照元、循環しない依存関係、簡潔な投影だけです。練習の検証器もデータ契約だけを確認します。どちらもプラットフォームの挙動、学習者や転移の証拠、安全結果、実際の製品実行を示すものではありません。
