# 汎用 LLM 協働の最初の四単位

**状態：**`candidate`。**実行状態：**`not_run`。

モデルや製品が変わっても、課題を明確にし、行動の範囲を限定し、他者が確認できる証拠と復旧計画を残す必要があります。そのための四つの安定した学習単位と、一つのオフライン接続確認をここにまとめました。これは完全な汎用カリキュラムではなく、各プラットフォームのツール、権限、記憶、Agent の振る舞いが同じだと主張するものでもありません。

1. **意図をタスク契約に変える**――成果、関連する文脈、行動境界、受け入れ条件、停止規則、引き継ぎを定めます。
2. **主張を証拠に対応させ、境界内で復旧する**――狭い主張から確認し、裏付けのない最初の層で止まります。
3. **証拠が残る一つの小さな切片を計画する**――他者が点検でき、続きも進められる最小の成果を選びます。
4. **能力、許可、確認、証拠を分ける**――可能であること、許可されていること、実行済み・検証済みであることを混同しません。

固有製品の操作はプラットフォーム・アダプターへ、分野ごとの練習はアプリケーション・ルートへ置きます。

## プラットフォームを選ぶ前に、一つの接続点を練習する

このルートに対応する練習には、最新要求の不一致、誤った対象、ツール受領書の欠落、構造化値の変更を扱う四つの架空記録があります。各記録について、見えている文章が何を証明できないかを挙げ、最小で安全な確認を選びます。実際の挙動にアダプターが必要になった時点で止めてください。日本語版の練習が完成するまでは、ここから英語ページへ移動させません。

![四つの証拠の接続点：タスクの同一性、対象の同一性、実行受領書、構造化された往復。それぞれ確認または停止で終わる。](../../assets/teaching/universal-seams-red-black.svg)

検証器が確認するのは固定された架空記録の整合性だけです。`verified_in_fixture` は製品の実行を意味せず、`not_run` は実行証拠ではありません。`inferred` から実際の診断へ進むにはアダプターが必要です。この練習によって章、Lab、Skill、モデル評価、互換性の主張が追加されることはありません。

## このルートが証明すること

この地図が示すのは、正規の担当、安定したアンカー、有効な参照元、循環しない依存関係、簡潔な投影だけです。練習の検証器もデータ契約だけを確認します。どちらもプラットフォームの挙動、学習者や転移の証拠、安全結果、実際の製品実行を示すものではありません。
