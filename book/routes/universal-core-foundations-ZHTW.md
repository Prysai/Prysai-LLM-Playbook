# 通用 LLM 協作：先做一個安全小任務，再學四個基礎單元

狀態：`candidate`。執行狀態：`not_run`。

如果你只是想先在普通聊天框裡把一件小事做好，不需要先選定某個平臺。下面的第一次練習可以在文字聊天中完成；它不把 ChatGPT、Claude、Grok、Gemini、Codex 或其他產品說成同一種產品。這條路線只教一個共同的決策層：把任務講清楚、只給必要材料、寫出檢查方式和停止點。它不表示各個平臺共享工具、許可權、記憶、賬號、價格或 Agent 行為。

## 現在就做一個安全小任務

只使用下面的虛構通知。不要貼上私人聊天、客戶資料、密碼或令牌、未公開內容或真實檔案。這次練習不需要瀏覽、工具、上傳、賬號變更、傳送或釋出。

把下面這段話複製到你選擇的文字聊天框：

```text
目標：把這則虛構社團通知改寫給新成員看。
材料：“社團每週二 6 點見面。請帶一本筆記本。房間稍後確認。”
輸出形式：寫兩句話。保留所有已經說明的事實；缺失的細節用 [方括號] 標出。然後列出你保留了哪些事實。
檢查：把原文和改寫並排比較。不得新增時間、房間、費用、聯絡人或承諾。
停止：不要瀏覽、傳送、釋出，也不要猜測未知細節。
```

然後自己檢查三件事：

1. 改寫裡的每一句話，能不能在原通知中找到依據？
2. 它是否遵守了“兩句話”和“列出保留事實”這兩個要求？
3. 它有沒有把本該未知的細節寫成事實？

如果第三項的答案是“有”，就刪掉新增細節，或只要求它改正這一處。如果聊天工具主動提出搜尋、傳送、釋出、呼叫工具，或要求更多材料，先停止。這段回答寫得通順，不等於其中的事實正確，也不等於這種方法已經在每個平臺上有效。

這是一個候選練習，不是萬能提示詞，也不是效果結論。它沒有跨模型執行、學習者或效果證據。還想練更多文字聊天起步卡，請讀[新手提示卡：把話說清](../communication-clinic-ZHTW.md)。

## 再用四個基礎單元理解剛才的練習

完成一次嘗試後，再看下面四個單元：為什麼小任務也要有目標、材料、檢查和停止線。任務一旦不再是純文字交流，這四個判斷會更重要。

1. [**把一個想法寫成任務契約**](../chapters/03-task-protocol-ZHTW.md#core-task-contract)——寫明結果、相關背景、行動邊界、驗收、停止規則和交接方式。
2. [**讓主張對應證據，並按邊界恢復**](../chapters/09-verification-and-recovery-ZHTW.md#core-evidence-recovery)——只驗證眼前這個小主張；遇到第一層證據不足就停下來。
3. [**規劃一個帶證據的最小切片**](../chapters/10-planning-and-slicing-ZHTW.md#core-evidence-bearing-slice)——選擇別人能檢查、也能繼續完成的最小結果。
4. [**分清能力、授權、確認與證據**](../chapters/13-action-boundaries-ZHTW.md#core-action-boundary)——能做，不等於被允許做，更不等於已經做成或已經驗證。

涉及特定產品的操作請放進對應的平臺介面卡；具體領域練習請放進應用路線。

## 先練一個“銜接點”，再選平臺

本路線配套的[通用銜接點固定練習](../../examples/universal-seam-v1/README-ZHTW.md)包含四條虛構記錄，分別對應“最新請求不一致”“目標錯誤”“缺少工具回執”和“結構化值被改動”。對每條記錄，先指出現有文字沒能證明什麼，再選擇最小且安全的檢查；一旦需要真實平臺行為，就先停下，等待介面卡說明。練習說明會保持在中文路徑；固定資料本身仍是共享的、虛構的材料。

![四個證據銜接點：任務身份、目標身份、執行回執與結構化往返；每一項都以檢查或停止為終點。](../../assets/teaching/universal-seams-red-black.svg)

該練習的驗證器只檢查固定虛構記錄是否自洽：`verified_in_fixture` 不等於產品實際執行，`not_run` 不等於已有執行證據；要從 `inferred` 走向真實診斷，仍需要平臺介面卡。它不會新增章節、實驗、Skill、模型評測或相容性主張。
