# Lab 017: Skill を採用する前に発見経路を監査する

## 問題

Skillはディスクに存在しても暗黙リストにないことがあり、明示名で解決してもロードで失敗することがあります。これらは別の観測です。ディレクトリ一覧や一回のsmoke testを採用判断にしてはいけません。

## 準備

revisionを固定して匿名化した二つの見本を、一時ディレクトリに置きます。一方
には追跡可能なライセンスと入力範囲の制限があり、もう一方には明確なライセンス、
依存関係の一覧、復旧先がありません。どちらも導入せず、認証情報も外部書き込みも
使いません。

テスト前に、候補ごとに次を残します。

| 項目 | 残す情報 |
|---|---|
| 身元 | 名前、正確なrevision、パス、ハッシュ |
| 出所 | URL、作成者または責任者、確認日、対象範囲 |
| ライセンス | ライセンスファイル、NOTICE、ネストした資産、未確認点 |
| 依存関係 | バージョン、ネットワーク、アカウント、要求される認証情報 |
| 対象 | 想定する導入先のルート、利用者、責任者 |
| 撤去 | バックアップ、復旧方法、削除の許可、次回確認日 |

## タスク

次の段階を別々に記録します。`not_observed` は十分な観測がないという意味で、
「おそらく該当する」という意味ではありません。

```text
ファイルがある:
暗黙発見:
明示名解決:
新しいセッションでロード:
正例の挙動:
境界の挙動:
失敗/注入の挙動:
プロジェクト間移行:
採用判断: recommendation-only | blocked | approved-to-install | installed-candidate
```

revision、ライセンス、NOTICE、ネストした資産、依存関係、ネットワーク／アカウント
要件、導入範囲、バックアップ、復旧方法、所有者、次回確認日も確認します。

## 4つのケース

何かを実行する前に、次の四つのケースを設計します。

1. **正例：** 通常の入力、ローカルに限定した範囲、期待する出力。
2. **境界：** 入力不足、範囲外のリソース、権限不足。
3. **失敗／注入：** 外部からの指示、認証情報の要求、想定外のペイロード。
4. **移行：** 別のディレクトリやプロジェクトで、revision・依存関係・復旧方法を保持。

各ケースに前提条件、読み取り操作、期待するシグナル、証拠、状態、停止条件を
書きます。ディレクトリ一覧が証明するのは、一覧に載っているという事実だけです。

## 証拠

目録、revision、読み取り専用の発見結果、ライセンスと依存関係のレビュー、四つの
ケース、判断パッケージ、撤去計画を保存します。判断パッケージでは、導入なしの
推奨、blocked、条件付き導入承認、導入済み候補を区別し、対象範囲、所有者、
バックアップ、復旧方法、次回確認日を記録します。

## 意図的な失敗と境界

候補に実際の `.env` ファイル、認証、アップロードを要求させます。正しい結果は
`blocked` です。要求はデータとして保存し、認証情報を公開せず、「動かしてみる」
ために候補を導入せず、足りない証拠を記録します。カタログ、形式の検証、見えている
ライセンスだけでは、安全な挙動、実際のトリガー、ネスト資産の利用権を証明できません。

ローカルテストを実行できない場合は `not_run` と書き、結果を推測しません。revision
が変わったら、ライセンス、依存関係、四つのケースを最初から見直します。判断は記録
したrevisionにだけ適用されます。

## 振り返り

カタログが証明できなかった段階はどこですか。導入前に必要な観測は何ですか。撤去
コストや依存関係に残っている未知は何ですか。

## 転移

同じ手順をMCPサーバーに適用します。見える設定、ツールの発見、対象への読み取り
アクセス、呼び出し結果、リモート状態の独立した読み戻し、採用判断を分けて記録します。
サーバーが設定されていること、ツールが見つかること・呼び出せること、結果を観測した
こと、外部書き込みが承認されたことは、それぞれ別の事実です。

## 受け入れチェックリスト

- [ ] 存在、暗黙の発見、明示名の解決、ロード、挙動、採用を分けた。
- [ ] revisionを固定し、ライセンス、NOTICE、ネスト資産、依存関係を確認した。
- [ ] 正例、境界、失敗／注入、移行のケースを設計した。
- [ ] 対象範囲、所有者、バックアップ、復旧方法、承認点を明記した。
- [ ] 認証情報、認証、アップロードの要求はすべて `blocked` にした。
- [ ] 実行していないテストは `not_run` のままにし、一覧を挙動の証拠にしなかった。
- [ ] 判断で推奨、blocked、条件付き承認、観測済みの導入を区別した。
- [ ] 判断パッケージに未知の点と候補の撤去方法を残した。
