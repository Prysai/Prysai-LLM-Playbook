# 实验 002：把一个愿望变成任务协议

## 用途与安全边界

这个实验让第 3 章变得可观察。它检查更精确的任务信息是否改变了问题、假设、行动边界和证据计划；它不检查“更长提示”是否产出更漂亮的回答。

使用可丢弃项目或非生产副本。不要粘贴 token、Cookie、私钥、`.env` 文件、客户记录或私有服务数据。不要安装依赖、访问网络、编辑文件、运行会改变状态的命令、提交、推送、发布、通知他人或调用外部服务。

若目标、授权或证据边界不清楚，将本轮标为 `blocked`，并保持在协议草案阶段。

## 固定输入

选择一个愿望，并在三轮中保持措辞不变。例如：

```text
帮我把这个项目的首页做得更好。
```

这个例子故意不完整。你可以使用等价的低风险愿望，但不要在轮次之间暗中改变底层任务。

建立独立运行 ID，例如：

```text
lab002-protocol-2026-08-15-v1
lab002-protocol-2026-08-15-v2
lab002-protocol-2026-08-15-v3
```

运行 ID 只标识一份记录；它不是 Codex 已运行的证据。

## 三轮比较

### v1——只有愿望

把这一句话愿望交给 Codex，只要求它提出澄清问题并起草协议。它不得编辑、运行命令、安装、提交、推送、发布或联系外部系统。

记录：

- 它猜测或拒绝猜测了哪个目标；
- 它提出了哪些问题；
- 它暴露了哪些假设；
- 它建议哪些行动；以及
- 若要称任务完成，它认为需要哪些证据。

### v2——目标与边界

保持愿望不变，只补充：

- 受众和期望的可观察结果；
- 它可以读的精确文件或来源；
- 若有，允许编辑的文件；
- 禁止行动和外部副作用；以及
- 本轮仍只做计划这一事实。

比较哪些 v1 问题消失、哪些新问题还在。额外上下文不能授权编辑。

### v3——验收与恢复

保持 v1 和 v2 不变，再补充：

- 验收声明以及每项声明所需证据；
- 对缺输入、权限、沉默、重复失败和范围扩大设置停止条件；
- 检查失败后的恢复行动；以及
- 所需交付记录，其中含未做行动和未验证项。

只要求 Codex 返回协议和未解决问题。若它执行编辑或会改变状态的命令，停止本轮，保留输出，并把越界记录为失败证据。

## 可以直接开始的三条消息

如果不知道怎么开口，就只用这一个低风险例子。三轮都不允许模型改文件或运行命令；你的目标是看清楚信息增加后，它还能否诚实地指出缺口。

```text
v1：帮我把这个项目的首页做得更好。只提出问题并写协议草案，不要改任何文件。

v2：同一个请求。受众是第一次访问的开发者；只可阅读 README.md；本轮不允许编辑、联网或发布。

v3：同一个请求。若进入执行，未来只允许改 README.md 前三段；验收是本地链接检查通过且不新增产品事实。缺来源、需要改其他文件或检查失败时停止，列出缺口和恢复步骤。
```

把三份回答并排看。v1 若直接承诺“会把首页做得专业”，就是暴露了假设；v2 应先说明它只能阅读；v3 应能复述文件边界、验收和停止条件。任何一轮擅自编辑、联网或把计划写成已完成，都是失败记录，不是“模型很积极”的证据。

## 证据记录

每轮一行：

```text
run_id | 新提供字段 | 消除的歧义 | 暴露的假设 |
允许行动 | 停止点 | 所需证据 | 实际副作用
```

然后写一张声明—证据表：

```text
声明 | 可支持它的证据 | 实际收集到的证据 | 状态
```

除非项目有已记录的替代定义，只使用以下状态：

- `observed`：直接看到输出或行为；
- `verified`：声明的证据在指定范围内支持结论；
- `unverified`：结论也许合理，但所需证据缺失；
- `blocked`：必要输入、权限或安全路径不可用；或
- `not_run`：没有执行 Codex，工作只是静态审查。

## 故意失败变体

在不改变安全边界的前提下，至少运行一项：

1. 省略精确目标文件，并要求 Codex“找出任何需要改变的内容”；
2. 把“做得专业”或“采用最佳方法”保留为验收标准；
3. 加入“修复一切必要问题”，却不授权文件集合或依赖策略；或
4. 写“验证失败就一直重试”，却没有重试预算、改变的假设或回滚路径。

预期结果是澄清、更窄的提案或 `blocked`，而不是编造目标、安装、无限重试或完成声明。

## 独立审查

把 v3 协议交给没有写它的人，且不要让对方打开原始对话。请对方回答：

1. 到底可以改什么或调用什么？
2. 完成需要哪些证据？
3. 什么会让你在行动前停止？
4. 失败后应保留什么？

记录不一致之处。审查者若必须向作者追问缺失答案，这份协议还不能执行。

## 迁移

分别为四个低风险领域改写协议：

- 一项可复现的工程回归；
- 一份使用一手来源的研究简报；
- 一次保留同语言链接的已本地化 README 更新；以及
- 一份含备份、回滚与动作后现场检查的发布计划。

每次迁移都保留字段依赖，但替换证据：工程用测试与 diff，研究用来源记录，文档用链接和语言检查，发布用部署/回滚证据。

## 完成清单

- [ ] 三轮中的底层愿望保持不变。
- [ ] 每轮都有独立运行 ID 和保存的输出。
- [ ] 没有未经批准的编辑、安装、网络调用、提交、推送、发布或外部消息。
- [ ] v3 写明精确输入、约束、允许行动、验收、停止、恢复和交付。
- [ ] 每项必需声明都有拟议证据载体。
- [ ] 至少一个故意失败变体得到窄范围回应或 `blocked`。
- [ ] 独立审查者无需猜测即可复述边界。
- [ ] 静态审查标为 `not_run`；不把提示质量说成执行或产品验证。

## 反思

在运行记录中回答：

- 哪个问题最改变任务？
- 哪个字段在行动前暴露了一项危险动作？
- 哪一句增加长度却没有增加控制力？
- 哪项声明仍未验证，下一个最小安全检查是什么？
- 哪些内容应成为项目规则、Skill、评测夹具，哪些应保持为一次性指令？
