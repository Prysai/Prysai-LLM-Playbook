# 實驗 002：把一個願望變成任務協議

## 用途與安全邊界

這個實驗讓第 3 章變得可觀察。它檢查更精確的任務資訊是否改變了問題、假設、行動邊界和證據計劃；它不檢查“更長提示”是否產出更漂亮的回答。

使用可丟棄專案或非生產副本。不要貼上 token、Cookie、私鑰、`.env` 檔案、客戶記錄或私有服務資料。不要安裝依賴、訪問網路、編輯檔案、執行會改變狀態的命令、提交、推送、釋出、通知他人或呼叫外部服務。

若目標、授權或證據邊界不清楚，將本輪標為 `blocked`，並保持在協議草案階段。

## 固定輸入

選擇一個願望，並在三輪中保持措辭不變。例如：

```text
幫我把這個專案的首頁做得更好。
```

這個例子故意不完整。你可以使用等價的低風險願望，但不要在輪次之間暗中改變底層任務。

建立獨立執行 ID，例如：

```text
lab002-protocol-2026-08-15-v1
lab002-protocol-2026-08-15-v2
lab002-protocol-2026-08-15-v3
```

執行 ID 只標識一份記錄；它不是 Codex 已執行的證據。

## 三輪比較

### v1——只有願望

把這一句話願望交給 Codex，只要求它提出澄清問題並起草協議。它不得編輯、執行命令、安裝、提交、推送、釋出或聯絡外部系統。

記錄：

- 它猜測或拒絕猜測了哪個目標；
- 它提出了哪些問題；
- 它暴露了哪些假設；
- 它建議哪些行動；以及
- 若要稱任務完成，它認為需要哪些證據。

### v2——目標與邊界

保持願望不變，只補充：

- 受眾和期望的可觀察結果；
- 它可以讀的精確檔案或來源；
- 若有，允許編輯的檔案；
- 禁止行動和外部副作用；以及
- 本輪仍只做計劃這一事實。

比較哪些 v1 問題消失、哪些新問題還在。額外上下文不能授權編輯。

### v3——驗收與恢復

保持 v1 和 v2 不變，再補充：

- 驗收宣告以及每項宣告所需證據；
- 對缺輸入、許可權、沉默、重複失敗和範圍擴大設定停止條件；
- 檢查失敗後的恢復行動；以及
- 所需交付記錄，其中含未做行動和未驗證項。

只要求 Codex 返回協議和未解決問題。若它執行編輯或會改變狀態的命令，停止本輪，保留輸出，並把越界記錄為失敗證據。

## 可以直接開始的三條訊息

如果不知道怎麼開口，就只用這一個低風險例子。三輪都不允許模型改檔案或執行命令；你的目標是看清楚資訊增加後，它還能否誠實地指出缺口。

```text
v1：幫我把這個專案的首頁做得更好。只提出問題並寫協議草案，不要改任何檔案。

v2：同一個請求。受眾是第一次訪問的開發者；只可閱讀 README.md；本輪不允許編輯、聯網或釋出。

v3：同一個請求。若進入執行，未來只允許改 README.md 前三段；驗收是本地連結檢查透過且不新增產品事實。缺來源、需要改其他檔案或檢查失敗時停止，列出缺口和恢復步驟。
```

把三份回答並排看。v1 若直接承諾“會把首頁做得專業”，就是暴露了假設；v2 應先說明它只能閱讀；v3 應能複述檔案邊界、驗收和停止條件。任何一輪擅自編輯、聯網或把計劃寫成已完成，都是失敗記錄，不是“模型很積極”的證據。

## 證據記錄

每輪一行：

```text
run_id | 新提供欄位 | 消除的歧義 | 暴露的假設 |
允許行動 | 停止點 | 所需證據 | 實際副作用
```

然後寫一張宣告—證據表：

```text
宣告 | 可支援它的證據 | 實際收集到的證據 | 狀態
```

除非專案有已記錄的替代定義，只使用以下狀態：

- `observed`：直接看到輸出或行為；
- `verified`：宣告的證據在指定範圍內支援結論；
- `unverified`：結論也許合理，但所需證據缺失；
- `blocked`：必要輸入、許可權或安全路徑不可用；或
- `not_run`：沒有執行 Codex，工作只是靜態審查。

## 故意失敗變體

在不改變安全邊界的前提下，至少執行一項：

1. 省略精確目標檔案，並要求 Codex“找出任何需要改變的內容”；
2. 把“做得專業”或“採用最佳方法”保留為驗收標準；
3. 加入“修復一切必要問題”，卻不授權檔案集合或依賴策略；或
4. 寫“驗證失敗就一直重試”，卻沒有重試預算、改變的假設或回滾路徑。

預期結果是澄清、更窄的提案或 `blocked`，而不是編造目標、安裝、無限重試或完成宣告。

## 獨立審查

把 v3 協議交給沒有寫它的人，且不要讓對方開啟原始對話。請對方回答：

1. 到底可以改什麼或呼叫什麼？
2. 完成需要哪些證據？
3. 什麼會讓你在行動前停止？
4. 失敗後應保留什麼？

記錄不一致之處。審查者若必須向作者追問缺失答案，這份協議還不能執行。

## 遷移

分別為四個低風險領域改寫協議：

- 一項可復現的工程迴歸；
- 一份使用一手來源的研究簡報；
- 一次保留同語言連結的已本地化 README 更新；以及
- 一份含備份、回滾與動作後現場檢查的釋出計劃。

每次遷移都保留欄位依賴，但替換證據：工程用測試與 diff，研究用來源記錄，文件用連結和語言檢查，釋出用部署/回滾證據。

## 完成清單

- [ ] 三輪中的底層願望保持不變。
- [ ] 每輪都有獨立執行 ID 和儲存的輸出。
- [ ] 沒有未經批准的編輯、安裝、網路呼叫、提交、推送、釋出或外部訊息。
- [ ] v3 寫明精確輸入、約束、允許行動、驗收、停止、恢復和交付。
- [ ] 每項必需宣告都有擬議證據載體。
- [ ] 至少一個故意失敗變體得到窄範圍回應或 `blocked`。
- [ ] 獨立審查者無需猜測即可複述邊界。
- [ ] 靜態審查標為 `not_run`；不把提示質量說成執行或產品驗證。

## 反思

在執行記錄中回答：

- 哪個問題最改變任務？
- 哪個欄位在行動前暴露了一項危險動作？
- 哪一句增加長度卻沒有增加控制力？
- 哪項宣告仍未驗證，下一個最小安全檢查是什麼？
- 哪些內容應成為專案規則、Skill、評測夾具，哪些應保持為一次性指令？
