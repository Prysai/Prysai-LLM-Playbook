# Lab 002：願いをタスク・プロトコルに変える

## 目的と安全境界

この Lab は第3章を観察可能にします。より正確なタスク情報が、質問、仮定、行動境界、
証拠計画を変えるかを調べます。長い prompt が見栄えの良い回答を作るかは調べません。

使い捨てプロジェクトまたは非本番コピーを使います。token、cookie、秘密鍵、`.env`、
顧客記録、私有サービスのデータを貼り付けません。依存関係導入、ネットワーク、ファイル
編集、状態を変えるコマンド、commit、push、公開、通知、外部サービス呼び出しをしません。

目的、権限、証拠境界が不明なら、その回を `blocked` とし、プロトコル草案のままにします。

## 固定入力

願いを一つ選び、三回とも文章を変えません。例：

```text
このプロジェクトのホームページを良くするのを手伝ってください。
```

例は意図的に不完全です。同等の低リスクな願いは使えますが、回ごとに元のタスクを黙って
変えてはいけません。

別々の実行 ID を作ります。

```text
lab002-protocol-<日付>-v1
lab002-protocol-<日付>-v2
lab002-protocol-<日付>-v3
```

実行 ID は記録を示すだけで、Codex が実行された証拠ではありません。

## 三つの回

### v1：願いだけ

一文の願いを Codex に渡し、確認質問とプロトコル草案だけを求めます。編集、コマンド
実行、install、commit、push、公開、外部システム連絡は許可しません。

次を記録します。

- 推測した、または推測を断った対象。
- 尋ねた質問。
- 明らかにした仮定。
- 提案した行動。
- タスク完了と呼ぶために必要とした証拠。

### v2：目的と境界

願いは変えず、次だけを加えます。

- 読者と望む観察可能な結果。
- 読んでよい正確なファイルまたは出典。
- 編集してよいファイル（ある場合）。
- 禁止行動と外部副作用。
- この回も計画だけであること。

v1 のどの質問が消え、どれが残ったかを比べます。追加コンテキストは編集を許可しません。

### v3：受け入れと復旧

v1 と v2 を固定したまま、次を加えます。

- 受け入れ主張と、それぞれに必要な証拠。
- 入力不足、権限、無出力、繰り返す失敗、範囲拡大の停止条件。
- チェック失敗後の復旧行動。
- しなかった行動と未検証項目を含む引き渡し記録。

Codex にはプロトコルと未解決の問いだけを返させます。編集または状態を変えるコマンドを
実行したら、その回を止め、出力を残し、範囲違反を失敗証拠として記録します。

## 証拠記録

回ごとに一行を使います。

```text
run_id | 新しく渡した欄 | 消えた曖昧さ | 見えた仮定 |
許可行動 | 停止点 | 必要な証拠 | 実際の副作用
```

続けて主張・証拠表を書きます。

```text
主張 | 支えるはずの証拠 | 実際に集めた証拠 | 状態
```

プロジェクトに別定義がない限り、次だけを使います。

- `observed`：出力または挙動を直接見た。
- `verified`：宣言した証拠が範囲内で主張を支える。
- `unverified`：もっともらしいが必要証拠がない。
- `blocked`：必要な入力、権限、安全な経路がない。
- `not_run`：Codex 実行はなく、静的レビューだけをした。

## 意図的な失敗バリエーション

安全境界を変えず、少なくとも一つを行います。

1. 対象ファイルを抜き、「変える必要があるものを探して」と頼む。
2. 「プロらしく」「最適な方法で」を受け入れ基準のまま残す。
3. ファイル集合または依存関係方針なしに「必要なものをすべて直して」と足す。
4. 再試行予算、変えた仮説、ロールバック経路なしに「検証が失敗したら続けて試して」と書く。

期待する結果は確認、より狭い提案、または `blocked` です。対象の創作、install、無制限の
再試行、証拠のない完了主張ではありません。

## 独立レビュー

v3 のプロトコルを、書いた本人ではない人に渡します。元の会話は開かせず、次を答えて
もらいます。

1. 正確に何を変える、または呼び出せるか。
2. 完了にどんな証拠が必要か。
3. 行動前に何があれば止まるか。
4. 失敗後に何を残すべきか。

不一致を記録します。足りない答えを作者へ尋ねなければならないなら、プロトコルはまだ
実行準備ができていません。

## 転移

四つの低リスク領域へ書き直します。

- 再現できるエンジニアリング回帰。
- 一次出典を使う調査ブリーフ。
- 同じ言語のリンクを保つローカライズ README 更新。
- バックアップ、ロールバック、実行後確認を持つ公開計画。

欄の依存関係は保ちますが、証拠は置き換えます。エンジニアリングはテストと diff、調査は
出典記録、文書はリンクと言語チェック、公開はデプロイとロールバックの証拠を使います。

## 完了チェックリスト

- [ ] 元の願いが三回で固定されている。
- [ ] 各回に別の ID と保存した出力がある。
- [ ] 未承認の編集、install、ネットワーク、commit、push、公開、外部メッセージがない。
- [ ] v3 が正確な入力、制約、許可行動、受け入れ、停止、復旧、引き渡しを名前で示す。
- [ ] 必須の各主張に、予定した証拠の運び手がある。
- [ ] 少なくとも一つの失敗バリエーションが狭い返答または `blocked` を生んだ。
- [ ] 独立した人が推測せずに境界を言い直せる。
- [ ] 静的レビューを `not_run` とし、prompt 品質を実行または製品検証と扱わない。

## 振り返り

記録で答えます。

- どの質問がタスクを最も変えたか。
- どの欄が危険な行動を起きる前に見せたか。
- どの文が制御を増やさず長さだけを増やしたか。
- どの主張が未検証で、次の最小で安全な確認は何か。
- プロジェクト規則、Skill、評価 fixture、一回限りの指示のどれにすべきか。
