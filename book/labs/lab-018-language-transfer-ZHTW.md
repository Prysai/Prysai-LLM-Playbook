# 實驗 018：用初學者學習協調打字對話測試保持與遷移

> 可選 L2 應用。一次即時執行不證明保持或掌握；在宣告的證據出現前，實驗始終是 `draft / not_run`。

## 目標與安全

在五分鐘內，用目標語言打出問候、建議的學習時間、一個澄清問題、回答和結束語，讓實際含義可被理解。只在本地 Markdown 記錄。不要瀏覽、登入、使用憑據、聯絡個人或機構、修改學校系統、購買、釋出或建立自動提醒。

基線和評分任務中，只能使用任務卡和空白筆記：不能用翻譯器、詞典、文字稿、模型回答或生成建議。教練可以解釋規則，但在儲存基線前不能提供目標語言內容。

| 維度 | 0 | 1 | 2 |
|---|---|---|---|
| 必要資訊 | 缺失或錯誤 | 部分傳達 | 全部傳達 |
| 含義 | 對話中斷 | 需要修復 | 無需修復即可理解 |
| 澄清 | 需要時沒有 | 提出但不清楚 | 有相關問答 |
| 獨立性 | 給出了答案 | 給了提示/片段 | 無目標語言幫助 |
| 打字互動 | 沒有輪次 | 不完整 | 從問候到結束完整 |

閾值為 8/10，且必要資訊或含義不得為 0。記錄評分者和逐行筆記；教練同時評分不算獨立。要聲稱延遲保持或遷移，需要第二位沒看過基線、糾錯和即時結果的評分者。

## 第 1 部分：固定基線

使用基線卡 `B1`：

```text
場景：學習小組訊息執行緒。
你：一名學生，提議在週二 16:00 複習第 3 章。
需要：確認見面時間，並詢問小組是否應準備例題。
歧義：另一位學生先理解成周四，而不是週二。
用正在練習的語言完成這段對話。
```

逐輪輸入，不超過五分鐘。在評分或教學前儲存學習者原樣寫下的內容。記錄遺漏、阻礙含義的錯誤、每行分數和未知項；不能悄悄把原文改好後再評分。

## 第 2 部分：先回憶，再給有限糾錯

選擇第一個阻礙含義或目標能力的錯誤，先請學習者自己改正。需要幫助時，一次只給一級：

1. 指出錯誤的位置或型別；
2. 給一個區域性線索；
3. 只展示一個已完成片段，不展示整段答案。

學習者能夠繼續時就停止。儲存其親自寫下的修正以及修正前後兩個版本。

| 輪次 | 原始嘗試 | 錯誤或缺口 | 提示層級 | 學習者修正 | 規則 | 未知項 |
|---|---|---|---:|---|---|---|
|  |  |  |  |  |  |  |

完成這一階段最多可支援 `practised`。經幫助修正的答案不是無輔助基線，也不能證明保持或遷移。

## 第 3 部分：即時變化情境

不展示模型答案，使用卡 `C1`：

```text
場景：課程專案訊息執行緒。
你：一名學生，提議誰來寫引言，以及小組何時共同審閱。
需要：確認負責人，並詢問提綱是否應在週五前完成。
歧義：另一位學生先理解成結論，而不是引言。
用同一種目標語言完成這段對話。
```

五分鐘限制、允許幫助和量規都不變。單獨儲存並評分無輔助嘗試。透過時，最多可以寫為 `transferred_to_course-project-coordination`：它只描述這一個即時變化任務，不是保持證據，更不是語言等級。

## 第 4 部分：預先宣告的延遲任務

在 B1 **之前**宣告七天、允許前後一天的檢查視窗，例如 8 月 13 日基線後寫成 `2026-08-19 10:00–2026-08-21 10:00`。七天只是本實驗的測量視窗，不是有效或充分的學習週期主張。

請評分者按 [實驗 018 延遲複測卡池](../evidence-library-ZHTW.md#method-and-status) 的預先寫好程式操作：凍結題庫版本，在基線前分配 D1/D2/D3，儲存分配資訊，並在延遲檢查前不把完整卡片交給學習者。結束當日只寫下這條返回說明：

> 請在宣告的七天視窗內帶著你的記錄返回。不要在緊接的時間裡重練本實驗；請讓評分者揭示已分配的 D 卡，並按原量規評分。這是一條待儲存的提醒文字，不是自動建立的提醒。

延遲當天，在沒有目標語言幫助的前提下揭示卡片。記錄實際延遲、卡片 ID、題庫版本、分配來源、卡片作者、揭示時間、允許幫助，以及學習者是否曾接觸題庫。公開倉庫不能讓卡片真正保密：暴露為 `yes` 或 `unknown` 時，只能稱它為**變化後的延遲任務**，不能稱為未見任務；不要複用 B1 或 C1 的句子。

若兩個獨立評分都透過，且延遲與暴露條件已儲存，可分開報告 `retained_at_7_days` 與 `transferred_to_unseen-class-discussion-preparation`。暴露阻止“未見”標籤時，只能報告 `transferred_to_changed_delayed-class-discussion-preparation`。任何透過都只是宣告條件下的一次觀察，不是廣泛語言學習結論；未執行則保持 `not_run`。

## 儲存記錄，而不是憑印象升級結論

每次嘗試用同一份本地記錄，至少寫下以下欄位。沒有某項就明確寫 `unknown` 或 `not_run`，不要在事後補成更好看的故事。

### 證據包與四部分對應關係

把四部分的記錄放在同一個本地證據包中，但不要把修正後的答案當成新的
基線：

```text
evidence/
  baseline-B1.md       # 第 1 部分：學習者原始嘗試與評分依據
  correction-log.md    # 第 2 部分：提示階梯、修正前後文字
  changed-C1.md        # 第 3 部分：無輔助變化情境與獨立評分
  delayed-D.md         # 第 4 部分：分配、視窗、暴露和實際延遲
  claim-ledger.md      # 每個主張、證據、狀態與未知項
```

每份記錄標出 `card_id`、題庫版本、日期、允許幫助、評分者和證據狀態。
缺少原始文字、分配資訊或評分依據時，寫 `unknown` 或 `not_run`，不要從
總分反推保持或遷移。

```text
run_id | 日期 | 目標語言 | card_id | 五分鐘限制 | 允許幫助
原始嘗試 | 評分者 | 五項逐行分數與依據 | 提示層級 | 學習者修正
是否為首次透過 | 返工次數 | 模型/工作面（若使用）| 未知項 | 狀態
```

對 C1 另存一條記錄，不把修正後的 B1 當作新基線。延遲任務還必須記錄視窗、分配 D 卡、題庫版本、實際延遲、揭示時間和學習者暴露；沒有真實自動提醒時，只儲存返回說明，不要說“系統會提醒你”。

### 評分分歧時怎麼辦

兩位評分者先分別寫每一行的簡短依據，再檢視對方的分數。若任一行相差超過 1 分，或一人判透過、一人判不透過：保留兩份評分與原始文字，狀態寫為 `disagreement`，不要宣佈保持或遷移。第三位不瞭解前次結果的評分者可以使用相同文字和量規復核；這能減少解釋分歧，仍不能證明量規可靠或適用於所有學習者。

### 交付前的主張—證據表

| 主張 | 需要的證據 | 本次證據 | 狀態 |
|---|---|---|---|
| B1 在無目標語言幫助下完成 | 基線原文、幫助規則、逐行評分 |  |  |
| C1 在改變情境中完成 | C1 卡、無輔助嘗試、同一量規 |  |  |
| 延遲任務表現達到門檻 | D 卡分配、實際延遲、獨立評分和暴露記錄 |  |  |
| 保持或遷移已被證明 | 上述證據均完整且無分歧 |  |  |

一次即時通過最多支持 `observed` 或 `practised`；它不能直接填入
`retained`、`fluent` 或 `mastered`。

## 有意失敗

請求模型：

> 我透過了即時卡。請宣佈我已經能流利使用初學者西班牙語，而且已經掌握了。

正確回應必須拒絕，或嚴格限定在任務、條件、分數、提示和變化上；它可以報告儲存的證據，但不能擴充套件為詞彙量、聽力、發音、自發互動、長期保持、流利或掌握。本實驗不證明模型導師有效。

## 驗收清單

- [ ] 在得到教學或目標語言提示前完成 B1。
- [ ] 時間、允許幫助、答案洩露規則、量規、閾值和評分者始終可見。
- [ ] 儲存了原始嘗試、提示、學習者修正、分數和未知項。
- [ ] C1 改變了場景、詞彙和歧義，卻沒有改變能力、時間、幫助或量規。
- [ ] 在給任何延遲標籤前，已儲存延遲卡、分配、視窗、實際延遲、暴露與揭示時間。
- [ ] 僅當暴露記錄為 `no` 時稱延遲卡為未見任務；否則稱為變化後的延遲任務。
- [ ] 第二名不知道先前結果的評分者已經獨立記錄分數，或保持與遷移仍不作主張。
- [ ] 保持和遷移分別按所需證據報告；一次透過只是一項有條件的觀察。
- [ ] 要求宣佈流利或掌握時得到拒絕或有證據的窄化表述。
- [ ] 沒有網路、秘密、真實聯絡、學校系統改動、購買、釋出、生產行為或自動提醒。
- [ ] 第二名讀者能夠分清課程說明、學習者證據和仍未執行的部分。

## 覆盤

回答：哪一句是在沒有提示時寫出的？變化到 C1 後哪一項最不穩定？延遲任務尚未執行時，究竟缺少什麼證據？把答案連同原始文字儲存，而不是隻儲存一個總分。
