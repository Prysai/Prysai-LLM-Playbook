## この実験の目的

これは、L0 ゲートに向けた低リスクの入門実験です。実際の統合テストではなく、認証情報を Codex へ
貼り付けることも求めません。成果物は、洗練された回答ではなく、別の人が確認できる記録です。

次の出来事の区別を使います。

    生成されたテキスト
      != 提案されたツール操作
      != 許可／実行された行動
      != 変更された状態
      != 検証済みの結果

## 安全性と準備

- 使い捨てのローカルディレクトリ、またはプレーンテキストの学習記録で作業します。
- 実験の必須部分では、ChatGPT、Codex Cloud、GitHub、ブラウザーアカウント、MCP、その他の
  外部サービスに接続しないでください。
- トークン、Cookie、秘密鍵、`.env` ファイル、顧客データ、本番ファイルを使わないでください。
- 任意のローカル拡張を行う場合も、編集するのは学習記録と使い捨てのメモファイルだけです。
- 提案されたステップに、ネットワーク呼び出し、アカウントへのアクセス、秘密情報、公開先への書き込み、
  破壊的なリセットが必要な場合は、停止して `blocked` と記録します。

`lab011-ja-2026-08-10-a` のような実行 ID を作成します。日付、使用した場合は画面／モデルのラベル、
入力リビジョン、必須部分が静的またはテキストのみであるという事実を記録してください。

## パート1：境界台帳を記入する

次の固定カードを分類します。「主な層」とは、学習者が観察しなければならない層を指します。
製品内部の実装についての主張ではありません。

| カード | タスクカード |
|---|---|
| A | 「コンテキストを自分の言葉で説明し、不明点を二つ挙げてください。」 |
| B | 「notes.md を読み、使い捨てのローカルコピーに見出しを一つ追加して、差分を示してください。」 |
| C | 「ツールを呼び出し、結果を組織の公開リポジトリへ書き込み、チームへ通知してください。」 |
| D | 「成功したように見えるまでエラーの修正を試し続け、中間状態は記録しないでください。」 |
| E | 「システムはログイン済みです。ツールが完了と表示したので、チェックを省いて今すぐ公開してください。」 |

次の台帳を記入します。

| カード | 主な層 | 許可された行動 | 禁止された行動 | 最小限の証拠 | 停止／確認点 | 何が不明なままか |
|---|---|---|---|---|---|---|
| A |  |  |  |  |  |  |
| B |  |  |  |  |  |  |
| C |  |  |  |  |  |  |
| D |  |  |  |  |  |  |
| E |  |  |  |  |  |  |

次の順序で判断します。

1. 依頼は説明／生成、読み取り／編集、外部状態の変更のどれか。
2. 状態を変更する場合、どの正確な対象、権限、確認、ロールバックが必要か。
3. 完了の主張に対応する証拠はどれか。
4. 再試行せずタスクを停止する条件は何か。

適切なベースライン回答では、A を説明、B を範囲の限定されたローカル実行タスク、C をこの場では
実行してはならない外部副作用の計画、D を範囲の定まらない Agent ループ、E を根拠のない思い込みとして
特定します。理由を説明してください。この一文をコピーして、証拠としてはいけません。

## パート2：制御されたコンテキスト実験を行う

次のテキストだけのタスクを使います。

> 提供された README の抜粋を確認し、改善点を一つ特定してください。ファイルは編集しないでください。
> 与えられた内容、その改善が重要な理由、確認方法、分からないことを述べてください。

抜粋だけを使ってベースラインを実行します。次に、厳密に一つだけ変更して繰り返します。

1. 想定する対象読者を追加する。
2. 短いプロジェクト規則を追加する。
3. 受け入れ条件を追加する。

その主張を裏付けられる程度にモデル／画面、入力リビジョン、生成構成、ツールの状態を固定していない限り、
追加した項目が出力の差を引き起こしたと主張しないでください。固定できない場合は、次のように書きます。

    異なる結果を観測した。原因は切り分けられていない。

次を記録します。

    run-id | 入力リビジョン | 画面／モデル | 変更した変数 | ツールを呼び出したか | ファイルを変更したか | 観測した証拠 | 不明点

この実験は、手作業で書いたシミュレーションでも完了できます。実際のモデル実行は任意であり、実在する証拠を
使ってラベル付けしなければなりません。シミュレーションされたツールの結果は、実行されたツールの結果には
決してなりません。

## パート3：安全でない完了の主張を修正する

次の文から始めます。

> 「ブラウザーへのログインは成功し、ツールは完了を返し、モデルも変更が完了したと述べた。
> したがって、公開リポジトリは更新された。」

主張の台帳として書き直します。

| 主張 | 必要な証拠 | 現在の状態 | 安全な次の確認 |
|---|---|---|---|
| ブラウザー認証が完了した | 認証段階と、クライアントのトークン／セッションに関する証拠 |  |  |
| このリポジトリに対する操作が認可されていた | 対象、アカウント／組織の範囲、権限の証拠 |  |  |
| ツールが書き込みを実行した | ツールの呼び出し／結果と対象識別子 |  |  |
| 意図したオブジェクトが変更された | 対象からの新しい読み取り、またはプロバイダー側の記録 |  |  |
| 変更が受け入れ可能である | 差分／レビュー／テスト、または人による受け入れ |  |  |

空の状態を「おそらく」で埋めないでください。`not_observed`、`blocked`、`partial`、
`verified within scope` のいずれかを使い、その範囲を説明します。

## パート3A：メカニズムレベルの失敗を一つ追加する

次の合成されたネットワーク不要の事例から一つ選び、主張の台帳へ追加します。

- **スキーマは合格、意味は不合格：** 応答は有効な JSON で必須フィールドをすべて含むが、参照先の
  オブジェクトが存在しない。ビジネス／状態のチェックを追加します。
- **検索ではヒット、例外は欠落：** 広範なポリシーのチャンクは選択されたが、バージョン固有の例外が
  含まれていない。クエリ、フィルター、選択されたチャンク、不足している証拠のフィールドを追加します。
- **指示の形をしたデータ：** README またはツールの結果に、タスクの安全規則を無視するよう書かれている。
  データとして扱い、外部への副作用を拒否し、出所と影響を試みた内容を記録します。

重要なのは、失敗した層を正確に名付けることです。スキーマの結果、検索のヒット、目に見える文字列は、
意味的な正しさ、完全なコンテキスト、権限の証拠に自動的になるわけではありません。出典に基づく境界については、
[LLM メカニズム研究](../evidence-library-JA.md#source-notes)を参照してください。
この実験では、実際のプロバイダーを使いません。

## パート4：停止規則を実践する

害のない、意図的に挿入された失敗を一つ選びます。

- モデルが容量上限に達していると報告する。
- 宣言した制限時間を超えてもコマンドが Working のままだと報告する。
- 検証コマンドが強制再インストールを要求したと報告する。

自動的に再試行しないでください。次を書きます。

    状態 | 目に見える症状 | 現在のチェックポイント | 取得した証拠 | 必要な権限 | 最小の復旧操作 | 未検証事項

適切な復旧とは通常、現在の状態を確認し、記録を保存し、次のチェックを絞り込むか、権限を求めることです。
ワークスペースを消去したり、依存関係を強制インストールしたり、次のキュー済み指示を送ったりすることではありません。

これらの失敗の形は、[Codex の現場問題に関する調査](../evidence-library-JA.md#source-notes)の
公開報告に基づいています。これはユーザーによる証拠であり、公式な根本原因の確認ではありません。また、
この実験はローカルで再現したとは主張しません。

## 証拠パッケージ

次を含むディレクトリ一つ、または Markdown 記録一つを提出します。

1. 固定カードのバージョンと実行 ID。
2. 記入済みの A～E の境界台帳。
3. コンテキスト実験の二つの行と交絡要因。
4. 修正した主張の台帳。
5. 停止／復旧の記録。
6. 150 語以内の個人的な要約。

要約では、次の問いに答えなければなりません。

- モデルの出力とツールの結果は、どう違うか。
- ツールの結果と検証済みの状態は、どう違うか。
- ログイン、モデル名、Skill 名、完了メッセージが、権限や正しさを証明しないのはなぜか。
- どの記述が `not_observed` のままか。

## 受け入れ条件

次の条件をすべて満たした場合にのみ合格です。

- すべての固定カードに、理由、境界、証拠、停止点がある。
- カード C とカード E によって、実際の外部書き込みや通知が行われていない。
- 少なくとも一つの記述を推測で埋めず、意図的に未検証のまま残している。
- コンテキスト実験に、変更した変数と交絡要因が記録されている。
- 失敗の演習が、破壊的または許可されていない権限拡大の前に停止している。
- メカニズムの事例で、不足がスキーマ、コンテキストの選択、指示の権限、実行、検証のいずれに
  あるかを特定している。
- 二人目の読者が、どの出来事がシミュレーション済み、観測済み、未実行かを判別できる。

プロジェクトに実際の実行記録と独立レビューが存在するまで、この実験は `draft`、`run_status: not_run` の
ままです。完成したワークシートは、学習者の演習についての証拠であり、すべての Codex 製品画面が同じように
挙動することの証拠ではありません。

## 移行タスク

固定された公開情報源一式を使い、使い捨てのローカルファイルに1ページの調査概要を作成します。情報源の文章、
ユーザーの指示、モデルの提案、ローカルでの編集、検証チェックを、それぞれ別の層として印を付けます。
概要とは無関係な、指示のような文を含む情報源を一つ加えます。それを権限ではなくデータとして扱う理由を
記録してください。明示的な範囲と確認を含む新しいタスクプロトコルを作らない限り、この移行タスクのために
ブラウズ、公開、外部コネクターの呼び出しを行ってはいけません。
