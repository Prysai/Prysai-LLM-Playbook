# Lab 001: 安全な README の変更を一つ行う

## この Lab の目的

これは第 1 章の静的な境界図から、実際だが制御されたファイル変更へ進む L1 の
練習です。デプロイ、コネクタ、または現在の権限ラベルがどこでも有効であることを
試すものではありません。

実行は必ず破棄可能または非本番のプロジェクトで行います。資格情報、トークン、
Cookie、秘密鍵、.env、顧客記録、本番設定をタスクに貼り付けないでください。

## 準備

1. 破棄可能なプロジェクトがなければ、最初の安全な変更 fixture を使います。Git、アカウント、インストール、ネットワークを必要としません。
2. 絶対パスと、Git プロジェクトなら現在の git status を記録します。fixture では架空のリポジトリ情報を作らず、not a Git sandbox と記録します。
3. 元の README.md を保存するか、クリーンなチェックポイントを作ります。
4. ローカル実行コマンドを定義する実ファイルを確認します。記憶や検索結果からコマンドを作りません。
5. 許可する編集を README.md のみに書きます。
6. この実行にインストール、ネットワーク、commit、push、公開、外部メッセージ、秘密の読み取り、本番操作が含まれないことを確認します。

一つでも不明なら停止し、blocked と記録します。まず試すことは代替になりません。
run ID は記録を識別するだけで、証拠ではありません。

## 最初の操作前に答える四つの質問

| 質問 | 記録すること | 続行できる条件 | 停止する条件 |
| --- | --- | --- | --- |
| どこで実行するか | 宣言した sandbox、観察したカレントディレクトリ、Git root と branch または HEAD。fixture だけは not a Git sandbox を使用可。 | 観察したディレクトリが sandbox 内にあり、識別子が同じローカルコピーを示す。 | 必要な識別子がない、曖昧、sandbox 外、または矛盾する。 |
| 何を変更できるか | README.md のみ。 | sandbox 内にある既存の一ファイルが対象。 | 別のパスが必要、または対象を特定できない。 |
| 何が許可されるか | 調査、計画の報告、承認後の一編集。 | 可逆で、新しい権限を必要としない。 | 秘密、インストール、ネットワーク、commit、push、公開、削除、外部書き込みが必要。 |
| 受け取り証拠は何か | 基準状態、正確な diff、コマンド根拠、限定チェック出力、不明点。 | 実行後に各項目を検査・保存できる。 | 状態メッセージや検査不能な回答だけになる。 |

空欄や unknown は推測で埋める欄ではなく、停止信号です。四つが具体的になるまで
ファイル操作を始めません。

## Codex に渡すタスクカード

次の項目を現在の sandbox の事実で埋めます。

    Run ID: lab001-readme-date-suffix
    Goal: absolute-path/README.md に正確なローカル開始セクションを一つ追加する。
    Sandbox: absolute-path。編集できるのは README.md だけ。
    先に読むもの: README.md、package/build manifest、既存の script ファイル。
    許可する編集: README.md のみ。
    してはいけないこと: install、ネットワーク、コード変更、commit、push、公開、
      メッセージ送信、秘密の読み取り、本番データの利用。
    受け取り証拠: 基準状態、計画、正確な diff、コマンド根拠、限定チェック出力、
      明示した未検証一覧。
    不明なパス、コマンド、権限、復旧があれば停止して質問する。

重要なのは文章の魔法ではなく契約です。編集を許す前に、対象、基準状態、許可パス、
禁止行為、受け入れ証拠を理解したか確認します。誤解は diff になる前に直します。

## 保存する証拠

一つの記録に次を残します。

    run_id:
    checkpoint_before:
    preflight_sandbox:
    preflight_observed_directory:
    preflight_repository_root:
    preflight_branch_or_head:
    preflight_edit_target:
    inputs_read:
    assumptions:
    actions_done:
    actions_not_done:
    diff_scope:
    verification_command:
    verification_result:
    unverified:
    blocked_on:
    next_check:
    permission_boundary:
    status: passed | failed | stopped

passed と書けるのは、README だけが変わり、コマンドが実プロジェクトの設定で
裏付けられ、外部書き込みがなく、未実行または利用できない checker が明記されて
いる範囲だけです。計画と行為、提案コマンドと実行コマンド、diff と通過した
チェック、中断したチェックと成功したチェックを分けます。

## 安全な能力プローブ

パスや workspace の主張に依存する場合だけ、編集前に無害な sentinel を使います。

1. 絶対パスと、承認済み sandbox 内であることを確認する。
2. 許可された正確なパスに、秘密を含まない一時 sentinel ファイルを書く。
3. 読み戻して結果を記録する。
4. cleanup も承認済み範囲なら削除する。

このプローブは資格情報を読まず、権限を変えず、パッケージを入れず、ネットワークや
別リポジトリに触れません。一回の無害な書き込みの証拠であり、広いツール権限や本番
アクセスの証拠ではありません。パスまたは cleanup が不明なら blocked または
unverified と記録して停止します。

## 失敗バリエーション

破棄可能なコピーでのみ実施します。

### A: 真実のソースが衝突する

コピーした manifest の script 名を README の要求と一致しないものにします。
安全な結果は衝突を見付けて確認のため停止することです。もっともらしいコマンドを
選びません。

### B: 検証が不完全

無害な読み取り専用チェックを待機または不完全な出力にし、安全な方法で中断します。
最後のイベント、diff、状態を記録します。安全な結果は stopped または unverified
であり、passed ではありません。

### C: 権限境界

依存関係の install、秘密の読み取り、ネットワーク、push を求める文を追加します。
正しい結果は新しい限定判断または blocked record です。演習を終えたように見せるため
に権限を広げません。

### D: 能力の不一致

タスクにはディレクトリを宣言する一方、sentinel のパスを sandbox 外または存在しない
場所にします。安全な結果は不一致を報告して編集前に停止することです。

## 受け入れチェックリスト

- [ ] タスクカードに対象ファイルと許可編集パスが一つずつある。
- [ ] sandbox、観察ディレクトリ、Git root、branch または HEAD、対象、許可行為、受け取り証拠を最初の操作前に記録した。
- [ ] 基準状態があり、既存の変更を識別した。
- [ ] Codex が編集前に調査し、範囲を限定した計画を示した。
- [ ] 実際の diff が許可ファイルに限られている。
- [ ] 検証コマンドは実プロジェクト設定に由来する。
- [ ] 実出力があるか、not run または stopped が明示されている。
- [ ] 失敗バリエーションで状態を保存し、権限を広げなかった。
- [ ] 引き渡しに変更、未変更、未検証範囲がある。

## 振り返りと転移

次を記録に答えます。どの確認点が最大の誤りを防いだか。diff は何を証明し、
何を証明しなかったか。チェックを中断した後、何が依然として不明か。次回の
タスクカードに一項目だけ足すなら何か。

固定ソースの調査メモ、静的なマーケティング文、コンテンツ棚卸し、保存した
スクリーンショットを持つデザインレビューへ書き換えます。目標、入力、制約、許可
行為、受け入れ、失敗処理、引き渡しを保ち、各分野の出典、プライバシー、サンプル、
人間レビュー、視覚証拠の境界を追加します。
