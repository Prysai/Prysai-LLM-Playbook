# 实验 008：把一个大话题收窄为可回答的研究问题

## 学习目标

研究质量在写第一句正文前就已经被决定。宽泛话题只会鼓励你写摘要；有用的问题会把对象或人群、时间范围、要支持的决策和可接受的证据说得足够具体，让审阅者能够提出质疑。

## 准备

选择一个公开、低风险的话题。排除个人数据以及法律、医疗或金融建议。准备一个当前可访问的一手或权威来源，以及一个权威性或可访问性不确定的候选来源。做笔记前先记录 URL 和访问日期。

## 任务与实验

写出三个候选问题。每个问题都记录：

```text
这个回答支持什么决策：
对象或人群：
时间范围：
包含 / 排除：
需要的来源类别：
答案形状：
停止条件：
```

选出其中一个，并说明另外两个为什么太宽、太模糊，或无法用允许的证据回答。写作前先建立来源计划。产品行为、政策、标准和统计数据优先使用一手来源；二手来源可以用于定位或比较，但不能悄悄替代一手记录。

创建下表：

| 主张 | 来源 | 访问日期 | 直接支持 | 推断 | 限制 | 状态 |
|---|---|---|---|---|---|---|

状态只能是 `supported`、`partial`、`disputed`、`unknown` 或 `out_of_scope`。只有当每个重要句子都有一行记录，或被清楚标注为分析时，才开始起草。最后写下：哪一个最小的来源或实验能减少目前最重要的不确定性。

## 先写问题卡，再打开搜索或模型

假设你想知道“某个 LLM 是否适合做资料整理”。这还不能直接搜索，更不能直接问模型“哪个最好”。先把它缩成一张卡：

```text
决策：为一份公开的读书会资料，是否尝试用模型先做标题和要点目录？
对象：一份已经公开、没有个人资料的 Markdown 文档。
时间：只看今天能访问的官方产品说明；不比较价格或长期质量。
来源：一份官方产品文档 + 一份明确标为用户经验的公开讨论。
排除：不推断隐私、准确率、团队效率，也不使用搜索摘要作为证据。
停止：官方资料打不开，或两个来源谈的不是同一入口时，结论停在 unknown。
```

然后才可请模型做一件受限的事：**“根据这张问题卡，列出我还缺什么证据，并把每条可能主张放入支持、推断或未知；不要替我搜索、引用或下结论。”** 它的回答是研究计划草稿，不是来源。你自己打开来源、记录位置与日期，再决定表中的状态。

这个顺序让“AI 帮我搜资料”变成可检查的合作：模型帮助暴露问题与缺口，来源支撑事实，最后由你说明结论的范围。

## 要保留的证据

保留原始话题、三个候选问题、选择理由、来源计划、摘录或精确位置、访问日期、主张表、草稿和限制部分。单独一个 URL 不能证明来源在访问当天说了什么。

项目为本实验准备了一份完全离线、冻结的维护者参考夹具：其中有当前来源、与范围相符但过期且冲突的来源、无法访问的来源记录，以及伪造引用候选。第一份简介故意过度声称支持，必须失败；修正后的简介必须收窄决策、保留分歧和未知项、拒绝不合格来源，并记录停止回执才能通过。

该维护者运行使用合成输入，是确定性的实现证据；它没有使用模型、浏览网页、测试学习者，也没有证明迁移或真实研究质量。因此本实验仍为 `draft`，学习者与迁移运行仍为 `not_run`。

## 失败案例

加入一个打不开、面对不同人群，或提出强结论却没有展示方法的来源。正确反应是将受影响的主张标为 `unknown`、`partial` 或 `out_of_scope`，降低结论强度，并写出替代检查。不要根据标题、搜索摘要或自信措辞重建缺失事实。

## 验收标准

- [ ] 最终问题写明范围、决策、证据类别和停止条件。
- [ ] 每项重要主张都对应精确来源位置和访问日期。
- [ ] 直接支持、推断、分歧和未知项始终分开。
- [ ] 薄弱来源夹具会降低信心，不会产生编造的支持。
- [ ] 没有发生私密数据使用、未授权外联、购买、提交或发布。
- [ ] 结论说明什么证据能够改变它。

## 复盘与迁移

在另一个领域重复该协议。哪一项收窄约束带来最大的改善？哪个来源看似有用，却无法支持实际主张？哪些仍然只是待验证的假设？
