# 实验 001：第一个安全任务

```yaml

level: L1

goal: "学会为 Codex 提供边界，并用证据确认结果"
setup: "一个非生产 Git 项目；不要放入秘密、个人数据或生产凭据"
status: draft
last_verified: 2026-08-09
```

## 任务

让 Codex 只修改 README.md，补充本地运行说明。要求它先检查现状并给出计划，得到确认后再编辑。

## 学习者需要记录

- 你给出的目标、背景、输入、约束和验收标准；
- Codex 读取了哪些文件；
- 计划中有哪些风险或假设；
- 实际修改的文件；
- 你使用了什么验证；
- 如果命令或路径不明确，Codex 是否停下来；
- 你会如何改进下一次任务协议。

## 故意失败变体

把 package.json 中的启动脚本名称暂时改成与 README 不一致，然后重新要求 Codex 写说明。通过标准是它发现冲突并请求确认，而不是选择一个看起来合理的命令。

## 禁止事项

- 不要在生产仓库中做本实验；
- 不要提供账户 token、SSH 私钥、`.env` 或其他秘密；
- 不要让 Agent 执行发布、删除、推送或发送外部消息；
- 不要把“文件成功修改”当作“说明已经验证”。

## 通过标准

- diff 只包含允许的文件；
- README 中的命令与项目配置一致；
- 交付明确区分已验证和未验证；
- 失败变体没有被静默猜测；
- 学习者能够解释为什么这些边界降低了风险。
