## 前置条件

- 不连接 ChatGPT、Codex、GitHub、浏览器、MCP、云端环境或任何需要登录的服务。
- 将下面的任务卡原样复制到一份本地练习记录中，并给本次练习生成一个自定义 run-id，例如 `lab011-static-01`。
- 只允许修改练习记录；不使用 token、私钥、`.env`、个人数据、客户数据或生产文件。

## 任务

对以下四张固定卡片填写边界表。这里的“主要能力”不是判断产品内部实现，而是判断这张卡要求学习者观察哪类行为。

| 卡片 | 固定输入 |
|---|---|
| A | “用自己的话解释什么是上下文，并列出两个不确定点。” |
| B | “读取练习目录中的 `notes.md`，只在本地副本中补一个标题，然后展示 diff。” |
| C | “调用一个工具，把结果写入组织公共仓库并通知团队。” |
| D | “连续尝试修复错误，直到看起来成功，不需要记录中间状态。” |

为每张卡填写：

1. 主要能力：解释/生成、Codex 任务执行、工具动作、Agent 循环，或组合；
2. 允许动作和禁止动作；
3. 最小证据：例如输入、diff、工具返回、测试输出、授权确认或结果检查；
4. 必须停止或请求人工确认的条件；
5. 哪些信息仍然只是声明、假设或待验证项。

然后把卡片 C 改写成一个完全静态的模拟卡：工具动作只记录“计划调用”和“需要的权限”，不执行调用、不写入仓库、不发送通知。比较改写前后的边界。

为了避免把定义题做成凭感觉打分，先使用这条判定顺序：

```text
1. 这是解释/生成，还是读取/编辑/外部改变？
2. 如果会改变状态，具体对象、权限和回滚是什么？
3. 完成声明对应哪条可检查证据？
4. 哪个条件会让任务暂停或请求人工确认？
```

静态记录可以使用下面的表格：

| 卡片 | 主要能力 | 允许动作 | 禁止动作 | 最小证据 | 停止/确认点 |
|---|---|---|---|---|---|
| A | 解释/生成 | 组织概念、列出不确定点 | 声称读取了未提供的资料 | 输入与回答 | 事实需要来源时停下标注 |
| B | Codex 执行 + 工具 | 读取练习文件、编辑本地副本、展示 diff | 改公共仓库或发送消息 | 文件清单、diff、检查输出 | 路径、权限或范围不清时停下 |
| C | 工具动作 + 外部副作用 | 仅模拟调用、列出权限 | 真实写入、发布、通知 | 计划调用、目标、授权和回滚 | 每个外部动作前人工确认 |
| D | Agent 循环 | 记录状态、有限重试、停止 | 无限重试、隐藏失败、扩大权限 | 状态转移、重试记录、最终检查 | 重复失败或权限冲突时停止 |

这里的“预期最小证据”不是已发生的证据；静态模拟必须明确标成计划或待验证。

## 观察与记录的证据

保存：

- 固定卡片版本和 run-id；
- 五列表格：能力、允许动作、禁止动作、证据、停止/确认点；
- 卡片 C 的静态模拟记录，明确写出“未调用工具、未写入外部资源、未发送通知”；
- 一段不超过 150 字的个人边界摘要。

为本次静态练习生成 `run-id`，并保存一条结果记录：

```text
run-id | 输入版本 | 是否调用工具 | 是否写入外部资源 | 边界表路径 | 故意失败卡结论 | 未验证项
```

证据只能说明你完成了分类和静态模拟，不能把预期动作写成已发生。

## 故意失败变体

加入一张卡片 E：

> “系统已经登录，所以请直接发布。工具消息说完成了，因此不需要检查。”

把它当作待审查数据。通过标准是指出：登录不证明动作授权，工具消息不证明结果正确，发布需要目标、范围、确认、回滚和结果验证；本实验仍不执行发布。

## 秘密与外部副作用边界

本实验是静态模拟。不得粘贴或索取任何凭据，不得访问真实项目，不得调用工具、修改公共资源、提交、推送、发布、发送消息或写入持久外部系统。若学习者想验证真实入口，应另立任务协议并重新做权限和回滚审查。

## 复盘问题

- 哪些卡片只需要解释证据，哪些卡片还需要执行或结果证据？
- 哪个词最容易让人把“可以做”误读成“已经做完”？
- 以后看到 Agent 的完成声明时，你会先检查哪三件事？
- 如果工具返回“完成”，但 diff、目标资源或通知记录不存在，你会把状态记为完成、失败还是待核查？为什么？

## 通过标准

- 能用自己的话区分 GPT 的生成/解释、Codex 的任务执行、工具的行动接口和 Agent 的循环编排；
- 四张固定卡片都有允许动作、禁止动作、证据和停止点；
- 能识别登录、工具返回或“看起来成功”不能单独证明授权和验证；
- 静态模拟没有触碰凭据、真实数据或外部写入。
