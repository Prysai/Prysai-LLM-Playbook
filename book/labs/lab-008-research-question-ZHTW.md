# 實驗 008：把一個大話題收窄為可回答的研究問題

## 學習目標

研究質量在寫第一句正文前就已經被決定。寬泛話題只會鼓勵你寫摘要；有用的問題會把物件或人群、時間範圍、要支援的決策和可接受的證據說得足夠具體，讓審閱者能夠提出質疑。

## 準備

選擇一個公開、低風險的話題。排除個人資料以及法律、醫療或金融建議。準備一個當前可訪問的一手或權威來源，以及一個權威性或可訪問性不確定的候選來源。做筆記前先記錄 URL 和訪問日期。

## 任務與實驗

寫出三個候選問題。每個問題都記錄：

```text
這個回答支援什麼決策：
物件或人群：
時間範圍：
包含 / 排除：
需要的來源類別：
答案形狀：
停止條件：
```

選出其中一個，並說明另外兩個為什麼太寬、太模糊，或無法用允許的證據回答。寫作前先建立來源計劃。產品行為、政策、標準和統計資料優先使用一手來源；二手來源可以用於定位或比較，但不能悄悄替代一手記錄。

建立下表：

| 主張 | 來源 | 訪問日期 | 直接支援 | 推斷 | 限制 | 狀態 |
|---|---|---|---|---|---|---|

狀態只能是 `supported`、`partial`、`disputed`、`unknown` 或 `out_of_scope`。只有當每個重要句子都有一行記錄，或被清楚標註為分析時，才開始起草。最後寫下：哪一個最小的來源或實驗能減少目前最重要的不確定性。

## 先寫問題卡，再開啟搜尋或模型

假設你想知道“某個 LLM 是否適合做資料整理”。這還不能直接搜尋，更不能直接問模型“哪個最好”。先把它縮成一張卡：

```text
決策：為一份公開的讀書會資料，是否嘗試用模型先做標題和要點目錄？
物件：一份已經公開、沒有個人資料的 Markdown 文件。
時間：只看今天能訪問的官方產品說明；不比較價格或長期質量。
來源：一份官方產品文件 + 一份明確標為使用者經驗的公開討論。
排除：不推斷隱私、準確率、團隊效率，也不使用搜尋摘要作為證據。
停止：官方資料打不開，或兩個來源談的不是同一入口時，結論停在 unknown。
```

然後才可請模型做一件受限的事：**“根據這張問題卡，列出我還缺什麼證據，並把每條可能主張放入支援、推斷或未知；不要替我搜尋、引用或下結論。”** 它的回答是研究計劃草稿，不是來源。你自己開啟來源、記錄位置與日期，再決定表中的狀態。

這個順序讓“AI 幫我搜資料”變成可檢查的合作：模型幫助暴露問題與缺口，來源支撐事實，最後由你說明結論的範圍。

## 要保留的證據

保留原始話題、三個候選問題、選擇理由、來源計劃、摘錄或精確位置、訪問日期、主張表、草稿和限制部分。單獨一個 URL 不能證明來源在訪問當天說了什麼。

專案為本實驗準備了一份完全離線、凍結的維護者參考夾具：其中有當前來源、與範圍相符但過期且衝突的來源、無法訪問的來源記錄，以及偽造引用候選。第一份簡介故意過度聲稱支援，必須失敗；修正後的簡介必須收窄決策、保留分歧和未知項、拒絕不合格來源，並記錄停止回執才能透過。

該維護者執行使用合成輸入，是確定性的實現證據；它沒有使用模型、瀏覽網頁、測試學習者，也沒有證明遷移或真實研究質量。因此本實驗仍為 `draft`，學習者與遷移執行仍為 `not_run`。

## 失敗案例

加入一個打不開、面對不同人群，或提出強結論卻沒有展示方法的來源。正確反應是將受影響的主張標為 `unknown`、`partial` 或 `out_of_scope`，降低結論強度，並寫出替代檢查。不要根據標題、搜尋摘要或自信措辭重建缺失事實。

## 驗收標準

- [ ] 最終問題寫明範圍、決策、證據類別和停止條件。
- [ ] 每項重要主張都對應精確來源位置和訪問日期。
- [ ] 直接支援、推斷、分歧和未知項始終分開。
- [ ] 薄弱來源夾具會降低信心，不會產生編造的支援。
- [ ] 沒有發生私密資料使用、未授權外聯、購買、提交或釋出。
- [ ] 結論說明什麼證據能夠改變它。

## 覆盤與遷移

在另一個領域重複該協議。哪一項收窄約束帶來最大的改善？哪個來源看似有用，卻無法支援實際主張？哪些仍然只是待驗證的假設？
