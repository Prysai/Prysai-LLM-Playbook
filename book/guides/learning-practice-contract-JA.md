# 学習実践契約

**状態：**`draft`｜**実行証拠：**`not_run`｜**プラットフォーム：**汎用テキストチャットの基準。製品固有の挙動には出典付きアダプターが必要です。

## 問題

整った回答でも答えの漏えいを隠せます。完了した授業でも手がかりへの依存を隠せます。一度の高得点も出題への慣れかもしれません。練習中に目標、許可する補助、課題、評価基準、保存物が変われば、学習者もレビュー担当者も何が示されたのか判断できません。

## 概念

学習実践契約は、指導を始める前に能力と証拠の規則を固定し、形成的な支援と成果の証拠を分けます。

```text
ベースライン → 想起 → 段階的支援 → 学習者による修正
             → 変更した即時確認 → 遅延確認 → 未見の転移
```

モデルは質問、段階的ヒント、誤りの説明、証拠の整理を行えます。しかし励ましや自己採点は独立した学習証拠ではありません。

## 決定

契約は観察可能な粒度で書きます。

```text
[入力/文脈] が与えられたとき、学習者は [時間] 内に [許可された補助] を使い、
[観察可能な行為] を行い、[評価基準の閾値] に達する。
```

受入規則に「理解する」「知る」「学ぶ」「習得する」を使わないでください。ベースライン前に次を固定します。

| 項目 | 必要な決定 |
|---|---|
| 目標能力 | 観察可能な行為、条件、時間、品質閾値 |
| 許可する補助 | 指定した資料、ツール、辞書、ノート、またはなし |
| 答えの漏えい | コーチが何を、どの順序で、いつ明かせるか |
| ベースライン | 固定した課題版、指示、時間、補助、評価基準 |
| 試行 | 元の回答、修正、即時、遅延、転移の試行を保存 |
| 修正台帳 | 誤り、ヒント水準、学習者の修正、規則、未解決項目 |
| 即時の変更例 | 能力は同じで、表面的な詳細だけが実質的に異なる |
| 遅延確認 | 明記した間隔、直後の反復なし、新しい課題 |
| 未見の転移 | 近似コピーではなく、能力に対して新しい変化を含む材料 |
| 採点者 | 固定の評価基準。必要に応じて決定的または独立した確認 |

状態表現は次だけを使います。

- `template_selected`：契約またはプロンプトを選択して保存した。
- `practised`：演習と支援・修正の記録を完了した。
- `demonstrated_on_this_task`：記録済み条件で固定確認が評価基準を満たした。
- `retained_at_[delay]`：指定間隔後の確認が評価基準を満たした。
- `transferred_to_[variation]`：未見の変更課題が評価基準を満たした。

これらはいずれも広い習得、流暢さ、専門性、恒久的保持、未試験条件での成績を意味しません。各ラベルは別々です。今日の転移成功は遅延保持の証拠にはなりません。

## 行動

1. 目標、条件、除外、補助、漏えい方針、評価基準を書く。
2. 例、説明、選択肢、ヒントの前に固定ベースラインを実施する。
3. ベースラインを保存し、支援前に想起を求める。
4. 支援は一段ずつ上げる。誤り箇所を示し、部分的な手がかりを出し、次に解決済み断片を見せる。最高水準を記録する。
5. 学習者本人の修正を求め、回答を黙って置き換えない。
6. 能力と評価基準は保ち、詳細だけを変えた即時課題を行う。
7. 遅延確認と異なる未見転移課題を準備するが、予定済みとは主張しない。可能なら使用前に版を記録する。
8. 固定評価基準で各成果物を採点し、食い違いと未知を平均で消さない。
9. 保存された証拠が支える最も狭い状態だけを出す。

必須演習は低リスクかつ可逆にします。使い捨てのローカル記録で架空または公開材料を使ってください。資格情報、私的データ、実顧客の仕事、外部連絡、本番システム、購入、公開、破壊的操作は使いません。必要なら停止し、別途承認された手順を作ります。

## 証拠

一つのパケットを保存します。

```text
contract_revision | task_revisions | date | surface/model label
target | conditions | allowed_aids | leakage_policy | rubric | scorer
baseline_attempt | hints_used | correction_ledger | corrected_attempt
immediate_changed_attempt | delayed_attempt | transfer_attempt
scores | scorer_disagreement | unknowns | status_claim | claim_limit
```

直後に修正した回答は実践の証拠であり、保持の証拠ではありません。固定確認の合格は `demonstrated_on_this_task`、遅延合格は `retained_at_[delay]`、未見変化例の合格は `transferred_to_[variation]` を支えます。証拠がなければ `not_run` のままにするか、主張しません。

## 失敗

- ベースライン前に理想解を求める。コーチは非漏えい規則を守るか、ベースラインを汚染済みと記録します。
- 授業文を繰り返して「転移」とする。レビュー担当者は近似コピーとして拒否し、実質的に異なる例を求めます。
- 教えた同じモデルに習得を宣言させる。拒否または主張の限定と、採点者依存の開示が必要です。
- 遅延日を逃す。`not_run` を記録し、即時結果から保持を後付けしません。

## 振り返り

最もヒントに依存した結果は何でしたか。本当に新しかった変化は何でしたか。独立した採点者は何に異議を唱えるでしょうか。現在の主張を強める、または反証する最小の次回確認は何でしょうか。

## 受入チェックリスト

- [ ] 目標は条件と閾値を備えた観察可能な行為である。
- [ ] 許可する補助と漏えい規則はベースライン前に固定した。
- [ ] 元の試行、ヒント、修正、得点、未知を保存した。
- [ ] 即時課題は能力を変えずに事例を変えた。
- [ ] 遅延・未見転移は異なり、宣言済みの評価基準を使う。
- [ ] 採点者、依存、食い違いが見える。
- [ ] 状態語が手元の証拠と一致する。
- [ ] 広い習得、流暢さ、専門性を暗示する状態がない。
- [ ] 必須経路に秘密、外部副作用、本番利用がない。
