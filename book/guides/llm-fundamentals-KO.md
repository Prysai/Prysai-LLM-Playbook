# LLM이란 무엇인가: 유용한 답변 뒤의 여러 층

**단위:** `core-llm-boundaries`
**상태:** `candidate`. **실행 상태:** `not_run`.
**시간:** 약 25분. **선행 조건:** 없음. Codex, Git, 유료 계정, 도구가 필요하지 않습니다.

이것은 Playbook의 기초입니다. 플랫폼을 고르고, 파일을 연결하고, Skill을 설치하거나,
Agent에게 행동을 맡기기 전에 무엇이 일어나는지 작은 모델로 설명할 수 있어야 합니다.
목표는 약어 암기가 아닙니다. 어떤 층이 주장을 만들었는지, 어떤 층이 외부에서 행동할 수
있는지, 무엇이 결과를 확인할 수 있는 영수증인지 구분하는 것입니다.

새 AI 기능을 보면 네 가지를 물어보세요.

1. **모델은 무엇을 생성하도록 요청받았는가?**
2. **이번 요청에 실제로 제공된 문맥은 무엇인가?**
3. **모델 밖에서 무언가를 보거나 바꿀 수 있는 제품 또는 도구가 있는가?**
4. **다른 사람이 주장을 확인할 수 있는 영수증은 무엇인가?**

답하지 못하는 항목이 있으면 결과를 초안이나 가설로 보관하세요. 자신 있어 보이는
설명으로 빈칸을 채우지 마세요.

## 남겨야 할 결과

끝에 자신의 말로 설명 카드를 쓰고 두 가지 경계 판단을 남깁니다. 카드에는 다음이
보여야 합니다.

- 텍스트 LLM이 한 요청에 제공된 문맥에서 어떻게 생성하는가;
- 안전한 첫 과제에 필요한 **LLM**, **토큰**, **문맥**, **프롬프트**, **도구**,
  **MCP**, **Agent**, **Skill**의 최소 의미;
- 유창한 문장이 그 자체로 참이라는 증거가 아닌 이유;
- 모델, 채팅 제품, 외부 도구에 속하는 부분.

범위를 정한 설명 과제이지 제품 전체 기능 시험이 아닙니다. 플랫폼별 절차는 뒤에서
다룹니다.

## 0.1 한 문장 작업 모델

현대 텍스트 LLM은 토큰의 시퀀스를 추정하고 생성하는 모델입니다. 많은 자기회귀 모델은
사용 가능한 문맥에서 다음 토큰을 예측하며 한 단계씩 생성합니다. 추가 학습과 제품
계층도 배포된 응답의 형태를 바꿉니다.

이는 유용한 작업 모델이지만 LLM이라 불리는 모든 언어·멀티모달·배포 시스템을 완전히
정의하지는 않습니다. 텍스트 이어 쓰기, 번역, 요약, 필드 추출, 초안 작성이 가능한
이유를 설명할 수 있지만 모든 출력이 사실이거나 제품 간 능력이 같다는 뜻은 아닙니다.
**예측**은 생성 방법을 말할 뿐, 모델이 세계를 확인했거나 사람을 이해했거나 행동을
허가했다는 뜻이 아닙니다. 유용한 답도 검사해야 합니다.

## 0.2 여덟 용어를 각자의 자리에 두기

다음은 안전한 입문에 필요한 작업 정의입니다. 공급업체마다 정확한 용법은 다를 수 있습니다.

| 용어 | 최소한의 유용한 뜻 | 추론하지 말 것 |
|---|---|---|
| **LLM / 모델** | 학습한 매개변수가 입력 문맥에서 응답을 생성합니다. 기반 모델은 텍스트를 생성하고 제품은 다른 층을 더할 수 있습니다. | 검증된 데이터베이스, 사람, 권한 있는 행위자라는 뜻. |
| **토큰 / 토크나이저** | 토크나이저는 텍스트와 모델별 토큰 ID를 오갑니다. 토큰은 단어 전체보다 단어 조각인 경우가 많습니다. | 토큰·단어·문자 사이의 보편적 비율. 한도, 비용, 속도는 제품에 따라 다릅니다. |
| **문맥** | 한 요청에 제공된 정보입니다. 지시, 대화, 자료, 검색된 구절, 도구 결과가 포함될 수 있고 제품이 검색, 파일, 기억, 도구를 더할 수 있습니다. | 문맥의 모든 정보가 참이거나 관련 있거나 제대로 사용된다는 뜻. |
| **context window** | 특정 모델이나 제품이 한 번에 처리하는 토큰화된 입력·출력의 **유한한 context window**입니다. | 모델, 계정, 화면마다 같은 수치라는 뜻. 창이 커도 출처 선택과 확인은 필요합니다. |
| **프롬프트** | 목표, 제약, 원하는 답변 형식을 포함해 시스템에 주는 요청과 자료입니다. | 마법 주문이라는 뜻. 길다고 자동으로 좋아지지 않습니다. |
| **사용자 프롬프트 / 시스템·개발자 지시** | 사용자는 당장의 과제를 말하고 호스트는 보이지 않는 더 높은 우선순위 지시를 더할 수 있습니다. | 사용자가 호스트 규칙을 덮어쓰거나 제품마다 같은 층을 볼 수 있다는 뜻. |
| **도구 / 검색·검색증강** | 호스트는 계산기, 검색, 파일 읽기, 데이터베이스 같은 외부 능력을 제공할 수 있습니다. 모델은 호출을 제안하고 호스트나 도구가 실행합니다. | 제안, 버튼, 요약만으로 외부 행동이나 결과의 정확성이 증명된다는 뜻. |
| **MCP / Agent / Skill** | MCP는 호환 호스트를 문맥·도구에 연결합니다. Agent는 관찰 가능한 여러 단계의 루프이고 Skill은 재사용 절차입니다. | 호환성, 신뢰, 숨은 추론, 권한 또는 루프 완료가 자동으로 보장된다는 뜻. |

두 가지 구분을 계속 사용하세요.

1. **능력, 권한, 증거는 다릅니다.** 행동을 제안할 수 있는지, 시도할 권한이 있는지,
   실제로 끝났는지는 서로 다른 관찰입니다.
2. **위 층이 아래 층의 문제를 고치지는 않습니다.** 검색은 오래된 페이지를 반환할 수
   있고, 파일 도구는 잘못된 파일을 읽을 수 있으며, Agent는 일찍 멈추고 Skill은
   부적절한 규칙을 가질 수 있습니다. 각 층을 따로 확인하세요.

### 자주 섞이는 말

**문맥은 영구 기억이 아닙니다.** 호스트가 이번 요청에 제공한 것이 문맥입니다. 대화
기록, 설정, 파일, 임베딩을 저장해 나중에 검색하는 기능은 별도의 저장·검색 결정입니다.
저장된 항목은 낡거나 불완전하거나 이번 입력에 없을 수 있으니 이번에 무엇이 제공됐는지
물어보세요.

**검색은 증거 경로이지 진실 보장이 아닙니다.** 검색이나 RAG는 문맥에 넣을 구절을
고릅니다. 최선의 자료를 놓치거나 복사본·옛 버전을 고를 수 있습니다. URL, 날짜,
주장과 출처의 대응을 남기세요. 창이 커져도 모든 구절이 맞게 되지는 않습니다.

**프롬프트는 계약이지 주문이 아닙니다.** 첫 요청에는 결과, 시작 자료, 제약, 답변 형식,
확인 방법, 중지선을 적습니다. 인용한 문서에는 신뢰하지 말아야 할 지시가 들어 있을 수
있으므로 명시적으로 지시로 만들지 않는 한 제공된 글은 데이터로 다룹니다.

**도구 호출에는 두 주체가 있습니다.** 모델은 구조화된 호출을 제안하고 호스트가 허용
여부를 판단하며 도구가 실행합니다. 대상, 권한, 의도한 효과, 반환 결과, 읽어온 증거를
기록하세요. 답변에 도구 이름이 나오는 것만으로는 영수증이 아닙니다.

**MCP는 통합 문제를 좁히지만 거버넌스를 없애지 않습니다.** 인증, 서버 구현, 승인,
네트워크 범위, 데이터 반출, 결과 확인은 별도의 결정입니다. “MCP 지원”은 안전이나
무제한 접근을 뜻하지 않습니다.

**Agent는 검사 가능한 루프이지 사람이 아닙니다.** intake, 계획, 제안, 승인·거절,
결과, 검증, 재시도, 인계, 중지라는 보이는 상태만 설명하세요. 숨은 사고 과정을 안다고
말하지 마세요. 글이 끝났다고 외부 작업이 끝난 것은 아닙니다.

**Skill은 방법 묶음이지 권한 부여가 아닙니다.** 적용 조건, 필요한 입력, 금지 행동,
중지 조건, 반환할 증거를 적어야 합니다. 지시를 로드해도 파일, 터미널, 브라우저,
계정, 게시 권한이 생기지 않습니다.

## 0.3 한 요청에서 일어나는 일

간단한 텍스트 교환에는 다음 관찰 모델이면 충분합니다.

```text
내 요청 + 제공한 자료
          ↓
호스트가 지시와 문맥을 조립
          ↓
모델이 토큰 시퀀스를 생성
          ↓
호스트가 글을 보여 주거나 도구 호출을 제안
          ↓
호스트와 권한이 허용할 때만 도구 실행
          ↓
사람이 글, 결과, 한계를 확인
```

모델의 문장은 실행되지 않은 호출도 설명할 수 있습니다. 도구 이벤트, 반환 데이터,
파일 diff, 명령 출력 같은 영수증을 확인한 뒤에만 행동을 완료했다고 부르세요.

Agent에서는 각 경계에서 반복합니다.

```text
상태 관찰 → 행동 제안 → 권한 확인 → 실행
→ 결과 읽기 → 수락 조건 확인 → 계속·인계·중지
```

시간 초과나 중단 뒤 상태가 불명확하면 전송, 게시, 삭제, 결제, 계정 변경을 일으킬 수
있는 행동을 맹목적으로 반복하지 마세요. 대상을 먼저 읽거나 사람에게 불확실성을 넘기세요.

## 0.4 역사는 보장이 아니다

2017년 *Attention Is All You Need*는 이후 연구에 영향을 준 Transformer 아키텍처를
소개했습니다. Attention은 입력 시퀀스의 토큰 관계를 다루기 쉽게 했지만 문맥을 무한하게
만들지는 않았습니다. 현재 제품에는 데이터 선택, 최적화, 지시 조정, 안전 제어, 검색,
도구, 화면도 들어갑니다. 역사적 이름 하나로 현재 서비스의 모든 동작을 설명할 수 없습니다.

## 0.5 LLM만으로 확립할 수 없는 것

모델은 제공한 글의 재작성, 개념 설명, 개요, 필드 추출, 테스트할 코드 제안처럼 분명한
텍스트 입출력을 도울 수 있습니다. 유용한 패턴이지 보장은 아닙니다.

적절한 출처나 도구가 없으면 인용이 실제인지, 웹사이트가 아직 있는지, 현재 주장이 맞는지,
제안한 행동이 일어났는지를 확립하지 못합니다. 기반 모델은 학습 데이터와 *일관된*
텍스트를 생성합니다. 제품은 검색, 검색·검색증강, 파일, 기억, 도구를 더할 수 있지만
자료가 오래됐거나 불완전하거나 틀릴 수 있습니다. **원문과 날짜를 확인하세요.**

붙여 넣기, 업로드, 연결을 켜기 전에 **무엇이 현재 화면을 떠날 수 있는지와 누가 이를 허가했는지**
확인하세요. 그럴듯한 초안을 증거 없이 결제, 게시, 삭제, 계정 변경, 믿음으로 바꾸지 마세요.

학습은 사용 전에 매개변수를 만들고 현재 요청은 새로운 문맥을 제공합니다. cutoff는 실시간
출처가 아니므로 최신 주장은 자료가 필요합니다. **cutoff만으로 판단하지 말고**, 검색·기억·
파일·도구 각각의 최신성과 권한을 확인하세요.

## 0.6 5분 경계 점검

텍스트만 관찰합니다. 검색, 파일 업로드, 개인정보를 사용하지 마세요.

먼저 모델에게 묻지 말고 다음을 완성하세요.

> 시립 도서관은 오늘 오후 6시에 문을 닫습니다.

가능한 이어 쓰기 두 개를 적고 어느 것이 문장에 근거하는지 표시하세요. 정답은 추가 시간,
이유, 연락처가 문장에 없다는 것입니다. 그럴듯함은 증거가 아닙니다.

그다음 이 가상의 공지만 보내세요.

```text
공지: "클럽은 화요일 오후 6시에 모입니다. 노트를 가져오세요. 방 번호는 나중에
확정합니다."

과제: 새 구성원을 위해 두 문장으로 다시 쓰세요. 적힌 사실은 모두 보존하고 빠진 내용은
[알 수 없음]으로 표시하세요. 그다음 보존한 사실을 나열하세요.
확인: 각 문장을 공지와 대조하세요. 방 번호, 회비, 연락처, 약속, 새 시간을 추가하지 마세요.
중지: 검색·전송·게시를 하지 말고 모르는 내용을 추측하지 마세요.
```

첫 요청과 첫 답변을 저장하고 다음을 확인합니다.

| 확인 | 질문 |
|---|---|
| 출처 일치 | 모든 사실을 공지의 어느 부분에서 가리킬 수 있나요? |
| 형식 | 두 문장과 보존한 사실 목록을 반환했나요? |
| 미상 | 방 번호를 만들지 않고 `[알 수 없음]`으로 남겼나요? |

번호를 지어냈다면 그 주장을 `FAIL`로 표시하세요. 한 번의 답변으로 모델 전체를 단정하지
마세요. 이 연습은 한 과제에서 보이는 한 가지 실패를 관찰합니다.

또한 **“시립 도서관은 오늘 오후 6시에 문을 닫습니다”**의 현재 진위를 찾아보기 전에
텍스트 모델만으로 확립할 수 있는 것을 적어 보세요. 현재 사실에는 출처가 필요합니다.

### 세 가지 제한된 관찰

앞의 점검은 작은 시연일 뿐이며, 학습자나 모델이 모든 과제에서 같은 방식으로
행동한다는 증거가 아닙니다. 계정, 개인 데이터, 도구 또는 네트워크 요청 없이 같은
경계를 연습하려면 다음의 허구 기록 프로토콜을 사용하세요(전체 본문은 현재 영어로만
제공됩니다).

- [Context change and unknowns(문맥 변화와 미상)](../../evals/candidates/core-course-v1/observations/context-change-and-unknowns.md) — 두 입력 버전을 비교하고 각 주장을 `PASS`, `FAIL`, `UNSURE`로 표시하며 방 번호는 미상으로 남깁니다.
- [First-request contract and controlled repeat(첫 요청 계약과 통제된 반복)](../../evals/candidates/core-course-v1/observations/first-request-contract.md) — 답변 전에 목표, 자료, 제약, 답변 형식, 중지 조건을 씁니다. 안전한 텍스트 화면이 있으면 같은 요청을 두 번 더 반복하고 공통점과 차이를 기록합니다.
- [Tool boundary, authority, and evidence(도구 경계·권한·증거)](../../evals/candidates/core-course-v1/observations/tool-boundary-authority-evidence.md) — 제안된 행동, 부여된 권한, 도구 실행, 읽어 온 증거를 분리합니다.

각 프로토콜은 단서를 받기 전에 첫 산출물을 보관하고 도움, 미상, 중지 규칙을 기록하게
합니다. 상태는 `candidate / not_run`입니다. 나중에 실행하더라도 지정한 과제·조건·평가
기준만 설명할 수 있으며, 과정의 효과, 프롬프트 우월성, 모델 품질, 기억 유지, 일반적
전이, 플랫폼 동등성 또는 프로덕션 준비를 입증할 수 없습니다.

### 어떤 모델에서도 쓰는 첫 요청 형식

낮은 위험의 실제 과제를 시작할 때 다음 여섯 줄을 채우세요.

```text
결과: [관찰 가능한 결과 하나]
시작 문맥: [내가 제공하는 사실 또는 글]
허용된 도움: [모델이 해도 되는 일]
제약: [그대로 유지할 것과 하면 안 되는 것]
답변과 확인: [확인할 형식과 확인 방법]
중지: [입력·권한·출처·증거가 없으면 멈출 조건]
```

처음에는 허구나 민감하지 않은 문맥을 사용하고 도구보다 초안·분류를 먼저 요청하세요.
첫 요청과 답변을 보관해야 나중의 수정이 문제를 고쳤는지 숨겼는지 구분할 수 있습니다.

## 0.7 이 단위의 완료 확인

이 페이지를 베끼지 말고 다음 카드를 자신의 말로 작성하세요.

```text
내 설명:

LLM 경계:
토큰 또는 문맥 경계:
프롬프트 / 제품 / 도구 경계:
문맥 / 기억 경계:
도구 / MCP / Agent / Skill 경계:
유창한 답변이 틀릴 수 있는 이유 하나:

판단 1 (근거 있음 / 없음):
증거:
판단 2 (모델 / 제품 / 도구):
증거:
```

`0`은 유창한 글을 증거로 취급하거나 모델에 권한을 부여하고 증거가 없는 상태입니다.
`1`은 문맥 기반 생성을 말하지만 경계나 확인 이유가 흐린 상태입니다. `2`는 자신의 말로
모델과 제품·도구를 나누고 이 과제에서 확인해야 하는 이유를 말하는 상태입니다.

카드, 첫 답변, 아직 모르는 것을 한 문장으로 저장하세요. 이 자기 점검만으로 학습 결과나
수료를 선언하지 마세요. 다음은 [1장: Codex를 믿기 전에 GPT를 이해하라](../chapters/01-gpt-and-codex-KO.md)입니다.

남겨야 합니다. 이 페이지는 최고의 모델, 보편적 동작, 학습 향상, 유지, 전이, production-ready를
주장하지 않습니다. 번역은 `candidate`이며 독립 언어 검토와 독자 실행이 남아 있습니다.
