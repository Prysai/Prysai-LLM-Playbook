# LLMとは何か：役に立つ回答の背後にある層

**ユニット:** `core-llm-boundaries`
**状態:** `candidate`。**実行状態:** `not_run`。
**時間:** 約25分。**前提:** なし。Codex、Git、有料アカウント、ツールは不要です。

これはPlaybook全体の土台です。プラットフォームを選び、ファイルを接続し、Skillを
インストールし、Agentに行動を頼む前に、何が起きているかを小さく説明できるように
なりましょう。暗記するのではなく、どの層が主張を作ったのか、どの層が外部に作用
できるのか、どんな記録があれば確認できるのかを見分けます。

新しいAI機能を見たら、次の4問を聞いてください。

1. **モデルは何を生成するよう求められているか。**
2. **このリクエストに実際に渡されたコンテキストは何か。**
3. **モデルの外側を観察・変更できる製品やツールはあるか。**
4. **別の人が主張を確認できるレシートは何か。**

答えられない項目があれば、結果を草稿または仮説として扱ってください。聞こえの
よい確信で空白を埋めないでください。

## 残す成果物

最後に、自分の言葉で説明カードを書き、2つの境界判断を残します。カードには、

- テキストLLMが1回のリクエストに与えられたコンテキストから生成する仕組み;
- 安全な最初のタスクに必要な **LLM**, **token**, **コンテキスト**, **prompt**,
  **tool**, **MCP**, **Agent**, **Skill** の最小の意味;
- 流暢な文章だけでは真実の証拠にならない理由;
- モデル、チャット製品、外部ツールに属する部分

が見えるようにします。これは限定された説明課題であり、AI製品の全機能試験では
ありません。製品ごとの操作は後で扱います。

## 0.1 一文の作業モデル

現代のテキストLLMは、tokenの系列を推定し生成するモデルです。多くの自己回帰型
モデルは、利用可能なコンテキストから次のtokenを予測しながら一歩ずつ生成します。
追加学習と製品の層も、配備された応答の形を変えます。

これは役に立つ作業モデルであり、LLMと呼ばれるすべての言語・マルチモーダル・
配備システムの完全な定義ではありません。テキストの続き、翻訳、要約、項目抽出、
下書きが可能な理由は説明できますが、出力が必ず真実であることや、製品の能力が
同じであることは意味しません。

「予測」は生成方法を表す言葉です。モデルが世界を確認した、人を理解した、行動を
許可した、という意味ではありません。役に立つ回答でも検査が必要です。

## 0.2 8つの用語をそれぞれのレーンに置く

以下は安全な入門に必要な作業定義です。すべてのベンダーが同じ意味で使うとは限り
ません。

| 用語 | 最小限の意味 | 推論してはいけないこと |
|---|---|---|
| **LLM / model** | 学習したパラメータが入力コンテキストから応答を生成する。基盤モデルはテキストを生成し、製品は別の層を加えられる。 | 検証済みデータベース、人間、権限を持つ実行者。 |
| **token / tokenizer** | tokenizerはテキストをモデル固有のtoken IDに変換し、戻す。tokenは単語全体ではなく語の断片であることが多い。 | tokenと単語・文字の普遍的な比率。上限、料金、速度は製品とtokenizerで変わる。 |
| **コンテキスト** | 1回のリクエストで利用できる情報。指示、会話、提供資料、検索された断片、あればツール結果を含む。製品は検索、retrieval、ファイル、記憶、ツールを追加できる。 | 含まれる情報が正しい、関連する、正しく使われるということ。 |
| **context window** | 特定のモデルや製品が1回に扱えるtoken化された入力と出力の有限量。 | モデル、アカウント、画面をまたいで同じ数字だということ。広い窓でも選択と確認は必要。 |
| **prompt** | 目標、制約、希望する回答形式を含めてシステムに渡す依頼と資料。 | 呪文。長いpromptほどよいということ。 |
| **user prompt / system・developer instruction** | ユーザーは当面の課題を書く。ホストは見えない高優先度の指示を加えることがある。 | ユーザーがホストの規則を上書きできること、製品間で同じ層が見えること。 |
| **tool / retrieval** | ホストは計算機、検索、ファイル読み取り、DBなど外部能力を提供できる。モデルは呼び出しを提案できるが、実行するのはホストやツール。 | 提案、ボタン、要約だけで外部操作や正しさが証明されること。 |
| **MCP / Agent / Skill** | MCPは対応ホストをコンテキストやツールに接続するプロトコル。Agentは観察可能な多段ループ。Skillは再利用できる手順。 | 互換性、信頼、隠れた推論、権限、ループ完了が自動で保証されること。 |

次の2つの区別を持ち歩きます。

1. **能力、権限、証拠は別物です。** 行動を提案できる、試す権限がある、実際に
   完了した、は別々の観察です。
2. **上の層は下の層の問題を直しません。** 検索は古いページを返し、ファイル
   ツールは誤ったファイルを読み、Agentは途中で止まり、Skillは不適切な規則を
   含むことがあります。各層を個別に確認してください。

### 混同しやすい用語

**コンテキストは永続メモリではありません。** ホストが今回のリクエストに渡した
ものがコンテキストです。履歴、設定、ファイル、embeddingを保存して後から検索する
機能は別の保存・検索判断です。保存された項目は古い、欠けている、今回の入力外で
ある可能性があります。今回何が渡ったかを確認してください。

**Retrievalは証拠への道であって真実の保証ではありません。** 検索やRAGはコンテキ
ストに加える断片を選びます。最良の資料を逃したり、コピーや古い版を選ぶことも
あります。URL、日付、主張と資料の対応を残します。窓が広くても正しさは増えません。

**Promptは契約であって呪文ではありません。** 最初の依頼には結果、開始資料、制約、
回答形式、確認方法、停止条件を明記します。引用した文書には信頼できない指示が
含まれる可能性があるため、明示的に指示にしない限り提供文はデータとして扱います。

**Tool callには2つの作者がいます。** モデルは構造化された呼び出しを提案し、ホスト
が許可を判断し、ツールが実行します。対象、権限、意図した効果、返却結果、読み戻し
を記録してください。回答にツール名が出ただけではレシートになりません。

**MCPは統合問題を狭めますが、ガバナンスを消しません。** 認証、サーバー実装、承認、
ネットワーク範囲、データ送信、結果確認は別の判断です。「MCP対応」は安全や無制限
アクセスを意味しません。

**Agentは検査できるループであり、人ではありません。** intake、計画、提案、承認・
拒否、結果、検証、再試行、引き継ぎ、停止という見える状態を説明します。隠れた
chain of thoughtを知っているとは言わないでください。文章の終了は外部作業の完了を
意味しません。

**Skillは方法のパッケージであり、能力付与ではありません。** 適用時、必要入力、
してはいけないこと、停止条件、返す証拠を記述します。手順をロードしても、ファイル、
端末、ブラウザ、アカウント、公開権限は付与されません。

## 0.3 1回のリクエストで起きること

単純なテキスト交換は、次の観察モデルで十分です。

```text
あなたの依頼 + 渡した資料
          ↓
ホストが指示とコンテキストを組み立てる
          ↓
モデルがtoken列を生成する
          ↓
ホストが文章を表示するかtool callを提案する
          ↓
許可と権限があればツールが実行される
          ↓
人が文章、結果、限界を確認する
```

モデルの文章は、実行されていない呼び出しを説明できます。toolイベント、返却データ、
ファイルdiff、コマンド出力などのレシートを確認してから完了と呼びます。

Agentでは各境界で繰り返します。

```text
状態を観察 → 行動を提案 → 権限を確認 → 実行
→ 結果を読み戻す → 受入条件を確認 → 継続・引き継ぎ・停止
```

タイムアウトや中断後に状態が不明なら、送信、公開、削除、支払い、アカウント変更に
つながる操作を盲目的に再実行しないでください。対象を読み直すか、人に不確実性を
渡します。

## 0.4 歴史は保証にしない

2017年の *Attention Is All You Need* は、後の言語モデル研究に影響したTransformer
アーキテクチャを紹介しました。Attentionは入力系列中のtoken同士の関係を扱いやすく
しましたが、コンテキストを無限にはしません。現在の製品にはデータ選択、最適化、
instruction tuning、安全制御、retrieval、ツール、画面も加わります。歴史上の名前
だけで現在のサービスの挙動を説明することはできません。

## 0.5 LLMだけでは確立できないこと

モデルは、渡した文章の書き換え、概念説明、アウトライン、項目抽出、テスト可能な
コード案など、明確なテキスト入出力を手伝えます。これは便利な型であり保証では
ありません。

適切な資料やツールなしには、引用が実在するか、サイトがまだ存在するか、現在の主張
が真か、提案した操作が起きたかを確立できません。基盤モデルは学習データと*整合する*テキストを生成します。検索を加えた製品でも資料は古い、
不完全、誤りであり得ます。**原典と日付を確認してください。**

貼り付け、アップロード、接続を有効にする前に、**何が現在の画面から出るのか、誰が許可したのか**を確認します。もっともらしい下書きを、証拠なしで支払い、公開、削除、
アカウント変更、信念に変えないでください。

実用モデルには**有限のcontext window**があります。学習は使用前にパラメータを形作り、現在のリクエストは新しいコンテキストを渡します。
カットオフはライブな資料ではありません。現在の主張には資料が必要であり、
**カットオフだけで判断せず**、検索、記憶、ファイル、ツールそれぞれの鮮度と権限を
確認します。

## 0.6 5分の境界チェック

テキストだけの観察です。検索、ファイルアップロード、個人情報は使いません。

まずモデルに聞かず、次の文を完成させます。

> 市立図書館は今日18時に閉館する。

2つの続き候補を書き、どれが文に支えられるか印を付けます。正しい答えは、追加の
部屋番号、理由、連絡先のどれも与えられていないことです。もっともらしさは証拠では
ありません。

次の架空の通知だけを送ります。

```text
通知: 「クラブは火曜日18:00に集まります。ノートを持ってきてください。部屋番号は
後で確認します。」

課題: 新しい参加者向けに2文で書き直してください。書かれた事実をすべて保ち、
不足する内容は[不明]と示してください。その後、保った事実を列挙してください。
確認: 各文を通知と照合してください。部屋番号、料金、連絡先、約束、新しい時刻を
追加しないでください。
停止: 閲覧、送信、公開をせず、不明な内容を推測しないでください。
```

最初の依頼と回答を保存し、次を確認します。

| 確認 | 問い |
|---|---|
| 原典一致 | それぞれの事実を通知のどこに指せますか。 |
| 形式 | 2文で、保った事実の一覧も返しましたか。 |
| 不明 | 部屋番号を作らず`[不明]`のままにしましたか。 |

番号を作ったら、その主張を`FAIL`にします。1回の結果でモデル全体を断定しません。
これは1つの課題で見えた1つの失敗例です。

もう一つ、**「市立図書館は今日18時に閉館する」**という文について、調べる前に
テキストモデルだけで何を確立できるかを書きます。現在の真偽には資料が必要です。

### 3つの限定された観察

上の確認は小さなデモであり、学習者やモデルがどの課題でも同じように
振る舞う証拠ではありません。アカウント、個人データ、ツール、ネットワーク要求を
使わずに同じ境界を練習するには、次の架空記録プロトコルを使います（本文は現在
英語のみです）。

- [Context change and unknowns（コンテキストの変化と不明点）](../../evals/candidates/core-course-v1/observations/context-change-and-unknowns.md) — 2つの入力版を比較し、各主張を `PASS`、`FAIL`、`UNSURE` に分け、部屋番号は不明のままにします。
- [First-request contract and controlled repeat（最初の依頼の契約と管理された反復）](../../evals/candidates/core-course-v1/observations/first-request-contract.md) — 回答の前に目的、資料、制約、回答形式、停止条件を書きます。安全なテキスト画面がある場合は同じ依頼を2回追加で行い、共通点と相違点を記録します。
- [Tool boundary, authority, and evidence（ツールの境界、権限、証拠）](../../evals/candidates/core-course-v1/observations/tool-boundary-authority-evidence.md) — 提案された行動、付与された権限、ツールの実行、読み戻しの証拠を分けます。

各プロトコルは、手がかりを受ける前に最初の成果物を保存し、支援、不明点、停止規則を
記録します。状態は `candidate / not_run` です。将来の実行が示せるのは指定した課題、
条件、評価基準だけであり、コースの有効性、プロンプトの優位性、モデル品質、保持、
一般的な転移、プラットフォーム間の同等性、または本番利用の準備を証明するものではありません。

### どのモデルでも使える最初の型

低リスクの実作業に進むときは、次の6行を埋めます。

```text
結果: [観察できる結果を1つ]
開始コンテキスト: [私が渡す事実または文章]
許可する支援: [モデルに許すこと]
制約: [保つこと、起こしてはいけないこと]
回答と確認: [確認できる形式と確認方法]
停止: [入力、権限、資料、証拠がなければ止まる条件]
```

最初は架空または機微でないコンテキストを使い、ツールの前に下書きや分類を頼みます。
依頼と最初の回答を残してください。そうしないと、後の書き直しが直したのか隠した
だけなのか分かりません。

## 0.7 このユニットの完了チェック

このページを写さず、次のカードを自分の言葉で書きます。

```text
私の説明:

LLMの境界:
tokenまたはコンテキストの境界:
prompt / 製品 / toolの境界:
コンテキスト / メモリの境界:
tool / MCP / Agent / Skillの境界:
流暢な回答が誤り得る理由を1つ:

判断1（支えられる / 支えられない）:
証拠:
判断2（モデル / 製品 / ツール）:
証拠:
```

`0`は流暢さを証拠扱いする、権限をモデルに与える、証拠がない状態です。`1`は
コンテキストからの生成に触れるが境界や確認理由が曖昧な状態です。`2`は自分の言葉で
モデルと製品・ツールを分け、この課題で確認が必要な理由を述べる状態です。

カード、最初の回答、まだ不明なことを1文で保存します。この自己チェックだけで学習
成果やコース修了を宣言しないでください。次は[第1章：Codexを信頼する前にGPTを理解する](../chapters/01-gpt-and-codex-JA.md)です。
