# 第 0 课：什么是大语言模型？

**阅读时间：** 约 20 分钟。**状态：** `candidate` · **学习证据：** `not_run`。

这是 Playbook 的第一课。如果你并不真正清楚"大语言模型"（LLM）到底是什么——抛开营销话术不谈——就从这里开始。我们会像教授引入一门新学科那样，逐层搭建一个心智模型：先讲本质，再讲机制，最后讲诚实的边界。本课全部内容都是用通俗语言复述文末列出的公开资料，并不是对任何单一文档的复制。

## 0.1 一句话，然后一幅图

**LLM 是一种预测下一段文本的机器：它接受过海量人类写作的训练，又被进一步调校为遵循指令。**

把这句话变成具体画面：想象你手机上的自动补全功能，只不过它是在一个收录了数百万册图书、文章、代码仓库和对话的文库上训练出来的，并且规模被急剧放大。自动补全只会建议一个词；而 LLM 可以续写一段话、回答问题、翻译、列提纲、调试代码，或者陪你聊下去——因为这些任务都可以改写成"给定到目前为止的文本，接下来是什么？"

这一个简单的想法能解释的事情比你想的更多：

- 为什么 LLM 几乎对任何话题都能写得流畅（它见过海量的文本）；
- 为什么它有时会编造事实（基础模型预测貌似合理的文本，并不会自行查找事实）；
- 为什么聊天产品能做得更多（它可能接入搜索、文件、记忆、检索或工具；每一项都有独立的数据与权限边界）；
- 为什么模型更新后它会变化（训练文本变了）。

对这套机制最直观的现代讲解，是 Grant Sanderson（3Blue1Brown）关于 GPT 与注意力机制的动画系列，文末资料里有链接。如果只打算看一样东西，就看它。

## 0.2 LLM 从哪里来：一条三十年的捷径

语言模型并不是新想法。它的谱系是这样的：

- **1950 年代至 1980 年代——规则与统计。** 早期系统依赖手写的语法规则或简单的词频统计（"如果单词 `bank` 跟在 `river` 后面，它多半指河岸"）。
- **1990 年代至 2010 年代——统计语言模型。** 研究者构建的模型会依据前面几个词，为下一个词赋予一个概率。早期手机键盘和机器翻译靠的就是它们。弱点在于：它们只能看到很短的上下文窗口。
- **2017 年——Transformer。** *Attention Is All You Need* 提出了一种架构：一个 token 可以关注当前可用上下文中的其他 token。它让模型更容易建模和扩展长距离关系，但没有取消上下文长度限制；实际模型仍有有限的上下文窗口。
- **2018 至 2022 年——规模与"预测下一 token"的招数。** 各家公司用同一个目标在巨大语料上训练 Transformer 模型：预测下一个 token（token 大致相当于一个词片段）。数据和算力足够多之后，模型开始能回答问题、编写代码、遵循指令，而不需要为每项任务专门编程。
- **2022 年至今——指令微调与对齐。** 原始的"预测下一 token"模型擅长续写文本，却不擅长响应请求。于是服务方进一步训练模型遵循指令（指令微调），并让它们倾向于给出有益、无害的回答（对齐，通常借助人类或 AI 的反馈）。这就是"能补全句子的模型"与"按你要求行事的聊天机器人"之间的差别。

技术核心——注意力机制——由 3Blue1Brown 的 *Transformer attention* 一课以可视化方式讲解，OpenAI、Anthropic 和 Google 的官方模型文档也用平实的文字作了说明。把 LLM 用得好并不需要那些数学，但知道核心是"预测下一个 token，然后对齐行为"，就能解释后面绝大部分内容。

## 0.3 现代 LLM 是如何构建的：训练、对齐、服务

可以把它想成三个阶段：

1. **预训练。** 模型通读一个庞大的语料库，学会预测下一个 token。"知识"（以统计规律的形式存在）大部分存储在这一步。模型的盲区也在这里定型：如果语料截止于 2025 年，模型就不知道 2026 年的事。
2. **对齐 / 指令微调。** 模型进一步接受训练，学会响应请求、拒绝有害请求，并匹配人类偏好。这就是为什么两个预训练相似的模型，在对话中给人的感觉可能截然不同。
3. **服务与安全层。** 当你在聊天窗口里输入文字，你的文本会被切分成 token、送入模型，服务方还可能在它周围加上过滤器、系统提示、检索或工具访问。你实际体验到的是模型加上这些层。

由此得出三条实际结论：

- **某个具体模型版本有训练截止日期。** 产品之后可能更新模型，也可能加入检索、搜索、文件、记忆或工具。面对时效性问题，不能只凭截止日期下结论；要核对产品当前文档、它使用的来源和日期。
- **每次请求都要消耗 token。** 你提供的输入和模型生成的输出都计入。长上下文很有用，但不是免费的。
- **同一个模型可以表现出不同的行为**，取决于系统提示、设置（temperature）和周围的工具。行为变了，并不自动等于模型换了。

## 0.4 四个你处处都会遇到的概念

**Token。** 模型读写的基本单位。token 常常是词片段，而不是整个词："ChatGPT" 可能是两到三个 token。价格、上下文限制和速度都以 token 计量。粗略地说，100 个 token ≈ 75 个英文单词。

**上下文窗口（context window）。** 模型一次最多能考虑的文本量——包括你的指令，以及你粘贴进来的任何对话或文档。它衡量的是工作记忆，而不是智力。窗口越大，你能粘贴的文档越长，但模型仍然把整个窗口当作"需要关注的内容"，而不是经过核验的事实。

**Temperature（与采样）。** 一个控制输出随机程度的设置。temperature 低 → 输出更可预测、更重复；temperature 高 → 变化更多，有时也更有创意。处理事实和代码时用低值；头脑风暴时，高一点可能有帮助。

**参数与规模。** "数十亿参数"描述的是模型的体量。体量与能力相关，但并不保证在你那个任务上的质量；在一个狭窄、定义清晰的任务上，小模型可能胜过更大的模型。判断模型要看它在你自己的任务上的表现，而不是看参数数量。

## 0.5 LLM 真正擅长什么

根据这些系统在官方文档和教学材料中的使用与描述，可靠的优势包括：

- **改写与概括**你提供的文本，并按指定的语气、长度或受众来执行；
- **讲解与辅导**：把一个概念拆成步骤、给出例子、换一种说法回答追问；
- **起草**：提纲、邮件、计划、代码骨架和初稿，之后再交给你来编辑；
- **翻译与语言练习**：在主要语言之间达到实用质量的翻译；
- **信息整理**：把笔记变成表格、列表或摘要；从文本中抽取字段；
- **生成代码并陪你调试**：编写小函数、解释报错、审查代码片段——始终以你的测试为准；
- **规划与比较**：列出选项和评判标准，前提是事实由你提供、决定由你来做。

共同的主线是：当任务属于**文本进、文本出，且有一个你可以核对的明确目标**时，LLM 最强。当任务暗中依赖事实、数学精度或现实世界中的行动时，它们最弱。

## 0.6 LLM 做不到的事（诚实的清单）

所有严肃的资料——从 Microsoft 的 LLM 基础到 Anthropic 的术语表，再到独立的教学材料——都指向同样的局限。一个模型：

- **不会自行查找事实。** 基础模型生成的是与训练数据*一致的*文本。产品可能接入搜索、检索、文件、记忆或工具；这些是独立的能力面，也各有数据与权限边界。返回的材料仍可能过时、不完整或错误，所以要核对原始来源和日期。
- **不会自动知道当下或你的私密数据。** 它有训练截止日期，并且只能接收你、接入的产品、账号记忆、检索系统、文件或工具提供的内容。粘贴、上传或启用连接前，先确认哪些数据会离开当前界面，以及谁授权这样做。
- **不能可靠地做算术。** 大型模型靠模式而非计算解决应用题；长而复杂的数学需要计算器、代码或工具。
- **无法核验。** 模型不能告诉你某条引用是否真实、某个网站是否存在、某个说法是否为真。只有你（或代你行事的工具）能检查。
- **不能独自对现实世界采取行动。** 除非工具层明确提供，否则聊天模型没有文件、账号或权限。一次登录、一个按钮或一份 agent 摘要，都不能证明某个动作真的发生了。
- **本身并不记得你。** 产品可能保存聊天记录或账号记忆；隐私、保留与删除行为取决于具体产品和设置。不要假定聊天既私密又会被记住，应先阅读适用的政策。
- **它本身不是搜索引擎、计算器、数据库或人。** 产品可以接入这些能力，但接入并不意味着每个回答都最新、正确、获授权或私密。

一个有用的心智模型：**基础 LLM 像一位博览群书、善于起草、却可能自信填补空白的实习生；聊天产品还可能给他搜索结果、文件、计算器、记忆或工具。** 你仍要决定他能读取或发送什么，核对来源和结果，也不会让他未经审查就发表法律意见。这正是使用 LLM 的方式。

## 0.7 这如何改变你的用法

Playbook 的方法直接来自 0.5 和 0.6 两节：

1. **用文字定义任务**——要什么结果、用什么输入、受哪些约束（第 3 章会讲授完整的契约）。
2. **提供上下文**——粘贴材料、说明受众、讲清限制。模型只能基于你给的东西工作。
3. **要求一个可检查的形态**——表格、diff、列表、改写后的段落；总之是你能亲自审查的东西。
4. **自己核验**——对照资料核对事实、对代码跑测试、接受 diff 之前先通读一遍。
5. **守住边界**——不要在没有证据的情况下，让一个貌似合理的回答变成一次行动、一笔付款、一篇发表或一个信念。

### 五分钟边界检查

继续之前，在任意文字聊天工具中用下面这条虚构主张做一次练习。不要开启搜索、上传文件或提供私人信息。

```text
我收到一条主张：“市图书馆今天下午 6 点关门。”
在你回答前，我会先标出纯文字模型能建立和不能建立的内容。

请先让我写出这些标记。然后只指出我漏掉的一项边界：生成、当前事实、来源核对，或现实世界中的行动。
不要查询任何信息，也不要编造来源。
```

保存你的第一次标记和那一条纠正。目的不是学会某句万能提示词，也不是证明模型准确；而是亲自观察“生成看似合理的句子”和“核实一项当下主张”之间的差别。

然后继续阅读[第 1 章：在信任 Codex 之前，先理解 GPT](../chapters/01-gpt-and-codex-ZH.md)。
