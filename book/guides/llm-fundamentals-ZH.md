# 什么是 LLM：先弄懂它能做什么、不能做什么

**单元：** `core-llm-boundaries`

**状态：** `candidate`。**运行状态：** `not_run`。
**时间：** 约 25 分钟。**前置条件：** 无。你不需要 Codex、Git、付费账户或工具。

这是 Playbook 的基础课。在选择平台、连接文件、安装 Skill，或让 Agent 开始行动前，
你需要先建立一个简单、准确的工作模型。重点不是背缩写，而是分清三件事：哪一层生成了文字，
哪一层能读取或改变模型之外的环境，以及要留下什么记录才能核对结果。

本页会出现一些工程术语。第一次看到时，先按下面的白话理解：

- **所用产品（host）**：你正在使用的聊天网站、桌面应用或命令行程序。它把模型、规则和工具组合起来。
- **可核对的记录**：做完后留下的短记录，例如原文、差异、命令输出、来源链接或截图。它的作用是让别人能重新检查你说的“已经完成”。
- **使用入口**：你打开产品的方式，例如网页、桌面应用、命令行或 IDE。不同产品对这个入口的叫法可能不同。
- **固定练习材料（fixture）**：为了练习而准备、可以随时丢弃的文件和输入，不是真实项目。

每当有人介绍一个新的 AI 功能，都问四个问题：

1. **模型被要求生成什么？**
2. **这一次请求实际提供了哪些上下文？**
3. **哪个产品或工具（如果有）能读取或改变模型之外的环境？**
4. **留下什么可核对的记录，别人才能检查这条说法？**

如果其中一项答不出来，就把结果保留为草稿或假设，不要用听起来很自信的句子来补空白。

## 你应该留下的结果

读完后，用自己的话写一张解释卡，并做出两个边界判断。一张合格的解释卡，应该让别人看清：

- 文本 LLM 如何根据一次请求提供的上下文生成内容；
- 在安全的第一次任务中，**LLM、token、上下文、提示词、工具、MCP、Agent** 和 **Skill**
  各自至少是什么意思；
- 为什么流畅文字本身不是事实为真的证据；
- 哪些部分属于模型、聊天产品，哪些属于外部工具。

这是一个有边界的解释任务，不是对某个 AI 产品全部能力的考试。详细的平台操作会在后面的课程中出现。

## 0.1 先用一句话理解

现代文本 LLM 是经过训练、能够估计并生成 token 序列的模型。许多自回归模型会根据可用上下文逐步预测下一个 token。额外训练和产品层会继续塑造部署后的响应方式。

这句话是一个实用工作模型，不是对所有语言、多模态系统或部署服务的完整定义。它能解释系统为何可以续写、翻译、总结、抽取字段或起草内容，但不能推出每个输出都是真实的，也不能推出所有产品具备相同能力。

这里的“预测”很重要。它描述内容如何生成，不表示模型已经核验现实、理解某个人，或判断某个行动已获授权。回答可能有帮助，但仍需要检查。

## 0.2 九个术语，各自放在自己的层里

下面的地图故意保持简短。它是安全入门所需的工作定义，不声称所有厂商都完全用同样的词义。

| 术语 | 最小有用含义 | 不要据此推断 |
| --- | --- | --- |
| **LLM / 模型** | 模型根据这次输入的内容生成回答。基础模型生成的是文字；产品还可能在模型之外增加其他能力。 | 它是已经核验过的数据库、一个人，或一个能自行执行操作的主体。 |
| **Token / tokenizer** | tokenizer 把文本映射为模型特定的 token ID，也能映射回来。token 常是词片段，不是单词或固定数量的字符。 | 存在通用的 token 对单词或字符换算。数量、上限、费用和速度取决于 tokenizer 与产品。 |
| **上下文** | 一次请求可用的信息：指令、对话、你提供的材料，以及在存在时的检索片段和工具结果。产品可能在模型周围加入**搜索、检索、文件、记忆或工具**。 | 上下文中的每一项都真实、相关，或被正确使用。 |
| **上下文窗口** | **有限的上下文窗口**是某个模型或产品一次能处理的、按 token 计算的输入和输出总量。 | 不同模型、账户和使用入口都有同一个固定数字。窗口更大也不代表你可以不挑选、不检查来源。 |
| **提示词** | 你发给系统的任务说明和材料，包括目标、限制和希望得到的格式。 | 它不是咒语；写得更长也不一定更好。 |
| **用户提示词 / 系统或开发者指令** | 用户提示词说明眼前的任务。所用产品还可能套用优先级更高的规则来影响回答；这些规则可能看不见，也不能由你修改。 | 用户可以覆盖产品规则，或不同产品都会公开同样的指令层。 |
| **工具 / 检索** | 所用产品可以连接到计算器、搜索、文件读取器、数据库等程序。模型可以提出调用，但要由产品和工具真正执行并返回结果。 | 回复里出现调用提议、按钮或“已完成”摘要，就能证明外部动作已经发生或一定正确。 |
| **MCP** | Model Context Protocol 是一种连接标准，让兼容的产品连接到工具或上下文提供者。它只统一连接的一部分；认证、批准、可用工具和数据范围仍要单独检查。 | 它保证所有地方都兼容、可信或可以无限访问。服务器已经配置也不等于已经安全或获批。 |
| **Agent / Skill** | Agent 是围绕模型、上下文、工具、反馈和停止条件组织起来的多步循环。Skill 是可按任务加载的一套方法和指令。 | 隐藏思维、人类般意图、额外权限，或循环已经成功完成的证据。 |

继续记住两个区别：

1. **能力、授权和证据不是一回事。** 系统可能能够提出行动、被授权尝试行动，或确实完成行动；这三种观察必须分开记录。
2. **新增一层能力，不会自动修复下层问题。** 搜索可能返回过时页面，文件工具可能读错文件，Agent 可能过早停止，Skill 也可能包含不合适的规则。新增层需要自己的检查。

### 最容易被混在一起的术语

**上下文不是永久记忆。** 上下文是所用产品为这一次请求提供的内容。产品可能保存对话历史、偏好、文件，或保存 embedding（把内容转成便于相似度检索的向量表示），以后再挑一部分使用；那是另外的数据保存和检索决定。保存的内容可能过时、不完整，甚至没有进入这次请求。要问：这一次到底提供了什么？

**检索是一条查证路径，不是真实性保证。** 搜索或 RAG 组件会挑选片段加入上下文。它可能漏掉最佳来源，选到转载，或返回旧版本。保留来源 URL、日期，并把每条说法和来源对应起来。更大的上下文窗口只是容量更大，不会让每个片段都相关或正确。

**提示词是任务说明，不是咒语。** 有用的首轮请求会说明结果、起始材料、限制、回答格式、检查方式和停止条件。系统或开发者指令可能优先于用户提示词；引用的文件也可能包含不可信指令。除非任务明确把文字设为指令，否则把提供的文字当作数据。

**一次工具调用至少涉及两个角色。** 模型可以提出结构化调用，所用产品决定是否允许，工具负责执行。记录目标、授权、预期影响和返回结果，再重新查看目标来核对。回复中出现工具名称不是执行记录。

**MCP 缩小了连接问题，但没有取消管理责任。** MCP 可以统一兼容产品发现并使用上下文或工具时的部分流程。认证、服务器实现、用户批准、网络范围、数据外发和结果检查仍然要单独确认。“支持 MCP”不等于“所有 MCP 服务器都兼容或安全”。

**Agent 是可以检查的循环，不是另一个人。** 教学时描述看得见的状态：接收、计划、提出行动、批准或拒绝、工具结果、验证、重试、交接和停止。不要声称知道隐藏思维。循环最后显示一段文字，也不代表外部任务已经完成。

**Skill 是方法包，不是权限。** 好的 Skill 要说明何时适用、需要什么输入、禁止做什么、如何停止，以及要留下什么记录。渐进加载可以让一套较大的方法只在需要时进入上下文，但加载指令不会自动授予文件、终端、浏览器、账户或发布权限。

## 0.3 一次请求中发生了什么

对纯文字交流，可以使用下面这个可观察模型：

```text
你的请求 + 你提供的材料
          ↓
所用产品组装指令和上下文
          ↓
模型生成 token 序列
          ↓
所用产品可能显示文字，或提出工具调用
          ↓
只有所用产品允许且授权成立时工具才运行
          ↓
人检查返回文字、工具结果和限制
```

这个图不描述隐藏思维链、厂商内部路由或每一种多模态流程，只指出一个常见错误：模型的文字可以描述工具调用，但工具实际上可能没有运行。要看到工具事件、返回数据、文件差异、命令输出或其他合适记录，才能把行动标成已完成。

对于多步 Agent，在每个边界重复同一检查：

```text
观察状态 → 提议下一步 → 检查授权 → 执行动作
→ 重新查看结果并核对 → 检查验收 → 继续、交接或停止
```

如果超时或中断后状态未知，不要盲目重复可能发送、发布、删除、付款或改变账户的行动。先重新查看目标，或者把不确定性交给人。

## 0.4 一点历史，但不要把历史当成保证

2017 年的论文 *Attention Is All You Need* 提出了影响后来语言模型的 Transformer 架构。Attention 让模型更容易关联所提供序列中的 token，但没有让上下文变成无限长。现代产品还会加入数据选择、优化、指令微调、安全控制、路由、检索、工具和界面代码。没有一个历史标签能解释今天每个服务的行为。

## 0.5 LLM 自己无法建立什么

面对清楚的文本输入、文本输出目标，模型通常能帮助改写你提供的文字、换一种方式解释概念、起草大纲、抽取字段，或提出可供你测试的代码。这些是有用模式，不是保证。

没有合适的来源或工具，它不能自行建立引用真实、网站仍存在、当前声明为真，或某个提议行动已经发生。产品可能加入搜索或检索，但返回材料仍可能过时、不完整或错误。接受当前事实前，**核对原始来源和日期**。

数据边界同样重要。粘贴、上传或启用连接前，先检查**哪些数据会离开当前界面，以及谁授权这样做**。没有明确的行动边界和证据时，不要把看起来合理的草稿变成付款、发布、删除、账户修改或承诺。

训练会在使用前塑造模型参数；当前请求提供新的上下文。训练截止时间不是实时来源，当前回答需要来源检查，**不能只凭截止日期下结论**。产品记忆、检索或搜索可以增加查证路径，但每条路径都可能过期，也有自己的权限边界。

## 0.6 五分钟边界检查

这是一次纯文字观察。使用聊天界面即可，但不要启用搜索、上传文件或提供私人信息。

先不要问模型，自己完成这句话：

> 俱乐部在周二 18:00 集合，房间号是……

写出两个可能的续写，并标记哪一个得到句子支持。正确答案是：句子没有提供任何房间号。你的大脑同样会自动补出合理内容；合理与有证据是两回事。

现在只发送下面这条虚构通知和请求：

```text
通知：“俱乐部周二 18:00 集合。请带笔记本。房间号稍后确认。”

任务：用两句话为新成员改写通知。保留每一个已给事实。把缺失细节放在[方括号]中，
然后列出你保留的事实。
检查：逐句与通知比较。不要添加房间号、费用、联系人、承诺或新的时间。
停止：不要浏览、发送、发布，也不要猜测未知细节。
```

保留第一次请求和第一次回答，并给每条输出标记：

| 检查 | 要看什么 |
| --- | --- |
| 来源匹配 | 每个事实都能在通知中找到吗？ |
| 形状 | 回答用了两句话，并列出了保留的事实吗？ |
| 未知项 | 房间号是否保持为 `[unknown]`，而不是被编造？ |

如果回答添加了房间号，就把那条说法标为 `FAIL`。不要从一次回答推断模型总是不可靠；这份固定练习材料只显示一次任务中的一个可见失败。

再做一次边界判断：先别查资料，写下仅凭纯文字模型，你能对这句话确认到什么程度：**“市图书馆今天下午 6 点关门。”** 模型可以讨论句子表达，但这条当前事实仍需要来源检查。不要要求它编造来源。

### 三个有边界的观察实验

上面的检查只是小型演示，不是学习者或模型在所有任务中都会重复同样行为的证据。要在不使用账户、私人数据、工具或网络请求的情况下练习这些边界，请使用下面的虚构记录协议（协议正文目前为英文）：

- [Context change and unknowns（上下文变化与未知项）](../../evals/candidates/core-course-v1/observations/context-change-and-unknowns.md) —— 比较两份输入版本，把每条声明标为 `PASS`、`FAIL` 或 `UNSURE`，并让房间号保持未知。
- [First-request contract and controlled repeat（第一轮请求契约与受控重复）](../../evals/candidates/core-course-v1/observations/first-request-contract.md) —— 在回答前写出目标、材料、限制、回答格式和停止条件；有安全的文字界面时，将同一请求再运行两次，记录共同点与差异。
- [Tool boundary, authority, and evidence（工具边界、授权与证据）](../../evals/candidates/core-course-v1/observations/tool-boundary-authority-evidence.md) —— 区分提议的行动、获得的授权、工具执行和重新查看后的证据。

每个协议都要求先保存第一次产物，再提供提示，并记录帮助、未知项和停止规则。状态为 `candidate / not_run`：未来运行只能描述指定任务、条件和评分标准，不能证明课程有效性、提示词优越性、模型质量、保持、普遍迁移、平台等价或生产就绪。

### 可迁移的首轮请求模板

准备尝试一个低风险真实任务时，先填好下面六行。标签适用于任何聊天模型；产品仍可能加入你看不到的其他指令。

```text
结果： [一个可观察的结果]
起始上下文： [我提供的事实或文本]
允许的帮助： [模型可以做什么]
限制： [哪些事实必须保持，哪些事不能发生]
回答与检查： [我要检查的格式，以及检查方法]
停止： [缺少输入、授权、来源或证据时暂停]
```

第一次尝试使用虚构或非敏感上下文。先要求草稿或分类，再考虑使用工具。保存第一条请求和回答；否则无法判断后来的改写究竟修复了问题，还是只把原问题藏起来。下一单元会把这个模式变成完整任务卡和保留记录：[通用 LLM 协作路线](../routes/universal-core-foundations-ZH.md)。

## 0.7 本单元唯一的完成检查

不要复制本页，自己写一张简短解释卡：

```text
我的解释：

LLM 边界：
Token 或上下文边界：
提示词 / 产品 / 工具边界：
上下文 / 记忆边界：
工具 / MCP / Agent / Skill 边界：
流畅回答仍可能错误的一个原因：

判断 1（支持 / 不支持）：
证据：
判断 2（模型 / 产品 / 工具）：
证据：
```

用下面的量规检查自己的卡片：

- `0`：把流畅文字当作证据，把能动性赋予模型，或没有任何判断证据；
- `1`：提到基于上下文生成，但有一项重要边界或验证理由仍不清楚；
- `2`：使用自己的话，分开模型与产品或工具，并指出本任务中至少一个需要核验的理由。

保留解释卡、第一次回答，以及一句仍未知道的内容。不要从这次自检报告课程完成或学习结果。下一步是[通用 LLM 协作路线](../routes/universal-core-foundations-ZH.md)；后面的 Codex 路线要等基础路线之后，从[第 1 章](../chapters/01-gpt-and-codex-ZH.md)开始。

本课是对公开材料的原创、简明改写。以下仅作参考输入；没有复制来源正文、提示词、图表或模型输出。本次改写访问日期：2026-08-17。

- Microsoft Learn，[LLM fundamentals](https://learn.microsoft.com/en-gb/agent-framework/journey/llm-fundamentals) —— 通俗概念与局限；属于产品范围的指导。
- Anthropic，[Claude glossary](https://platform.claude.com/docs/en/about-claude/glossary) —— token 与上下文术语；产品范围且会变化。
- Model Context Protocol，[Specification](https://modelcontextprotocol.io/specification/2025-06-18) —— 协议范围；不能证明某个承载产品或服务器已经设置。
- OpenAI，[Prompt engineering](https://platform.openai.com/docs/guides/prompt-engineering) —— 一个厂商当前的提示词建议；不是跨平台保证。
- Vaswani 等，[Attention Is All You Need](https://arxiv.org/abs/1706.03762) —— Transformer 历史论文。
- NIST，[AI 600-1 Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf) —— 风险与信息完整性背景，不是产品测试。
- 3Blue1Brown，[Attention in transformers](https://www.3blue1brown.com/lessons/attention) —— 独立视觉解释，不是产品行为的权威来源。

易变产品事实需要在相应来源记录中保存负责人、URL、访问日期、适用范围和下次复核时间。本页不声称存在最佳模型、普遍产品行为、学习提升、保持、迁移或生产就绪状态。
