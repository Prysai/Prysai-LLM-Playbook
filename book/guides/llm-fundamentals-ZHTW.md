# 什麼是 LLM：先弄懂它能做什麼、不能做什麼

**單元：** `core-llm-boundaries`

**狀態：** `candidate`。**執行狀態：** `not_run`。
**時間：** 約 25 分鐘。**前置條件：** 無。你不需要 Codex、Git、付費帳號或工具。

這是 Playbook 的基礎課。在選擇平台、連接檔案、安裝 Skill 或讓 Agent 採取行動之前，
你需要先有一個簡單、準確的工作模型。目標不是背縮寫，而是分清三件事：誰生成了文字、
誰能讀寫外部世界，以及要留下哪些紀錄才能核對結果。

本頁會出現一些工程術語。第一次看到時，先按下面的白話理解：

- **使用中的產品（host）**：你正在使用的聊天網站、桌面應用程式或命令列程式。它把模型、規則和工具組合在一起。
- **可核對的紀錄**：做完後留下的簡短紀錄，例如原文、差異、命令輸出、來源連結或截圖。這些紀錄讓別人可以重新檢查你所說的「已經完成」。
- **使用入口**：你打開產品的方式，例如網頁、桌面應用程式、命令列或 IDE。不同產品對這個入口的叫法可能不同。
- **練習材料（fixture）**：為了練習而準備、可以隨時丟棄的檔案和輸入，不是真實專案。

每當有人介紹一個新的 AI 功能，都問四個問題：

1. **模型被要求生成什麼？**
2. **這一次請求實際提供了哪些上下文？**
3. **哪個產品或工具（如果有）能觀察或改變模型以外的世界？**
4. **留下什麼可核對的紀錄，別人才能檢查這個說法？**

如果其中一項答不出來，就把結果保留為草稿或假設，不要用聽起來很有把握的句子來補空白。

## 你應該留下的結果

讀完後，用自己的話寫一張解釋卡，並做出兩個邊界判斷。合格的解釋卡應讓別人看見：

- 文字 LLM 如何根據一次請求提供的上下文生成內容；
- 在安全的第一次任務中，**LLM、token、上下文、提示詞、工具、MCP、Agent** 和 **Skill**
  各自至少是什麼意思；
- 為什麼流暢文字本身不是事實為真的證據；
- 哪些部分屬於模型、聊天產品，哪些屬於外部工具。

這是一個有邊界的解釋任務，不是對某個 AI 產品全部能力的考試。詳細的平台操作會在後面的課程中出現。

## 0.1 一句話工作模型

現代文字 LLM 是經過訓練、能夠估計並生成 token 序列的模型。許多自迴歸模型會根據可用上下文逐步預測下一個 token。額外訓練和產品層會繼續塑造部署後的回應方式。

這句話是一個實用工作模型，不是對所有語言、多模態系統或部署服務的完整定義。它能解釋系統為何可以續寫、翻譯、總結、抽取欄位或起草內容，但不能推出每個輸出都是真實的，也不能推出所有產品具備相同能力。

這裡的「預測」很重要。它描述內容如何生成，不表示模型已經核驗現實、理解某個人，或判斷某個行動已獲授權。回答可能有幫助，但仍需要檢查。

## 0.2 九個術語，各自放在自己的層裡

下面的地圖故意保持簡短。它是安全入門所需的工作定義，不聲稱所有廠商都完全用同樣的詞義。

| 術語 | 最小有用含義 | 不要據此推斷 |
| --- | --- | --- |
| **LLM / 模型** | 模型根據這次輸入的內容生成回答。基礎模型生成的是文字；產品外層還可能加上其他能力。 | 它是已經核驗過的資料庫、一個人，或能自行執行操作的主體。 |
| **Token / tokenizer** | tokenizer 把文字映射為模型特定的 token ID，也能映射回文字。token 常是詞片段，不是單詞或固定數量的字元。 | 存在通用的 token 對單詞或字元換算。數量、上限、費用和速度取決於 tokenizer 與產品。 |
| **上下文** | 一次請求可用的資訊：指令、對話、你提供的材料，以及在存在時的檢索片段和工具結果。產品可能在模型周圍加入**搜尋、檢索、檔案、記憶或工具**。 | 上下文中的每一項都真實、相關，或被正確使用。 |
| **上下文視窗** | **有限的上下文視窗**是某個模型或產品一次能處理的、按 token 計算的輸入和輸出總量。 | 不同模型、帳戶和使用入口不一定有同一個固定數字。視窗更大也不代表你可以不挑選、不檢查來源。 |
| **提示詞** | 你發給系統的任務說明和材料，包括目標、限制和希望得到的格式。 | 它不是咒語；寫得更長也不一定更好。 |
| **使用者提示詞 / 系統或開發者指令** | 使用者提示詞說明眼前的任務。使用中的產品還可能套用優先順序更高的規則來影響回答；這些規則可能看不見，也不能由你修改。 | 使用者可以覆蓋產品規則，或不同產品都會公開同樣的指令層。 |
| **工具 / 檢索** | 使用中的產品可以連接計算器、搜尋、檔案讀取工具、資料庫等程式。模型可以提出呼叫，但必須由產品和工具實際執行並回傳結果。 | 回覆裡出現呼叫提議、按鈕或「已完成」摘要，就能證明外部行動已經發生或一定正確。 |
| **MCP** | Model Context Protocol 是一種連線標準，讓相容的產品連接工具或上下文提供者。它只規範連線的一部分；身分驗證、核准、可用工具和資料範圍仍要單獨檢查。 | 它保證所有地方都相容、可信或可以無限存取。已設定的伺服器也不等於已安全或已獲核准。 |
| **Agent / Skill** | Agent 是圍繞模型、上下文、工具、回饋和停止條件組織起來的多步迴圈。Skill 是可按任務載入的一套方法和指令。 | 隱藏思維、人類般意圖、額外權限，或迴圈已經成功完成的證據。 |

繼續記住兩個區別：

1. **能力、授權和證據不是一回事。** 系統可能能夠提出行動、被授權嘗試行動，或確實完成行動；這三種觀察必須分開記錄。
2. **新增一層能力，不會自動修復下層問題。** 搜尋可能回傳過時頁面，檔案工具可能讀錯檔案，Agent 可能過早停止，Skill 也可能包含不合適的規則。新增層需要自己的檢查。

### 最容易被混在一起的術語

**上下文不是永久記憶。** 上下文是使用中的產品為這一次請求提供的內容。產品可能儲存對話歷史、偏好、檔案，或儲存 embedding（把內容轉成方便做相似度檢索的向量表示），之後再挑一部分使用；那是另外的資料保存和檢索決定。保存的內容可能過時、不完整，甚至沒有進入這次請求。要問：這一次到底提供了什麼？

**檢索是一條查證路徑，不是真實性保證。** 搜尋或 RAG 元件會挑選片段加入上下文。它可能漏掉最佳來源，選到轉載，或回傳舊版本。保留來源 URL、日期，並把每個說法和來源對應起來。更大的上下文視窗只是容量更大，不會讓每個片段都相關或正確。

**提示詞是一份任務說明，不是咒語。** 有用的第一輪請求會說明結果、起始材料、限制、回答形式、檢查方式和停止線。系統或開發者指令可能優先於使用者提示詞；引用的檔案也可能包含不可信指令。除非任務明確把文字設為指令，否則把提供的文字當作資料。

**一次工具呼叫至少涉及兩個角色。** 模型可以提出結構化呼叫，使用中的產品決定是否允許，工具負責執行。記錄目標、授權、預期影響和回傳結果，再重新查看目標來核對。回覆中出現工具名稱不是執行紀錄。

**MCP 縮小了連線問題，但沒有取消管理責任。** MCP 可以統一相容產品發現並使用上下文或工具時的部分流程。身分驗證、伺服器實作、使用者核准、網路範圍、資料外發和結果檢查仍要單獨確認。「支援 MCP」不等於「所有 MCP 伺服器都相容或安全」。

**Agent 是可以檢查的迴圈，不是另一個人。** 教學時，請描述可觀察到的狀態：接收、規劃、提出行動、核准或拒絕、工具結果、驗證、重試、交接和停止。不要聲稱知道隱藏思維。迴圈最後顯示一段文字，也不代表外部任務已經完成。

**Skill 是方法包，不是權限。** 好的 Skill 要說明何時適用、需要什麼輸入、禁止做什麼、如何停止，以及要留下什麼紀錄。漸進載入可以讓一套較大的方法只在需要時進入上下文，但載入指令不會自動授予檔案、終端機、瀏覽器、帳號或發布權限。

## 0.3 一次請求中發生了什麼

對純文字交流，可以使用下面這個可觀察模型：

```text
你的請求 + 你提供的材料
          ↓
使用中的產品組裝指令和上下文
          ↓
模型生成 token 序列
          ↓
使用中的產品可能顯示文字，或提出工具呼叫
          ↓
只有使用中的產品允許且授權成立時工具才會執行
          ↓
人檢查回傳文字、工具結果和限制
```

這個圖不描述隱藏思維鏈、廠商內部路由或每一種多模態流程，只指出一個常見錯誤：模型的文字可以描述工具呼叫，但工具實際上可能沒有執行。要看到工具事件、回傳資料、檔案差異、命令輸出或其他合適紀錄，才能把行動標成已完成。

對於多步 Agent，在每個邊界重複同一檢查：

```text
觀察狀態 → 提議下一步 → 檢查授權 → 行動執行
→ 重新查看結果並核對 → 檢查驗收 → 繼續、交接或停止
```

如果超時或中斷後狀態未知，不要盲目重複可能傳送、發布、刪除、付款或變更帳戶的行動。先重新查看目標狀態，或者把不確定性交給人。

## 0.4 一點歷史，但不要把歷史當成保證

2017 年的論文 *Attention Is All You Need* 提出了影響後來語言模型的 Transformer 架構。Attention 讓模型更容易關聯所提供序列中的 token，但沒有讓上下文變成無限長。現代產品還會加入資料選擇、最佳化、指令微調、安全控制、路由、檢索、工具和介面程式碼。沒有一個歷史標籤能解釋今天每個服務的行為。

## 0.5 LLM 自己無法建立什麼

面對清楚的文字輸入、文字輸出目標，模型通常能幫助改寫你提供的文字、換一種方式解釋概念、起草大綱、抽取欄位，或提出可供你測試的程式碼。這些是有用模式，不是保證。

沒有合適的來源或工具，它不能自行建立引用真實、網站仍存在、目前宣告為真，或某個提議行動已經發生。產品可能加入搜尋或檢索，但回傳的材料仍可能過時、不完整或錯誤。接受目前事實前，**核對原始來源和日期**。

資料邊界同樣重要。貼上、上傳或啟用連線前，先檢查**哪些資料會離開目前的介面，以及誰授權這樣做**。沒有明確行動邊界與證據時，不要把看起來合理的草稿變成付款、發布、刪除、帳號修改或承諾。

訓練會在使用前塑造模型參數；目前的請求提供新的上下文。訓練截止時間不是即時來源，目前的回答需要來源檢查，**不能只憑截止日期下結論**。產品記憶、檢索或搜尋可以增加證據路徑，但每條路徑都有自己的新鮮度和權限邊界。

## 0.6 五分鐘邊界檢查

這是一次純文字觀察。使用聊天介面即可，但不要啟用搜尋、上傳檔案或提供私人資訊。

先不要問模型，自己完成這句話：

> 俱樂部在週二 18:00 集合，房間號是……

寫出兩個可能的續寫，並標記哪一個得到句子支援。正確答案是：句子沒有提供任何房間號。你的大腦同樣會自動補出合理內容；合理與有證據是兩回事。

現在只傳送下面這條虛構通知和請求：

```text
通知：「俱樂部週二 18:00 集合。請帶筆記本。房號稍後確認。」

任務：用兩句話為新成員改寫通知。保留每一個已給事實。把缺失細節放在[方括號]中，
然後列出你保留的事實。
檢查：逐句與通知比較。不要新增房間號、費用、聯絡人、承諾或新的時間。
停止：不要瀏覽、傳送、發布，也不要猜測未知細節。
```

保留第一次請求和第一次回答，並給每條輸出標記：

| 檢查 | 要看什麼 |
| --- | --- |
| 來源匹配 | 每個事實都能在通知中找到嗎？ |
| 格式 | 回答用了兩句話，並列出了保留的事實嗎？ |
| 未知項 | 房間號是否保持為 `[unknown]`，而不是被編造？ |

如果回答新增了房間號，就把那條宣告標為 `FAIL`。不要從一次回答推斷模型總是不可靠；這份練習材料只顯示一次任務中的一個可見失敗。

再做一次邊界判斷：在查任何資料前，寫下純文字模型對這句話能建立什麼：**「市立圖書館今天下午 6 點閉館。」** 模型可以討論句子表達，但這條當前事實需要來源檢查。不要要求它編造來源。

### 三個有邊界的觀察實驗

上面的檢查只是小型演示，不是學習者或模型在所有任務中都會重複同樣行為的證據。要在不使用帳號、私人資料、工具或網路請求的情況下練習這些邊界，請使用下面的虛構記錄協定（協定正文目前為英文）：

- [Context change and unknowns（上下文變化與未知項）](../../evals/candidates/core-course-v1/observations/context-change-and-unknowns.md) —— 比較兩份輸入版本，把每條宣告標為 `PASS`、`FAIL` 或 `UNSURE`，並讓房間號保持未知。
- [First-request contract and controlled repeat（第一輪請求契約與受控重複）](../../evals/candidates/core-course-v1/observations/first-request-contract.md) —— 在回答前寫出目標、材料、限制、回答形狀和停止條件；有安全的文字介面時，將同一請求再執行兩次，記錄共同點與差異。
- [Tool boundary, authority, and evidence（工具邊界、授權與證據）](../../evals/candidates/core-course-v1/observations/tool-boundary-authority-evidence.md) —— 區分提議的行動、獲得的授權、工具執行和重新查看後的證據。

每個協定都要求先儲存第一次結果，再提供提示，並記錄所用的協助、未知項和停止規則。狀態為 `candidate / not_run`：未來執行只能描述指定任務、條件和評分標準，不能證明課程有效性、提示詞優越性、模型品質、保持、普遍遷移、平台等價或生產就緒。

### 可遷移的首輪請求模板

準備嘗試一個低風險真實任務時，先填好下面六行。標籤適用於任何聊天模型；產品仍可能加入你看不到的其他指令。

```text
結果： [一個可觀察的結果]
起始上下文： [我提供的事實或文字]
允許的幫助： [模型可以做什麼]
限制： [哪些事實必須保持，哪些事不能發生]
回答與檢查： [我要檢查的格式，以及檢查方法]
停止： [缺少輸入、授權、來源或證據時暫停]
```

第一次嘗試使用虛構或非敏感上下文。先要求草稿或分類，再考慮使用工具。儲存第一條請求和回答；否則無法判斷後來的改寫究竟修復了問題，還是只把原問題藏起來。下一單元會把這個模式變成完整任務卡和保留紀錄：[通用 LLM 協作路線](../routes/universal-core-foundations-ZHTW.md)。

## 0.7 本單元唯一的完成檢查

不要複製本頁，自己寫一張簡短解釋卡：

```text
我的解釋：

LLM 邊界：
Token 或上下文邊界：
提示詞 / 產品 / 工具邊界：
上下文 / 記憶邊界：
工具 / MCP / Agent / Skill 邊界：
流暢回答仍可能錯誤的一個原因：

判斷 1（支援 / 不支援）：
證據：
判斷 2（模型 / 產品 / 工具）：
證據：
```

用下面的量規檢查自己的卡片：

- `0`：把流暢文字當作證據，把能動性賦予模型，或沒有任何判斷證據；
- `1`：提到基於上下文生成，但有一項重要邊界或驗證理由仍不清楚；
- `2`：使用自己的話，分開模型與產品或工具，並指出本任務中至少一個需要核驗的理由。

保留解釋卡、第一次回答，以及一句仍未知道的內容。不要從這次自檢報告課程完成或學習結果。下一步是[通用 LLM 協作路線](../routes/universal-core-foundations-ZHTW.md)；後面的 Codex 路線要等基礎路線之後，從[第 1 章](../chapters/01-gpt-and-codex-ZHTW.md)開始。
