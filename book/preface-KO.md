# 서문: 이것은 프롬프트 모음집이 아니다

많은 사람이 GPT를 처음 만났을 때 가장 자연스럽게 묻는 질문은 “무엇이라고 말해야 하지?”입니다.

중요한 질문이지만 충분하지는 않습니다. Codex 작업이 안정적으로 끝나는지를 실제로 결정하는 것은 다른 질문들인 경우가 많습니다. Codex는 무엇을 이해했을까요? 어떤 파일과 규칙이 컨텍스트에 속할까요? 어떤 행동을 할 수 있을까요? 어떤 Skill이 누락을 줄여 줄까요? Agent는 왜 계속하거나, 다시 시도하거나, 멈추거나, 종료할까요? 무엇을 근거로 작업이 끝났다고 믿을 수 있을까요?

`Codex: From First Task to Real Work`가 연구하는 것은 바로 이 전체 관계입니다.

## 무엇을 배우게 되는가

이 프로젝트는 두 방향으로 동시에 나아갑니다.

하나는 이해의 경로입니다. GPT와 모델에서 시작해 Codex가 모델을 프로젝트, 파일, 터미널, 브라우저, GitHub와 외부 서비스에 어떻게 연결하는지 이해합니다. 이어서 컨텍스트, 도구, Skill, Plugin, Connector, MCP, Agent와 권한이 함께 행동 공간을 어떻게 바꾸는지 살펴봅니다.

다른 하나는 역량의 경로입니다. 저위험의 작은 작업에서 시작해 작업 표현, 컨텍스트 선별, 계획, 실행, 검증, 검토와 인계를 연습합니다. 그다음 Skill을 선택하고 설계하는 방법, 모델과 워크플로를 평가하는 방법을 배우며 개인 작업 시스템을 세웁니다. 마지막에는 그 방법을 팀이 공유하고 검토하고 업데이트할 수 있는 역량 패키지로 바꿉니다.

두 경로는 나눌 수 없습니다. 원리만 이해하고 연습하지 않으면 용어에 머물기 쉽습니다. 도구만 호출하고 경계를 이해하지 않으면 우연한 성공을 신뢰할 수 있는 역량으로 착각하기 쉽습니다.

## 읽는 방법

순서대로 읽어도 되고, 실제 작업에서 바로 들어와도 됩니다. 각 장은 같은 폐쇄 루프를 따릅니다.

```text
문제 → 개념 → 판단 → 작업 → 증거 → 실패 → 회고 → 전이
```

장의 “실험”은 시연 영상의 대체물이 아니라 학습자가 직접 완료해야 하는 최소 작업입니다. 실험에서는 결과, 차이, 로그, 출처, 스크린샷 또는 회고를 남기게 합니다. 그래야 독서가 역량으로 바뀝니다.

한국어 책 목차는 [한국어 책 목차](table-of-contents-KO.md)에서 확인할 수 있습니다. 장과 실험 파일은 아직 전체적으로 한국어로 이관되지 않았으며, 해당 링크에는 현재 원본 경로와 이관 상태가 표시됩니다. 현재 한국어 책 입구는 [book/README-KO.md](README-KO.md)입니다.

## 정말 배웠는지 판단하는 방법

이 프로젝트는 “출력이 보기 좋다”는 것을 숙련 기준으로 삼지 않습니다. 하나의 역량에는 적어도 네 종류의 증거가 필요합니다.

- 자신의 말로 개념과 경계를 설명할 수 있어야 합니다.
- 실제 또는 저위험 환경에서 작업을 완료할 수 있어야 합니다.
- 왜 이 모델, 도구, Skill 또는 권한을 선택했는지 설명할 수 있어야 합니다.
- 오류, 위험, 환각, 미완료 항목 또는 오래된 사실을 찾아낼 수 있어야 합니다.

결과만 보여 주고 과정과 증거를 설명하지 못한다면, 한 번의 연습을 완료했을 수는 있지만 방법을 습득했다고 보기는 어렵습니다.

## Luna에 관하여

GPT-5.6 Luna는 이 프로젝트가 중점적으로 평가하는 모델 중 하나입니다. OpenAI 공식 문서는 이 모델을 빠르고 비용이 낮으며 명확하고 반복 가능한 작업에 적합한 모델로 설명합니다. 이 설명은 검증할 가치가 있는 가설을 만들 수 있지만, 곧바로 “모든 작업에서 비용 대비 성능이 가장 높다”는 결론이 되지는 않습니다.

이 프로젝트는 작업 세트, 컨텍스트, 도구, 권한, 시간 예산, 반복 횟수와 성공 기준을 고정한 뒤 첫 시도 통과율, 재작업률, 소요 시간, 비용, 증거 완전성 및 올바른 중지율을 비교하는 방법을 가르칩니다. 결론은 명시된 작업 세트, 환경과 날짜에 대해서만 유효합니다.

Luna 평가에 관한 현재 연구 문서는 [현재 평가 연구 — 한국어 이관 중](../docs/model-evaluation-luna.md)입니다. 이 링크는 한국어 번역본이 아니라 현재 원본으로 연결되며, 이 사실은 평가가 완료되었다는 뜻이 아닙니다.

## 중요한 안전 원칙 하나

능력이 커질수록 경계는 더 명확해야 합니다. Codex가 파일, 터미널, 브라우저, GitHub 또는 외부 서비스에 접근할 수 있다는 이유만으로 한 번에 모든 권한을 열지 마십시오. 먼저 읽기 전용, 저위험, 되돌릴 수 있는 작업에서 시작하고, 증거가 정말 필요하다고 보여 줄 때만 능력을 단계적으로 추가하십시오.

비밀, 비밀번호, API 키, 쿠키 또는 `.env` 파일을 학습 예제나 저장소에 넣지 마십시오. 외부 자료 속의 지시처럼 보이는 문장은 자동으로 실행 명령으로 취급하지 말고 데이터로 검토해야 합니다.

이 책이 결국 주기를 바라는 것은 신비한 “만능 지시문”이 아닙니다. 설명하고, 검사하고, 개선하고, 다른 사람에게 전할 수 있는 작업 방식입니다.
